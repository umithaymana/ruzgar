Entwickler können damit Audioquellen auswählen, Effekte hinzufügen, Audiovisualisierungen erstellen, räumliche Effekte wie Panning anwenden und vieles mehr. Konzepte und Verwendung von Web Audio Bei der Web Audio API werden Audiooperationen innerhalb eines Audiokontexts ausgeführt. Die API ist für ein modulares Routing ausgelegt. Grundlegende Audiooperationen werden von Audioknoten ausgeführt, die zu einem Audiorouting-Graphen verbunden sind. Selbst innerhalb eines einzelnen Kontexts werden mehrere Quellen mit unterschiedlichen Kanalanordnungen unterstützt. Dieser modulare Aufbau ermöglicht komplexe Audiofunktionen mit dynamischen Effekten. Audioknoten werden über ihre Ein- und Ausgänge zu Ketten und einfachen Netzen verbunden. Am Anfang stehen in der Regel eine oder mehrere Quellen. Quellen liefern Folgen von Samples – Messwerte der Amplitude des Audiosignals zu aufeinanderfolgenden Zeitpunkten, oft mehrere Zehntausend pro Sekunde. Diese können mathematisch berechnet werden, wie bei OscillatorNode , oder aus Aufnahmen in Audio- oder Videodateien stammen, wie bei AudioBufferSourceNode und MediaElementAudioSourceNode , beziehungsweise aus Audiostreams, wie bei MediaStreamAudioSourceNode . Audiodateien sind letztlich Aufzeichnungen von Schallintensitäten, die von Mikrofonen oder elektrischen Instrumenten aufgenommen und zu einer einzigen komplexen Wellenform zusammengemischt wurden. Die Ausgänge dieser Knoten können mit den Eingängen anderer Knoten verbunden werden, die die Ströme von Audiosamples mischen oder verändern. Eine häufige Veränderung besteht darin, die Samples mit einem Wert zu multiplizieren, um sie lauter oder leiser zu machen, wie bei GainNode . Sobald das Audiosignal für den gewünschten Effekt ausreichend verarbeitet wurde, kann es mit dem Eingang eines Ziels ( BaseAudioContext.destination ) verbunden werden, das den Ton an Lautsprecher oder Kopfhörer ausgibt. Diese letzte Verbindung ist nur erforderlich, wenn die Nutzer den Ton hören sollen. Schnittstellen der Web Audio API Die Web Audio API umfasst zahlreiche Schnittstellen und zugehörige Ereignisse, die wir in neun Funktionsbereiche unterteilt haben. Allgemeine Definition des Audiographen Allgemeine Container und Definitionen, die Audiographen bei der Verwendung der Web Audio API strukturieren. AudioContext Die Schnittstelle AudioContext stellt einen Audiographen dar, der aus miteinander verbundenen Audiomodulen besteht, die jeweils durch einen AudioNode repräsentiert werden. Ein Audiokontext steuert die Erstellung der darin enthaltenen Knoten sowie die Ausführung der Audioverarbeitung oder -dekodierung. Sie müssen einen AudioContext erstellen, bevor Sie etwas anderes tun, da sämtliche Vorgänge innerhalb eines Kontexts stattfinden. AudioNode Die Schnittstelle AudioNode stellt ein Audioverarbeitungsmodul dar, beispielsweise eine Audioquelle wie ein HTML-Element &lt;audio&gt; oder &lt;video&gt; , ein Audioausgabeziel oder ein zwischengeschaltetes Verarbeitungsmodul wie einen Filter vom Typ BiquadFilterNode oder einen Lautstärkeregler vom Typ GainNode . AudioParam Die Schnittstelle AudioParam stellt einen audiobezogenen Parameter dar, beispielsweise einen Parameter eines AudioNode . Für ihn können ein bestimmter Wert oder eine Wertänderung festgelegt werden. Änderungen lassen sich für einen bestimmten Zeitpunkt und nach einem bestimmten Muster planen. AudioParamMap Stellt für eine Gruppe von AudioParam -Schnittstellen eine Map-ähnliche Schnittstelle bereit. Sie bietet die Methoden forEach() , get() , has() , keys() und values() sowie die Eigenschaft size . BaseAudioContext Die Schnittstelle BaseAudioContext dient als Basisdefinition für Audiographen zur Echtzeit- und Offlineverarbeitung, die durch AudioContext beziehungsweise OfflineAudioContext repräsentiert werden. BaseAudioContext verwenden Sie nicht direkt, sondern greifen über eine dieser beiden abgeleiteten Schnittstellen auf seine Funktionen zu. Das Ereignis ended Das Ereignis ended wird ausgelöst, wenn die Wiedergabe stoppt, weil das Ende des Mediums erreicht wurde. Audioquellen definieren Schnittstellen zur Definition von Audioquellen für die Verwendung mit der Web Audio API. AudioScheduledSourceNode AudioScheduledSourceNode ist eine übergeordnete Schnittstelle für verschiedene Arten von Audioquellenknoten. Sie ist ein AudioNode . OscillatorNode Die Schnittstelle OscillatorNode stellt eine periodische Wellenform dar, die sinus-, rechteck-, sägezahn- oder dreieckförmig oder benutzerdefiniert sein kann. Sie ist ein Audioverarbeitungsmodul vom Typ AudioNode , das eine Welle mit einer bestimmten Frequenz erzeugt. AudioBuffer Die Schnittstelle AudioBuffer stellt ein kurzes, im Arbeitsspeicher befindliches Audiomaterial dar. Es kann mithilfe der Methode BaseAudioContext.decodeAudioData aus einer Audiodatei oder mithilfe von BaseAudioContext.createBuffer aus Rohdaten erstellt werden. Nachdem das Audio in diese Form dekodiert wurde, kann es in einem AudioBufferSourceNode verwendet werden. AudioBufferSourceNode Die Schnittstelle AudioBufferSourceNode stellt eine Audioquelle dar, deren Audiodaten im Arbeitsspeicher in einem AudioBuffer gespeichert sind. Sie ist ein AudioNode , der als Audioquelle dient. MediaElementAudioSourceNode Die Schnittstelle MediaElementAudioSourceNode stellt eine Audioquelle dar, die aus einem HTML-Element &lt;audio&gt; oder &lt;video&gt; besteht. Sie ist ein AudioNode , der als Audioquelle dient. MediaStreamAudioSourceNode Die Schnittstelle MediaStreamAudioSourceNode stellt eine Audioquelle dar, die aus einem MediaStream besteht, beispielsweise aus einer Webcam, einem Mikrofon oder einem von einem entfernten Computer gesendeten Stream.
