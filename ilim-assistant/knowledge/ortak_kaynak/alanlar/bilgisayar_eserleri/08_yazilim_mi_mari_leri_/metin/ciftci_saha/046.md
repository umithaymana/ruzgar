Download XLSX Download CSV API URL ( Open in new tab , copy this URL into your application, or paste an API URL to restore its settings) Data Sources This API provides access to both real-time IFS HRES 9 km forecasts and open-data ECMWF IFS and AIFS 0.25° . Different weather models may use different temporal resolutions. The Open-Meteo API dynamically interpolates all data to a consistent 1-hourly time-series for up to 15 days. The ECMWF IFS model runs every 6 hours at a 9 km resolution. Open-Meteo delivers the full native 9 km IFS forecasts on the reduced Gaussian grid O1280, ensuring direct, original ECMWF outputs at the highest resolution. The first 90 forecast hours use 1-hourly data, switching to 3-hourly after 90 hours and 6 hourly after 144 hours. The open-data IFS 0.25 updates every 6 hours, but only offers 0.25° resolution and 3- and 6-hourly data. The open-data distribution has an additional delay of 2 hours compared to the real-time IFS dissemination. AIFS is ECMWF’s artificial intelligence weather model, delivering improved performance compared to other AI-based models. Currently, only 6-hourly time steps are available. More details about AIFS can be found here . As ECMWF expands its data offering, new AIFS products will also be integrated into this API. For higher-resolution local forecasts, we recommend the Generic Weather Forecast API , which integrates models down to 1 km resolution. ECMWF ensemble forecasts are available via the Ensemble API , ECMWF WAM wave forecasts can be accessed through the Marine Forecast API , and HRES IFS data are archived in the Historical Weather API . You can find the update timings in the model updates documentation . Derived Variables ECMWF publishes temperature, pressure, wind components, precipitation, snowfall water equivalent, cloud cover, global solar radiation and CAPE natively. Several convenient API variables are not direct model output — Open-Meteo derives them from the native fields for every forecast step. Derived Variable How is it derived? Relative humidity and dew point ECMWF publishes 2 m dew point rather than relative humidity. Relative humidity is calculated from temperature and dew point. On AIFS pressure levels, relative humidity is derived from native specific humidity. Weather code Computed from cloud cover, precipitation, snowfall and CAPE. The IFS HRES 9 km model additionally uses showers, convective inhibition and boundary layer height. Wind speed and direction Calculated from the native U and V wind components at 10 m, 100 m and on all pressure levels. Snowfall and rain Snowfall converts the native snowfall water equivalent with 0.7 cm per mm. Rain is total precipitation minus snowfall water equivalent and showers. Direct and diffuse solar radiation IFS 0.25° and AIFS provide only global radiation: diffuse is separated using the Razo, Müller Witwer model. IFS HRES 9 km provides direct radiation natively; diffuse is the difference to global radiation. DNI, GTI and instant values follow from solar geometry. Surface pressure Calculated from mean sea-level pressure, 2 m temperature and terrain elevation. Pressure-level cloud cover Estimated from pressure-level relative humidity following Sundqvist et al. (1989). Low, mid and high cloud layers use native model fields where available. Vertical velocity ECMWF publishes vertical velocity as omega in Pa/s. It is converted to geometric velocity in m/s using the temperature at each pressure level. Apparent temperature, ET₀, vapour pressure deficit and wet bulb temperature Standard formulas combining 2 m temperature, humidity, wind speed and solar radiation. ET₀ follows the FAO-56 Penman-Monteith equation. Sunshine duration Seconds per hour with direct normal irradiance above the WMO threshold of 120 W/m². Sunrise, sunset, daylight duration and the day-or-night flag are astronomical calculations. Daily values are aggregated from hourly data. API Documentation The API endpoint /v1/ecmwf accepts a geographical coordinate, a list of weather variables and responds with a JSON hourly weather forecast for 10 days. Time always starts at 0:00 today. All URL parameters are listed below: Parameter Format Required Default Description latitude, longitude Floating point Yes Geographical WGS84 coordinates of the location. Multiple coordinates can be comma separated. E.g. &amp;latitude=52.52,48.85&amp;longitude=13.41,2.35 . To return data for multiple locations the JSON output changes to a list of structures. CSV and XLSX formats add a column location_id . elevation Floating point No The elevation used for statistical downscaling. Per default, a 90 meter digital elevation model is used . You can manually set the elevation to correctly match mountain peaks. If &amp;elevation=nan is specified, downscaling will be disabled and the API uses the average grid-cell height. For multiple locations, elevation can also be comma separated. hourly String array No A list of weather variables which should be returned. Values can be comma separated, or multiple &amp;hourly= parameter in the URL can be used. temperature_unit String No celsius If fahrenheit is set, all temperature values are converted to Fahrenheit. wind_speed_unit String No kmh Other wind speed units: ms , mph and kn precipitation_unit String No mm Other precipitation amount units: inch timeformat String No iso8601 By default, timestamps use ISO 8601 format with a fixed offset, utc_offset_seconds , resolved at request time (see timezone ). With unixtime , timestamps are seconds since 1970-01-01 00:00 UTC.
