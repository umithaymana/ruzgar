Available values are: &lsquo; auto &rsquo; Automatic selection based on internal heuristics. This is the default. &lsquo; clip &rsquo; Performs no tone-mapping, just clips out-of-range colors. Retains perfect color accuracy for in-range colors but completely destroys out-of-range information. Does not perform any black point adaptation. Not configurable. &lsquo; st2094-40 &rsquo; EETF from SMPTE ST 2094-40 Annex B, which applies the Bezier curves from HDR10+ dynamic metadata based on Bezier curves to perform tone-mapping. The OOTF used is adjusted based on the ratio between the targeted and actual display peak luminances. &lsquo; st2094-10 &rsquo; EETF from SMPTE ST 2094-10 Annex B.2, which takes into account the input signal average luminance in addition to the maximum/minimum. Note that this does not currently include the subjective gain/offset/gamma controls defined in Annex B.3. &lsquo; bt.2390 &rsquo; EETF from the ITU-R Report BT.2390, a hermite spline roll-off with linear segment. The knee point offset is configurable using tonemapping_knee_offset . Note that this parameter defaults to 1.0 , rather than the value of 0.5 from the ITU-R spec. &lsquo; bt.2446a &rsquo; EETF from ITU-R Report BT.2446, method A. Designed for well-mastered HDR sources. Can be used for both forward and inverse tone mapping. Not configurable. &lsquo; spline &rsquo; Simple spline consisting of two polynomials, joined by a single pivot point. The knee point is determined from the source scene average brightness, falling back to tonemapping_knee_default (defaulting to 0.4 ). Can be used for both forward and inverse tone mapping. &lsquo; reinhard &rsquo; Simple non-linear, global tone mapping algorithm. The tonemapping_reinhard_contrast option specifies the local contrast coefficient at the display peak. Essentially, a value of 0.5 implies that the reference white will be about half as bright as when clipping. Defaults to 0.5 , which results in the simplest formulation of this function. &lsquo; mobius &rsquo; Generalization of the reinhard tone mapping algorithm to support an additional linear slope near black. The tonemapping_linear_knee option indicates the trade-off between the linear section and the non-linear section. Essentially, for a given parameter x , every color value below x will be mapped linearly, while higher values get non-linearly tone-mapped. Values near 1.0 make this curve behave like clip , while values near 0.0 make this curve behave like reinhard . The default value is 0.3 , which provides a good balance between colorimetric accuracy and preserving out-of-gamut details. &lsquo; hable &rsquo; Piece-wise, filmic tone-mapping algorithm developed by John Hable for use in Uncharted 2, inspired by a similar tone-mapping algorithm used by Kodak. Popularized by its use in video games with HDR rendering. Preserves both dark and bright details very well, but comes with the drawback of changing the average brightness quite significantly. This is sort of similar to reinhard with parameter 0.24 . &lsquo; gamma &rsquo; Fits a gamma (power) function to transfer between the source and target color spaces, effectively resulting in a perceptual hard-knee joining two roughly linear sections. This preserves details at all scales fairly accurately, but can result in an image with a muted or dull appearance. The tonemapping_linear_knee option is used as the cutoff point, defaulting to 0.3 . &lsquo; linear &rsquo; Linearly stretches the input range to the output range, in PQ space. This will preserve all details accurately, but results in a significantly different average brightness. Can be used for inverse tone-mapping in addition to regular tone-mapping. The tonemapping_exposure option can be used as an additional linear gain coefficient (defaulting to 1.0 ). tonemapping_param For tunable tone mapping functions, this parameter can be used to fine-tune the curve behavior. Refer to the documentation of tonemapping . The default value of 0.0 is replaced by the curve&rsquo;s preferred default setting, or by tonemapping_* options below as applicable. This option, if nonzero, takes effect over the corresponding values of the other tonemapping_* options. Deprecated, do not use. tonemapping_knee_adaptation Controls how strongly the knee point adapts to the source scene average brightness, relative to the target average in PQ space. A value of 1.0 fully adapts the source average to the target average, while 0.0 disables adaptation. Defaults to 0.4 . Affects st2094-40 , st2094-10 and spline . tonemapping_knee_minimum Sets the minimum knee point as a fraction of the PQ luminance range. Limits how low the automatically determined knee point can be. Defaults to 0.1 . tonemapping_knee_maximum Sets the maximum knee point as a fraction of the PQ luminance range. Limits how high the automatically determined knee point can be. Defaults to 0.8 . tonemapping_knee_default Sets the fallback knee point used when source scene average brightness metadata is unavailable. Normally, the knee point is determined from the source scene average instead. The value should be between tonemapping_knee_minimum and tonemapping_knee_maximum . Defaults to 0.4 . tonemapping_knee_offset Sets the knee point offset for bt.2390 . The ITU-R specification defines 0.5 as the default, but libplacebo uses 1.0 . Defaults to 1.0 . tonemapping_slope_tuning Controls how the slope of the spline curve is adjusted based on the difference between source and target peaks. The tuning aims to preserve a slope closer to 1.0 for small differences and approach linear mapping for larger differences. Defaults to 1.5 . tonemapping_slope_offset Controls the slope adjustment of the spline curve, together with tonemapping_slope_tuning . Defaults to 0.2 . tonemapping_spline_contrast Controls the contrast of the spline curve. Higher values produce a steeper curve, preserving midtone contrast at the cost of shadow and highlight detail. Lower values produce a shallower curve, preserving highlights at the cost of midtone contrast. Values above 1.0 can increase contrast beyond that of the source. Defaults to 0.5 . tonemapping_reinhard_contrast Sets the local contrast coefficient at the display peak for reinhard . A value of 0.5 makes reference white approximately half as bright as when clipping. Defaults to 0.5 . tonemapping_linear_knee Sets the knee point for the legacy mobius and gamma curves, which operate on linear light. Defaults to 0.3 . tonemapping_exposure Sets the linear exposure or gain applied by the linear tone-mapping method. Defaults to 1.0 . inverse_tonemapping If enabled, this filter will also attempt stretching SDR signals to fill HDR output color volumes. Disabled by default. tonemapping_lut_size Size of the tone-mapping LUT, between 2 and 1024 . Defaults to 256 . Note that this figure is squared when combined with peak_detect . contrast_recovery Contrast recovery strength. If set to a value above 0.0 , the source image will be divided into high-frequency and low-frequency components, and a portion of the high-frequency image is added back onto the tone-mapped output. May cause excessive ringing artifacts for some HDR sources, but can improve the subjective sharpness and detail left over in the image after tone-mapping. Defaults to 0.30 . contrast_smoothness Contrast recovery lowpass kernel size. Defaults to 3.5 . Increasing or decreasing this will affect the visual appearance substantially. Has no effect when contrast_recovery is disabled. 11.148.1.8 Dithering # TOC By default, libplacebo will dither whenever necessary, which includes rendering to any integer format below 16-bit precision. It&rsquo;s recommended to always leave this on, since not doing so may result in visible banding in the output, even if the debanding filter is enabled. If maximum performance is needed, use ordered_fixed instead of disabling dithering. dithering Dithering method to use. Accepts the following values: &lsquo; none &rsquo; Disables dithering completely. May result in visible banding. &lsquo; blue &rsquo; Dither with pseudo-blue noise. This is the default. &lsquo; ordered &rsquo; Tunable ordered dither pattern. &lsquo; ordered_fixed &rsquo; Faster ordered dither with a fixed size of 6 . Texture-less. &lsquo; white &rsquo; Dither with white noise. Texture-less. dither_lut_size Dither LUT size, as log base2 between 1 and 8 . Defaults to 6 , corresponding to a LUT size of 64x64 . dither_temporal Enables temporal dithering.
