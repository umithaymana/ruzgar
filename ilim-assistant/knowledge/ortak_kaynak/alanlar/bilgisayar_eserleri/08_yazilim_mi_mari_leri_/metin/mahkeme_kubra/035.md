Safety [ edit ] JSON being a subset of JavaScript can lead to the misconception that it is safe to pass JSON texts to the JavaScript eval () function. This is not safe, due to certain valid JSON texts, specifically those containing U+2028 LINE SEPARATOR or U+2029 PARAGRAPH SEPARATOR , not being valid JavaScript code until JavaScript specifications were updated in 2019, and so older engines may not support it. [ 14 ] To avoid the many pitfalls caused by executing arbitrary code from the Internet, a new function, JSON . parse () , was first added to the fifth edition of ECMAScript, [ 35 ] which as of 2017 is supported by all major browsers. For non-supported browsers, an API-compatible JavaScript library is provided by Douglas Crockford . [ 36 ] In addition, the TC39 proposal "Subsume JSON" made ECMAScript a strict JSON superset as of the language's 2019 revision. [ 37 ] [ 38 ] Alternatives [ edit ] See also: Comparison of data-serialization formats JSON is promoted as a low-overhead alternative to XML as both of these formats have widespread support for creation, reading, and decoding in the real-world situations where they are commonly used. [ 39 ] Depending on the specific use-case, JSON alternatives include: For textual formats, CSV and supersets of JSON (see below). Ion also offers a textual format that's a JSON superset (wider range of primary types, annotations, comments, and allowing trailing commas). [ 40 ] For faster processing at the cost of human-readability, data interchange formats that can express all JSON objects (i.e. that have a data model that is a superset of JSON's) include CBOR (an IETF RFC standard) and Ion binary. [ 40 ] Google Protocol Buffers can also fill this niche due to the ability to be parsed without a schema, but it is not intended as an interchange language. In addition, databases such as SQLite and PostgreSQL have their own internal binary representations called "JSONB", not intended for outside use. [ 41 ] XML [ edit ] Main article: XML XML has been used to describe structured data and to serialize objects. Various XML-based protocols exist to represent the same kind of data structures as JSON for the same kind of data interchange purposes. Data can be encoded in XML in several ways. The most expansive form using tag pairs results in a much larger (in character count) representation than JSON, but if data is stored in attributes and short tag form where the closing tag is replaced with "},"parts":[{"template":{"target":{"wt":"code","href":"./Template:Code"},"params":{"1":{"wt":"/>"}},"i":0}}]}'>/> , the representation is often about the same size as JSON or just a little larger. [ 42 ] However, an XML attribute can only have a single value and each attribute can appear at most once on each element. XML separates data from metadata (via the use of elements and attributes), while JSON does not have such a concept. Another key difference is the addressing of values. JSON has objects with a simple key-to-value mapping, whereas in XML addressing happens on nodes , each of which receives a unique ID via the XML processor. Additionally, the XML standard defines a common attribute xml:id , that can be used by the user, to set an ID explicitly. XML tag names cannot contain any of the characters !"#$% &amp; '()*+,/; &lt; = > ?@[\]^`{|}~ , nor a space character, and cannot begin with - , . , or a numeric digit, whereas JSON keys can (even if quotation mark and backslash must be escaped). [ 43 ] XML values are strings of characters , with no built-in type safety . XML has the concept of schema , that permits strong typing, user-defined types, predefined tags, and formal structure, allowing for formal validation of an XML stream. JSON has several types built-in and has a similar schema concept in JSON Schema . XML supports comments, while JSON does not. [ 44 ] [ 22 ] Supersets [ edit ] Support for comments and other features have been deemed useful, which has led to several nonstandard JSON supersets being created. Among them are HJSON, [ 45 ] HOCON, and JSON5 (which despite its name, is not the fifth version of JSON). [ 46 ] [ 47 ] CSON (" CoffeeScript Object Notation") uses significant indentation and unquoted keys, and assumes an outer object declaration. It was used for configuring GitHub 's Atom text editor . [ 48 ] [ 49 ] [ 50 ] There is also an unrelated project called CSON ("Cursive Script Object Notation") that is more syntactically similar to JSON. [ 51 ] HOCON ("Human-Optimized Config Object Notation") is a format for human-readable data, and a superset of JSON. [ 52 ] HOCON is developed by Lightbend and used along the Play Framework . [ 53 ] It is also supported as a data format by Puppet [ 54 ] , TIBCO Streaming [ 55 ] [ 56 ] [ 57 ] , Exabeam Advanced Analytics [ 58 ] , Jitsi .properties -Files [ 59 ] [ 60 ] , and .NET projects via Akka.NET. [ 61 ] [ 62 ] JSON5 ("JSON5 Data Interchange Format") is an extension of JSON syntax that adds trailing commas, unquoted object keys, single quoted and multiline strings, additional number formats, and comments. Like JSON, JSON5 is valid JavaScript syntax. The specification was started in 2012 and finished in 2018 with version 1.0.0. [ 63 ] JSON5 syntax is supported in SQLite . [ 64 ] JSONC (JSON with Comments) is a subset of JSON5 used in Microsoft's Visual Studio Code . [ 65 ] [ 66 ] It supports single-line comments ( // ) and block comments ( /* */ ) [ 67 ] , and accepts trailing commas, but they are discouraged and the editor will display a warning. JWCC (JSON With Commas and Comments) is a superset that adds trailing commas, single-line code comments, and block comments. [ 68 ] It is used by Tailscale . [ 69 ] YAML [ edit ] See also: YAML § JSON YAML version 1.2 is a superset of JSON; prior versions were not strictly compatible. For example, escaping a slash / with a backslash \ is valid in JSON, but was not valid in YAML. [ 70 ] YAML supports comments, while JSON does not. [ 70 ] [ 46 ] [ 22 ] Derivatives [ edit ] Several serialization formats have been built on or from the JSON specification. Examples include GeoJSON , a format designed for representing simple geographical features [ 71 ] [ 72 ] JSON-LD , a method of encoding linked data using JSON [ 73 ] [ 74 ] JSON-RPC , a remote procedure call protocol encoded in JSON [ 75 ] JsonML , a lightweight markup language used to map between XML and JSON [ 76 ] [ 77 ] Smile (data interchange format) [ 78 ] [ 79 ] UBJSON , a binary computer data interchange format imitating JSON, but requiring fewer bytes of data [ 80 ] [ 81 ] Jsonnet is a prototype-based domain-specific language that produces JSON files. All JSON documents are valid Jsonnet programs that will be emitted unchanged when run. Jsonnet extends JSON by supporting variables, imports, loops, comments, etc. [ 82 ] [ 83 ] Jsonnet is used as a configuration language for cloud infrastructure engineering.
