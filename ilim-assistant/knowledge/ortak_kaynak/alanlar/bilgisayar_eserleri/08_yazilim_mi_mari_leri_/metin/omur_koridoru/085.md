REQUEST The &quot;REQUEST&quot; method in a &quot;VTODO&quot; calendar component provides the following scheduling functions: o Assign a to-do to one or more &quot;Calendar Users&quot;. o Reschedule an existing to-do. o Update the details of an existing to-do, without rescheduling it. o Update the completion status of &quot;Attendees&quot; of an existing to-do, without rescheduling it. o Reconfirm an existing to-do, without rescheduling it. o Delegate/reassign an existing to-do to another &quot;Calendar User&quot;. The assigned &quot;Calendar Users&quot; are identified in the &quot;VTODO&quot; calendar component by individual &quot;ATTENDEE;ROLE=REQ-PARTICIPANT&quot; property value sequences. Daboo Standards Track [Page 46] RFC 5546 iTIP December 2009 Typically, the originator of a &quot;REQUEST&quot; is the &quot;Organizer&quot; of the to-do, and the recipient of a &quot;REQUEST&quot; is the &quot;Calendar User&quot; assigned the to-do. The &quot;Attendee&quot; uses the &quot;REPLY&quot; method to convey their acceptance and completion status to the &quot;Organizer&quot; of the &quot;REQUEST&quot;. The &quot;UID&quot;, &quot;SEQUENCE&quot;, and &quot;DTSTAMP&quot; properties are used to distinguish the various uses of the &quot;REQUEST&quot; method. If the &quot;UID&quot; property value in the &quot;REQUEST&quot; is not found on the recipient&#x27;s calendar, then the &quot;REQUEST&quot; is for a new to-do. If the &quot;UID&quot; property value is found on the recipient&#x27;s calendar, then the &quot;REQUEST&quot; is a rescheduling, an update, or a reconfirmation of the &quot;VTODO&quot; calendar object. If the &quot;Organizer&quot; of the &quot;REQUEST&quot; method is not authorized to make a to-do request on the &quot;Attendee&#x27;s&quot; calendar system, then an exception is returned in the &quot;REQUEST-STATUS&quot; property of a subsequent &quot;REPLY&quot; method, but no scheduling action is performed. For the &quot;REQUEST&quot; method, multiple &quot;VTODO&quot; components in a single iCalendar object are only permitted for components with the same &quot;UID&quot; property. That is, a series of recurring events may have instance-specific information. In this case, multiple &quot;VTODO&quot; components are needed to express the entire series.
