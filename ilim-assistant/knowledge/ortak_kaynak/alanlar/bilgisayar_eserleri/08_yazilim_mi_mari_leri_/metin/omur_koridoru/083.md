CANCEL The &quot;CANCEL&quot; method in a &quot;VEVENT&quot; calendar component is used to send a cancellation notice of an existing event request to the affected &quot;Attendees&quot;. The message is sent by the &quot;Organizer&quot; of the event. For a recurring event, either the whole event or instances of an event may be cancelled. To cancel the complete range of a recurring event, the &quot;UID&quot; property value for the event MUST be specified and a &quot;RECURRENCE-ID&quot; MUST NOT be specified in the &quot;CANCEL&quot; method. In order to cancel an individual instance of the event, the &quot;RECURRENCE-ID&quot; property value for the event MUST be specified in the &quot;CANCEL&quot; method. There are two options for canceling a sequence of instances of a recurring &quot;VEVENT&quot; calendar component: a. The &quot;RECURRENCE-ID&quot; property for an instance in the sequence MUST be specified with the &quot;RANGE&quot; property parameter value of &quot;THISANDFUTURE&quot; to indicate cancellation of the specified &quot;VEVENT&quot; calendar component and all instances after. b. Individual recurrence instances may be cancelled by specifying multiple &quot;VEVENT&quot; components each with a &quot;RECURRENCE-ID&quot; property corresponding to one of the instances to be cancelled. Daboo Standards Track [Page 29] RFC 5546 iTIP December 2009 The &quot;Organizer&quot; MUST send a &quot;CANCEL&quot; message to each &quot;Attendee&quot; affected by the cancellation. This can be done using a single &quot;CANCEL&quot; message for all &quot;Attendees&quot; or by using multiple messages with different subsets of the affected &quot;Attendees&quot; in each. When a &quot;VEVENT&quot; is cancelled, the &quot;SEQUENCE&quot; property value MUST be incremented as described in Section 2.1.4 . COUNTER The &quot;COUNTER&quot; method for a &quot;VEVENT&quot; calendar component is used by an &quot;Attendee&quot; of an existing event to submit to the &quot;Organizer&quot; a counter proposal to the event. The &quot;Attendee&quot; sends this message to the &quot;Organizer&quot; of the event. The counter proposal is an iCalendar object consisting of a &quot;VEVENT&quot; calendar component that provides the complete description of the alternate event. The &quot;Organizer&quot; rejects the counter proposal by sending the &quot;Attendee&quot; a &quot;DECLINECOUNTER&quot; method. The &quot;Organizer&quot; accepts the counter proposal by rescheduling the event as described in Section 3.2.2.1 , &quot;Rescheduling an Event&quot;. The &quot;Organizer&#x27;s&quot; CUA SHOULD send a &quot;REQUEST&quot; message to all &quot;Attendees&quot; affected by any change triggered by an accepted &quot;COUNTER&quot;.
