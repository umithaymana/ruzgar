If the recipient CUA of a &quot;REQUEST&quot; method finds that the &quot;UID&quot; property value already exists on the calendar but that the &quot;SEQUENCE&quot; property value in the &quot;REQUEST&quot; is greater than the value for the existing &quot;VTODO&quot;, then the &quot;REQUEST&quot; method describes a rescheduling of the &quot;VTODO&quot; calendar component. 3.4.2.2 . REQUEST for Update or Reconfirmation of a VTODO The &quot;REQUEST&quot; method may be used to update or reconfirm a &quot;VTODO&quot; calendar component. Reconfirmation is merely an update of &quot;Attendee&quot; completion status or overall &quot;VTODO&quot; calendar component status. An update to an existing &quot;VTODO&quot; calendar component does not involve changes to the start or due time, recurrence intervals, or (generally) the description for the &quot;VTODO&quot; calendar component. If the recipient CUA of a &quot;REQUEST&quot; method finds that the &quot;UID&quot; property value already exists on the calendar and that the &quot;SEQUENCE&quot; property value in the &quot;REQUEST&quot; is the same as the value for the existing event, then the &quot;REQUEST&quot; method describes an update of the &quot;VTODO&quot; calendar component details, but not a rescheduling of the &quot;VTODO&quot; calendar component. The update &quot;REQUEST&quot; is the appropriate response to a &quot;REFRESH&quot; method sent from an &quot;Attendee&quot; to the &quot;Organizer&quot; of a &quot;VTODO&quot; calendar component. Unsolicited &quot;REQUEST&quot; methods MAY be sent by the &quot;Organizer&quot; of a &quot;VTODO&quot; calendar component. The unsolicited &quot;REQUEST&quot; methods are used to update the details of the &quot;VTODO&quot; (without rescheduling it or updating the completion status of &quot;Attendees&quot;) or the &quot;VTODO&quot; calendar component itself (i.e., reconfirm the &quot;VTODO&quot;). 3.4.2.3 . REQUEST for Delegating a VTODO The &quot;REQUEST&quot; method is also used to delegate or reassign ownership of a &quot;VTODO&quot; calendar component to another &quot;Calendar User&quot;. For example, it may be used to delegate an &quot;Attendee&#x27;s&quot; role (i.e., &quot;chair&quot; or &quot;participant&quot;) for a &quot;VTODO&quot; calendar component. The &quot;REQUEST&quot; method is sent by one of the &quot;Attendees&quot; of an existing &quot;VTODO&quot; calendar component to some other individual. The &quot;Attendee&quot; receiving the delegation request is referred to as the &quot;Delegate&quot;. The &quot;Delegator&quot; of a &quot;VTODO&quot; calendar component MUST forward the existing &quot;REQUEST&quot; method for a &quot;VTODO&quot; calendar component to the &quot;Delegate&quot;. The &quot;VTODO&quot; calendar component description MUST include the &quot;Delegator&#x27;s&quot; up-to-date &quot;VTODO&quot; calendar component definition. The &quot;REQUEST&quot; method MUST also include an &quot;ATTENDEE&quot; property with the calendar address of the &quot;Delegate&quot;. The &quot;Delegator&quot; MUST also send a &quot;REPLY&quot; method back to the &quot;Organizer&quot; with the &quot;Delegator&#x27;s&quot; &quot;Attendee&quot; property &quot;PARTSTAT&quot; parameter value set to &quot;DELEGATED&quot;. In addition, the &quot;DELEGATED-TO&quot; parameter MUST be included with the calendar address of the &quot;Delegate&quot;. A response to the delegation &quot;REQUEST&quot; is sent from the &quot;Delegate&quot; to the &quot;Organizer&quot;, and optionally to the &quot;Delegator&quot;. The &quot;REPLY&quot; method from the &quot;Delegate&quot; SHOULD include the &quot;ATTENDEE&quot; property with their calendar address and the &quot;DELEGATED-FROM&quot; parameter with the value of the &quot;Delegator&#x27;s&quot; calendar address. The delegation &quot;REQUEST&quot; method MUST assign a value for the &quot;RSVP&quot; property parameter associated with the &quot;Delegator&#x27;s&quot; &quot;Attendee&quot; property to that of the &quot;Delegate&#x27;s&quot; &quot;ATTENDEE&quot; property. For example, if the &quot;Delegator&#x27;s&quot; &quot;ATTENDEE&quot; property specifies &quot;RSVP=TRUE&quot;, then the &quot;Delegate&#x27;s&quot; &quot;ATTENDEE&quot; property MUST specify &quot;RSVP=TRUE&quot;. 3.4.2.4 . REQUEST Forwarded to an Uninvited Calendar User An &quot;Attendee&quot; assigned a &quot;VTODO&quot; calendar component may send the &quot;VTODO&quot; calendar component to another new CU not previously associated with the &quot;VTODO&quot; calendar component. The current &quot;Attendee&quot; assigned the &quot;VTODO&quot; calendar component does this by forwarding the original &quot;REQUEST&quot; method to the new CU. The new CU can send a &quot;REPLY&quot; to the &quot;Organizer&quot; of the &quot;VTODO&quot; calendar component. The reply contains an &quot;ATTENDEE&quot; property for the new CU. The &quot;Organizer&quot; ultimately decides whether or not the new CU becomes part of the to-do and is not obligated to do anything with a &quot;REPLY&quot; from a new (uninvited) CU. If the &quot;Organizer&quot; does not want the new CU to be part of the to-do, the new &quot;ATTENDEE&quot; property is not added to the &quot;VTODO&quot; calendar component. The &quot;Organizer&quot; MAY send the CU a &quot;CANCEL&quot; message to indicate that they will not be added to the to- do. If the &quot;Organizer&quot; decides to add the new CU, the new &quot;ATTENDEE&quot; property is added to the &quot;VTODO&quot; calendar component. Furthermore, the &quot;Organizer&quot; is free to change any &quot;ATTENDEE&quot; property parameter from the values supplied by the new CU to something the &quot;Organizer&quot; Daboo Standards Track [Page 50] RFC 5546 iTIP December 2009 considers appropriate. The &quot;Organizer&quot; SHOULD send the new &quot;Attendee&quot; a &quot;REQUEST&quot; message to inform them that they have been added. When forwarding a &quot;REQUEST&quot; to another CU, the forwarding &quot;Attendee&quot; MUST NOT make changes to the original message. 3.4.2.5 . REQUEST Updated Attendee Status An &quot;Organizer&quot; of a &quot;VTODO&quot; may request an updated status from one or more &quot;Attendees&quot;. The &quot;Organizer&quot; sends a &quot;REQUEST&quot; method to the &quot;Attendee&quot; with the &quot;ATTENDEE;RSVP=TRUE&quot; property sequence. The &quot;SEQUENCE&quot; property for the &quot;VTODO&quot; is not changed from its previous value. A recipient determines that the only change in the &quot;REQUEST&quot; is that their &quot;RSVP&quot; property parameter indicates a request for an updated status. The recipient SHOULD respond with a &quot;REPLY&quot; method indicating their current status with respect to the &quot;REQUEST&quot;. 3.4.3 . REPLY The &quot;REPLY&quot; method in a &quot;VTODO&quot; calendar component is used to respond (e.g., accept or decline) to a request or to reply to a delegation request. It is also used by an &quot;Attendee&quot; to update their completion status. When used to provide a delegation response, the &quot;Delegator&quot; MUST include the calendar address of the &quot;Delegate&quot; in the &quot;DELEGATED-TO&quot; parameter of the &quot;Delegator&#x27;s&quot; &quot;ATTENDEE&quot; property. The &quot;Delegate&quot; MUST include the calendar address of the &quot;Delegator&quot; on the &quot;DELEGATED-FROM&quot; parameter of the &quot;Delegate&#x27;s&quot; &quot;ATTENDEE&quot; property. The &quot;REPLY&quot; method MAY also be used to respond to an unsuccessful &quot;VTODO&quot; calendar component &quot;REQUEST&quot; method. Depending on the &quot;REQUEST-STATUS&quot; value, no scheduling action may have been performed. The &quot;Organizer&quot; of a &quot;VTODO&quot; calendar component MAY receive a &quot;REPLY&quot; method from a &quot;Calendar User&quot; not in the original &quot;REQUEST&quot;. For example, a &quot;REPLY&quot; method MAY be received from a &quot;Delegate&quot; of a &quot;VTODO&quot; calendar component. In addition, the &quot;REPLY&quot; method MAY be received from an unknown &quot;Calendar User&quot; who has been forwarded the &quot;REQUEST&quot; by an original &quot;Attendee&quot; of the &quot;VTODO&quot; calendar component. This uninvited &quot;Attendee&quot; MAY be accepted or the &quot;Organizer&quot; MAY cancel the &quot;VTODO&quot; calendar component for the uninvited &quot;Attendee&quot; by sending them a &quot;CANCEL&quot; method.
