Alarm Component Component Name: VALARM Purpose: Provide a grouping of component properties that define an alarm. Format Definition: A &quot;VALARM&quot; calendar component is defined by the following notation: alarmc = &quot;BEGIN&quot; &quot;:&quot; &quot;VALARM&quot; CRLF (audioprop / dispprop / emailprop) &quot;END&quot; &quot;:&quot; &quot;VALARM&quot; CRLF audioprop = *( ; ; &#x27;action&#x27; and &#x27;trigger&#x27; are both REQUIRED, Desruisseaux Standards Track [Page 71] RFC 5545 iCalendar September 2009 ; but MUST NOT occur more than once. ; action / trigger / ; ; &#x27;duration&#x27; and &#x27;repeat&#x27; are both OPTIONAL, ; and MUST NOT occur more than once each; ; but if one occurs, so MUST the other. ; duration / repeat / ; ; The following is OPTIONAL, ; but MUST NOT occur more than once. ; attach / ; ; The following is OPTIONAL, ; and MAY occur more than once. ; x-prop / iana-prop ; ) dispprop = *( ; ; The following are REQUIRED, ; but MUST NOT occur more than once. ; action / description / trigger / ; ; &#x27;duration&#x27; and &#x27;repeat&#x27; are both OPTIONAL, ; and MUST NOT occur more than once each; ; but if one occurs, so MUST the other. ; duration / repeat / ; ; The following is OPTIONAL, ; and MAY occur more than once. ; x-prop / iana-prop ; ) emailprop = *( ; ; The following are all REQUIRED, ; but MUST NOT occur more than once. ; action / description / trigger / summary / Desruisseaux Standards Track [Page 72] RFC 5545 iCalendar September 2009 ; ; The following is REQUIRED, ; and MAY occur more than once. ; attendee / ; ; &#x27;duration&#x27; and &#x27;repeat&#x27; are both OPTIONAL, ; and MUST NOT occur more than once each; ; but if one occurs, so MUST the other. ; duration / repeat / ; ; The following are OPTIONAL, ; and MAY occur more than once. ; attach / x-prop / iana-prop ; ) Description: A &quot;VALARM&quot; calendar component is a grouping of component properties that is a reminder or alarm for an event or a to-do. For example, it may be used to define a reminder for a pending event or an overdue to-do. The &quot;VALARM&quot; calendar component MUST include the &quot;ACTION&quot; and &quot;TRIGGER&quot; properties. The &quot;ACTION&quot; property further constrains the &quot;VALARM&quot; calendar component in the following ways: When the action is &quot;AUDIO&quot;, the alarm can also include one and only one &quot;ATTACH&quot; property, which MUST point to a sound resource, which is rendered when the alarm is triggered. When the action is &quot;DISPLAY&quot;, the alarm MUST also include a &quot;DESCRIPTION&quot; property, which contains the text to be displayed when the alarm is triggered. When the action is &quot;EMAIL&quot;, the alarm MUST include a &quot;DESCRIPTION&quot; property, which contains the text to be used as the message body, a &quot;SUMMARY&quot; property, which contains the text to be used as the message subject, and one or more &quot;ATTENDEE&quot; properties, which contain the email address of attendees to receive the message. It can also include one or more &quot;ATTACH&quot; properties, which are intended to be sent as message attachments. When the alarm is triggered, the email message is sent. The &quot;VALARM&quot; calendar component MUST only appear within either a &quot;VEVENT&quot; or &quot;VTODO&quot; calendar component. &quot;VALARM&quot; calendar components cannot be nested. Multiple mutually independent Desruisseaux Standards Track [Page 73] RFC 5545 iCalendar September 2009 &quot;VALARM&quot; calendar components can be specified for a single &quot;VEVENT&quot; or &quot;VTODO&quot; calendar component. The &quot;TRIGGER&quot; property specifies when the alarm will be triggered. The &quot;TRIGGER&quot; property specifies a duration prior to the start of an event or a to-do. The &quot;TRIGGER&quot; edge may be explicitly set to be relative to the &quot;START&quot; or &quot;END&quot; of the event or to-do with the &quot;RELATED&quot; parameter of the &quot;TRIGGER&quot; property. The &quot;TRIGGER&quot; property value type can alternatively be set to an absolute calendar date with UTC time. In an alarm set to trigger on the &quot;START&quot; of an event or to-do, the &quot;DTSTART&quot; property MUST be present in the associated event or to-do. In an alarm in a &quot;VEVENT&quot; calendar component set to trigger on the &quot;END&quot; of the event, either the &quot;DTEND&quot; property MUST be present, or the &quot;DTSTART&quot; and &quot;DURATION&quot; properties MUST both be present. In an alarm in a &quot;VTODO&quot; calendar component set to trigger on the &quot;END&quot; of the to-do, either the &quot;DUE&quot; property MUST be present, or the &quot;DTSTART&quot; and &quot;DURATION&quot; properties MUST both be present. The alarm can be defined such that it triggers repeatedly. A definition of an alarm with a repeating trigger MUST include both the &quot;DURATION&quot; and &quot;REPEAT&quot; properties. The &quot;DURATION&quot; property specifies the delay period, after which the alarm will repeat. The &quot;REPEAT&quot; property specifies the number of additional repetitions that the alarm will be triggered. This repetition count is in addition to the initial triggering of the alarm. Both of these properties MUST be present in order to specify a repeating alarm. If one of these two properties is absent, then the alarm will not repeat beyond the initial trigger. The &quot;ACTION&quot; property is used within the &quot;VALARM&quot; calendar component to specify the type of action invoked when the alarm is triggered. The &quot;VALARM&quot; properties provide enough information for a specific action to be invoked. It is typically the responsibility of a &quot;Calendar User Agent&quot; (CUA) to deliver the alarm in the specified fashion. An &quot;ACTION&quot; property value of AUDIO specifies an alarm that causes a sound to be played to alert the user; DISPLAY specifies an alarm that causes a text message to be displayed to the user; and EMAIL specifies an alarm that causes an electronic email message to be delivered to one or more email addresses. In an AUDIO alarm, if the optional &quot;ATTACH&quot; property is included, it MUST specify an audio sound resource. The intention is that the sound will be played as the alarm effect. If an &quot;ATTACH&quot; property is specified that does not refer to a sound resource, or Desruisseaux Standards Track [Page 74] RFC 5545 iCalendar September 2009 if the specified sound resource cannot be rendered (because its format is unsupported, or because it cannot be retrieved), then the CUA or other entity responsible for playing the sound may choose a fallback action, such as playing a built-in default sound, or playing no sound at all. In a DISPLAY alarm, the intended alarm effect is for the text value of the &quot;DESCRIPTION&quot; property to be displayed to the user. In an EMAIL alarm, the intended alarm effect is for an email message to be composed and delivered to all the addresses specified by the &quot;ATTENDEE&quot; properties in the &quot;VALARM&quot; calendar component. The &quot;DESCRIPTION&quot; property of the &quot;VALARM&quot; calendar component MUST be used as the body text of the message, and the &quot;SUMMARY&quot; property MUST be used as the subject text. Any &quot;ATTACH&quot; properties in the &quot;VALARM&quot; calendar component SHOULD be sent as attachments to the message. Note: Implementations should carefully consider whether they accept alarm components from untrusted sources, e.g., when importing calendar objects from external sources. One reasonable policy is to always ignore alarm components that the calendar user has not set herself, or at least ask for confirmation in such a case.
