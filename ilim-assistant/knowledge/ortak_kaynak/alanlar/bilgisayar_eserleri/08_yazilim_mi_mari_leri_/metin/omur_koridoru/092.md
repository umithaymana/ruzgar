Delegating an Event When delegating an event request to another &quot;Calendar User&quot;, the &quot;Delegator&quot; must both update the &quot;Organizer&quot; with a &quot;REPLY&quot; and send a request to the &quot;Delegate&quot;. There is currently no protocol limitation to delegation depth. It is possible for the original delegate to delegate the meeting to someone else, and so on. When a request is delegated from one CUA to another, there are a number of responsibilities required of the &quot;Delegator&quot;. The &quot;Delegator&quot; MUST: o Send a &quot;REPLY&quot; to the &quot;Organizer&quot; with the following updates: A. The &quot;Delegator&#x27;s&quot; &quot;ATTENDEE&quot; property &quot;PARTSTAT&quot; parameter is set to &quot;DELEGATED&quot; and the &quot;DELEGATED-TO&quot; parameter is set to the address of the &quot;Delegate&quot;. B. Add an additional &quot;ATTENDEE&quot; property for the &quot;Delegate&quot; with the &quot;DELEGATED-FROM&quot; property parameter set to the &quot;Delegator&quot;. C. Indicate whether they want to continue to receive updates when the &quot;Organizer&quot; sends out updated versions of the event. Setting the &quot;RSVP&quot; property parameter to &quot;TRUE&quot; will cause the updates to be sent; setting it to &quot;FALSE&quot; causes no further updates to be sent. Note that in either case, if the &quot;Delegate&quot; declines the invitation, the &quot;Delegator&quot; will be notified.
