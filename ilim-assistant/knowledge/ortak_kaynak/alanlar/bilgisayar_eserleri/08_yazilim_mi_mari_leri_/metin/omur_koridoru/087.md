ADD The &quot;ADD&quot; method allows the &quot;Organizer&quot; to add one or more new instances to an existing &quot;VTODO&quot; using a single iTIP message without having to send the entire &quot;VTODO&quot; with all the existing instance data, as it would have to do if the &quot;REQUEST&quot; method were used. The &quot;UID&quot; must be that of the existing to-do. If the &quot;UID&quot; property value in the &quot;ADD&quot; is not found on the recipient&#x27;s calendar, then the recipient SHOULD send a &quot;REFRESH&quot; to the &quot;Organizer&quot; in order to be updated with the latest version of the &quot;VTODO&quot;. If an &quot;Attendee&quot; implementation does not support the &quot;ADD&quot; method, it should respond with a &quot;REQUEST-STATUS&quot; value of 3.14 and ask for a &quot;REFRESH&quot;. When handling an &quot;ADD&quot; message, the &quot;Attendee&quot; treats each component in the &quot;ADD&quot; message as if it were referenced via an &quot;RDATE&quot; in the main component. The &quot;SEQUENCE&quot; property value is incremented since the sequence of to-dos has changed. CANCEL The &quot;CANCEL&quot; method in a &quot;VTODO&quot; calendar component is used to send a cancellation notice of an existing &quot;VTODO&quot; calendar request to the affected &quot;Attendees&quot;. The message is sent by the &quot;Organizer&quot; of a &quot;VTODO&quot; calendar component to the &quot;Attendees&quot; of the &quot;VTODO&quot; calendar component. For a recurring &quot;VTODO&quot; calendar component, either the whole &quot;VTODO&quot; calendar component or instances of a &quot;VTODO&quot; calendar component may be cancelled. To cancel the complete range of a recurring &quot;VTODO&quot; calendar component, the &quot;UID&quot; property value for the &quot;VTODO&quot; calendar component MUST be specified and a &quot;RECURRENCE- ID&quot; MUST NOT be specified in the &quot;CANCEL&quot; method. In order to cancel an individual instance of a recurring &quot;VTODO&quot; calendar component, the &quot;RECURRENCE-ID&quot; property value for the &quot;VTODO&quot; calendar component MUST be specified in the &quot;CANCEL&quot; method. There are two options for canceling a sequence of instances of a recurring &quot;VTODO&quot; calendar component: a. The &quot;RECURRENCE-ID&quot; property for an instance in the sequence MUST be specified with the &quot;RANGE&quot; property parameter value of &quot;THISANDFUTURE&quot; to indicate cancellation of the specified &quot;VTODO&quot; calendar component and all instances after. b. Individual recurrence instances may be cancelled by specifying multiple &quot;VTODO&quot; components each with a &quot;RECURRENCE-ID&quot; property corresponding to one of the instances to be cancelled. The &quot;Organizer&quot; MUST send a &quot;CANCEL&quot; message to each &quot;Attendee&quot; affected by the cancellation. This can be done by using either a single &quot;CANCEL&quot; message for all &quot;Attendees&quot; or multiple messages with different subsets of the affected &quot;Attendees&quot; in each. REFRESH The &quot;REFRESH&quot; method in a &quot;VTODO&quot; calendar component is used by &quot;Attendees&quot; of an existing &quot;VTODO&quot; calendar component to request an updated description from the &quot;Organizer&quot; of the &quot;VTODO&quot; calendar component. The &quot;Organizer&quot; of the &quot;VTODO&quot; calendar component MAY use this method to request an updated status from the &quot;Attendees&quot;. The &quot;REFRESH&quot; method MUST specify the &quot;UID&quot; property corresponding to the &quot;VTODO&quot; calendar component needing update. A refresh of a recurrence instance of a &quot;VTODO&quot; calendar component may be requested by specifying the &quot;RECURRENCE-ID&quot; property corresponding to the associated &quot;VTODO&quot; calendar component. The &quot;Organizer&quot; responds with the latest description and rendition of the &quot;VTODO&quot; calendar component. In most cases, this will be a &quot;REQUEST&quot; unless the &quot;VTODO&quot; has been cancelled, in which case the &quot;Organizer&quot; MUST send a &quot;CANCEL&quot;. This method is intended to facilitate machine processing of requests for updates to a &quot;VTODO&quot; calendar component.
