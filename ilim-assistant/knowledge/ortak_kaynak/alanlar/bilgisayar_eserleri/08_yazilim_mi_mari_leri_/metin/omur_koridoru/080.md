In situations where the &quot;UID&quot;, &quot;RECURRENCE-ID&quot;, and &quot;SEQUENCE&quot; property values match, the &quot;DTSTAMP&quot; property is used as the tie- breaker. The component with the latest &quot;DTSTAMP&quot; overrides all others. Similarly, for &quot;Attendee&quot; responses where the &quot;UID&quot;, &quot;RECURRENCE-ID&quot;, and &quot;SEQUENCE&quot; property values match, the response with the latest &quot;DTSTAMP&quot; overrides all others. Hence, CUAs will need to persist the following component properties in order to correctly process iTIP messages: &quot;UID&quot;, &quot;RECURRENCE-ID&quot;, &quot;SEQUENCE&quot;, and &quot;DTSTAMP&quot;. Furthermore, for each &quot;ATTENDEE&quot; property of a component, &quot;Organizer&quot; CUAs will need to persist the &quot;SEQUENCE&quot; and &quot;DTSTAMP&quot; property values associated with the &quot;Attendee&#x27;s&quot; last response, so that any earlier responses from an &quot;Attendee&quot; that are received out of order (e.g., due to a delay in the transport) can be correctly discarded. 3 . Application Protocol Elements iTIP messages are &quot;text/calendar&quot; MIME entities that contain calendaring and scheduling information. The particular type of iCalendar message is referred to as the &quot;method type&quot;. Each method type is identified by a &quot;METHOD&quot; property specified as part of the &quot;text/calendar&quot; content type.
