Property Parameters: IANA, non-standard, feature, and label property parameters can be specified on this property. Conformance: This property can be specified multiple times in a &quot;VEVENT&quot; or &quot;VTODO&quot; calendar component. Description: This property specifies information for accessing a conferencing system for attendees of a meeting or task. This might be for a telephone-based conference number dial-in with access codes included (such as a tel: URI [ RFC3966 ] or a sip: or sips: URI [ RFC3261 ]), for a web-based video chat (such as an http: or https: URI [ RFC7230 ]), or for an instant messaging group chat room (such as an xmpp: URI [ RFC5122 ]). If a specific URI for a conferencing system is not available, a data: URI [ RFC2397 ] containing a text description can be used. A conference system can be a bidirectional communication channel or a uni-directional &quot;broadcast feed&quot;. The &quot;FEATURE&quot; property parameter is used to describe the key capabilities of the conference system to allow a client to choose the ones that give the required level of interaction from a set of multiple properties. The &quot;LABEL&quot; property parameter is used to convey additional details on the use of the URI. For example, the URIs or access codes for the moderator and attendee of a teleconference system could be different, and the &quot;LABEL&quot; property parameter could be used to &quot;tag&quot; each &quot;CONFERENCE&quot; property to indicate which is which. The &quot;LANGUAGE&quot; property parameter can be used to specify the language used for text values used with this property (as per Section&nbsp;3.2.10 of [RFC5545] ). Security Considerations Several of the new properties or parameters defined by this specification allow reference to &quot;external&quot; URIs. Care MUST be taken when accessing data at external URIs as malicious content could be present. Clients SHOULD ensure that suitable permission is granted by calendar users before such URIs are dereferenced. The &quot;REFRESH-INTERVAL&quot; property could be used by an attacker to make a client carry out rapid requests to the server hosting the calendar by specifying a very short duration (e.g., one second). This could lead to resource consumption on the client or server and to denial- of-service attacks against the server. Clients MUST ensure that they throttle requests to the server to a reasonable rate. In most cases, updating a public calendar once per day would suffice. If the &quot;REFRESH-INTERVAL&quot; is any less than that, clients SHOULD warn the calendar user and allow them to override it with a longer value. The &quot;CONFERENCE&quot; property can include a &quot;FEATURE&quot; property parameter with a &quot;MODERATOR&quot; value.
