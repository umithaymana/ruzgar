This page describes tags for basic 3D attributes of buildings . This description scheme is therefore limited, not all details can be described by it. You can report cases of complex edits on the talk page or consult the page F3DB (Full 3D Building) for 3D mapping proposals advanced. The following tagging methods are results of the 2nd 3D Workshop Garching , where most 3D developers agreed on supporting a unified subset of tags in their programs. Basically, we describe the volume of a building using two types of areas: 1) building outlines ( building =&#42; ) for the most general area of a complex building and 2) building parts ( building:part =&#42; ) to describe sections of the building, especially those with different height or other attributes. Gaps between polygons are illustrative only, in reality their sides match precisely. The building outline represents the area of land covered by the union of all parts of the building. The outline may in most cases also be considered the building footprint. This is a closed way or multipolygon tagged with building =&#42; . Building attributes (e.g., address, name, overall height, operator, etc.) must be tagged on this building outline. A building should have a single area tagged building =&#42; . The building outline provides backward compatibility for 2D rendering software, such as Mapnik, and other data consumers not interested in 3D modeling. When a building has any building:part =&#42; areas, the building outline is not considered for 3D rendering &#91; 1 &#93; . Underground parts extending beyond the visible above-ground parts should not be included in the outline (see #Underground parts below). Building parts Parts of a building that have differing physical characteristics (height, color, etc) are usually modeled by drawing an area within the building outline tagged with the building:part =&#42; tag. The value of the building:part =&#42; tag is usually yes , but it can be any building =&#42; value (example building = yes , building:part = government and building:part = school if a building has a part used by the town hall and a room used as a classroom). The entire building outline should be filled with building:part =&#42; areas, tagged with their respective height and other attributes. These areas may overlap each other or may be disjunct, depending on the building. That said, while 2D footprints can (and often need to) overlap, avoid overlapping 3D volumes – especially if the volumes have common faces. See the following section for building tags typically applied to areas tagged with building:part =&#42; . Areas tagged with building:part =&#42; are mainly considered for 3D rendering. 2D renderers ignore the building attribute tags described in the following section. Editor Support Working with a distinct building =&#42; and building&#58;part =&#42; ways on top of each other in editors can be problematic. JOSM Overlapping shapes like this can be selected via the middle mouse or a left click while holding down the 'Alt' key to cycle through overlapping objects to make the selection you want. &#91; 2 &#93; Drawing multiple ways on top of each other can be achieve via plugins including Shrinkwrap and DuplicateWayInPlace , or out of the box via Tools &gt; Follow line, via Edit &gt; Paste at source position followed by a Validator fix to remove overlapping nodes. iD Overlapping ways can be selected by first selecting a common node then using Ctrl + UpArrow to reveal a list of the parent ways at that node in the panel. Underground parts If a building extends underground beyond the outline or footprint visible above the ground, treat these parts in the same way as overhanging parts. That is, tag the underground outlines of the building with building:part =&#42; with layer = -1 (and the overhanging parts with layer = 1 ). Create a type = building relation including the building =&#42; polygon and all the building:part =&#42; polygons. Assign a role = outline to the building =&#42; polygon and a role = part to the building:part =&#42; polygons, especially the underground part. Building relations There is no need to create a type = building relation, i.e. simply position all building parts inside the building outline. Relation could be useful in the case where at least one part of a building is hanging over the building footprint or if the building has a complex structure with lots of parts, a type = building relation can be used to group the building outline and all building parts together. If the type = building relation is present for a building, all building parts must be listed as the relation members with the role part . The building outline must be listed with the role outline . The building parts can be located in any possible way (inside, outside, intersecting, touching) relative to the building outline in the presence of the type = building relation. If there is no type = building relation, an application should treat all building parts within the area of the building outline as part of that building.
