Here, we proceed to write a simple JSON Schema. Hello, World! When learning any new language, it&#x27;s often helpful to start with the simplest thing possible. In JSON Schema, an empty object is a completely valid schema that will accept any valid JSON. schema { } ﻿ This accepts anything, as long as it&#x27;s valid JSON: data 42 ﻿ compliant to schema data &quot;I&#x27;m a string&quot; ﻿ compliant to schema data { &quot; an &quot; : [ &quot;arbitrarily&quot; , &quot;nested&quot; ] , &quot; data &quot; : &quot;structure&quot; } ﻿ compliant to schema New in draft 6 You can also use true in place of the empty object to represent a schema that matches anything, or false for a schema that matches nothing. This accepts anything, as long as it&#x27;s valid JSON: schema true ﻿ data 42 ﻿ compliant to schema data &quot;I&#x27;m a string&quot; ﻿ compliant to schema data { &quot; an &quot; : [ &quot;arbitrarily&quot; , &quot;nested&quot; ] , &quot; data &quot; : &quot;structure&quot; } ﻿ compliant to schema Documents for this schema will always be invalid: schema false ﻿ data &quot;Resistance is futile... This will always fail!!!&quot; ﻿ not compliant to schema The type keyword Of course, we wouldn&#x27;t be using JSON Schema if we wanted to just accept any JSON document. The most common thing to do in a JSON Schema is to restrict to a specific type. The type keyword is used for that. When this book refers to JSON Schema &quot;keywords&quot;, it means the &quot;key&quot; part of the key/value pair in an object. Most of the work of writing a JSON Schema involves mapping a special &quot;keyword&quot; to a value within an object. For example, in the following, only strings are accepted: schema { &quot; type &quot; : &quot;string&quot; } ﻿ data &quot;I&#x27;m a string&quot; ﻿ compliant to schema data 42 ﻿ not compliant to schema The type keyword is described in more detail in here . Declaring a JSON Schema It&#x27;s not always easy to tell which draft a JSON Schema is using. You can use the $schema keyword to declare which version of the JSON Schema specification the schema is written to. See $schema for more information. It&#x27;s generally good practice to include it, though it is not required. For brevity, the $schema keyword isn&#x27;t included in most of the examples in this book, but it should always be used in the real world. schema { &quot; $schema &quot; : &quot;https://json-schema.org/draft/2020-12/schema&quot; } ﻿ Draft-specific info In Draft 4, a $schema value of http://json-schema.org/schema# referred to the latest version of JSON Schema. This usage has since been deprecated and the use of specific version URIs is required. Declaring a unique identifier New in draft 6 It is also best practice to include an $id property as a unique identifier for each schema. For now, just set it to a URL at a domain you control, for example: schema { &quot; $id &quot; : &quot;http://yourdomain.com/schemas/myschema.json&quot; } ﻿ The details of $id become more apparent when you start structuring a complex schema .
