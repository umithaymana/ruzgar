This Month in Automerge: November '26 Skip to Content Automerge This Month in Automerge: November '26 A quick note on naming: starting with this edition, each issue is named for the month it comes out, not the month it covers. This one covers October, picking up right where the September edition left off, so nothing was skipped. As always, the community hangs out in the Automerge Discord . Come say hi, and let us know if you’d like something included in next month’s edition! ✨ Highlights Keyhive had a big month: a streamlined authority graph (Keyline), causal encryption, and a canonical codec all landed in Keyhive 0.6. automerge-repo 3.0, rebuilt on Subduction , is now out as an alpha. 📺 Community Call On October 8, Brooke Zelenka and Alex Good hosted our Q4 community call, and the recording is up on YouTube . Want to join the next one? Follow the Automerge calendar on Luma to hear when it’s scheduled. Automerge Masking Changes by Author In September , Automerge learned to record an author for each change. In October, Fintan Halpenny built the next step on top of that: hiding an author’s changes from your view of a document ( #1581 ). It’s on main now and will ship in the next release. import * as Automerge from "@automerge/automerge" // Hide everything `author` wrote after `heads` doc = Automerge . maskAuthor ( doc , author , heads ) Automerge . isAuthorMasked ( doc , author ) // true // ...and bring it back doc = Automerge . revealAuthor ( doc , author ) The point at which the author is cut off is called a write frontier . Changes from that author up to the frontier stay visible, and anything after it is hidden. Masking doesn’t delete anything or move the document’s heads. It only changes what your replica shows, so you can undo it with revealAuthor . We built this for Keyhive revocation. When Keyhive revokes someone’s access to a document, Automerge can stop showing the changes they made after that point, even if those changes still reach you through sync. We think masking is useful well beyond access control. For example, you could hide edits from a misbehaving bot or AI agent, review someone’s changes before accepting them, or see what a document looks like without one collaborator’s contributions. If you have other ideas, we’d love to hear them! Alex Good also made masking work when you only have part of the write frontier ( #1595 ). Your replica no longer has to wait for every head before it can show the changes you do have. Fintan made this fast too. Masked reads use Automerge’s indexes instead of scanning the whole document, and loading skips the reindex step when the mask hides nothing. Property tests check that patches and hydrated documents agree under every mask. Fixes &amp; Polish Aran Donohue fixed list_range on text, which returned the start and end of each mark as if they were characters ( #1608 ). For &quot;hello world&quot; with one mark, you now get eleven characters instead of thirteen items. Aran also added CI coverage for the utf16-indexing feature ( #1630 ). Thanks to first-time contributor Wahaj18 , looking up a cursor against the wrong object now returns InvalidCursor instead of panicking ( #1597 ). Fintan Halpenny migrated another benchmark ( load_actors ) from Criterion into the benchmark battery . 📦 automerge-repo Darcy Parker kept up the steady stream of fixes: Sync state is now saved per document, and removing DocHandle listeners now works correctly ( #773 ). react-hooks and solid-primitives no longer bundle their dependencies ( #758 ). The minimum versions of cbor-x and ws were raised to pick up upstream fixes ( #756 ). Importing an older copy of a document under the same ID can no longer delete newer stored changes during compaction ( #774 ). automerge-repo v3.0 (Alpha) Alex Currie-Clark spent much of October rebuilding automerge-repo on top of Subduction . Instead of plugging network and storage adapters straight into the Repo , automerge-repo 3.0 talks to a Sedimentree backend that owns them, and the first one is built on Subduction. The work went out early in the month as v3.0.0-experimental.1 and .2 , on npm under the experimental tag, and continued on its branch through the rest of October. In early November it graduated to a proper alpha: v3.0.0-alpha.1 is on npm under the next tag. What’s new: A simpler core. The old scheduler is gone.
