Status | Open Policy Agent Skip to main content The 2026 OPA Community Survey is open - We need your input On this page Status OPA can periodically report status updates to remote HTTP servers. The updates contain status information for OPA itself as well as the Bundles that have been downloaded and activated. OPA sends status reports whenever one of the following happens: Bundles are downloaded and activated -- If the bundle download or activation fails for any reason, the status update will include error information describing the failure. This includes Discovery bundles. A plugin state has changed -- All plugin status is reported, and an update to any plugin will trigger a Status API report which contains the latest state. Decision logs are uploaded -- Each upload attempt reports its outcome. If the upload fails, the status update will include error information describing the failure. When status.trigger is set to manual , these events don&#x27;t send reports on their own; reports are only sent when the status plugin is triggered. The status updates will include a set of labels that uniquely identify the OPA instance. OPA automatically includes an id value in the label set that provides a globally unique identifier or the running OPA instance and a version value that provides the version of OPA. See the Configuration Reference for configuration details. Status Service API ​ OPA expects the service to expose an API endpoint that will receive status updates. POST /status[/&lt;partition_name&gt;] HTTP/1.1 Content-Type : application/json The partition name is an optional path segment that can be used to route status updates to different backends.
