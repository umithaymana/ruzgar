Rego Keyword: contains | Open Policy Agent Skip to main content The 2026 OPA Community Survey is open - We need your input On this page Rego Keyword: contains Rego&#x27;s contains keyword is used to incrementally build multi-value rules in a policy. Often, tasks like validation are defined as a series of checks and these break down nicely into a series of contains rules that evaluate to a larger result. A contains rule typically takes the following form: my_rule contains value if { # logic to check if the value should be set # set the value # value := ... } However, there are some different ways to use contains in a policy which are covered in the examples below. note If you&#x27;re looking for the built-in function contains for substring checking, you can read about it in the built-ins section . Examples ​ Building sets While this first example is simple and unlikely to be useful when building real policies, it illustrates the fundamental reason for using the contains keyword: building sets. Sets are unordered collections, and they form an important building block for many policies. In this example, a multi-value rule defined using the contains keyword creates a simple list of todos. Just remember that sets are unordered and so you should not depend on the order of the result. data.json { } input.json { } policy.rego package play todo contains &quot;Buy bread for lunch&quot; todo contains &quot;Send off tax return&quot; todo contains &quot;Do laundry&quot; Output { &quot;todo&quot;: [ &quot;Buy bread for lunch&quot;, &quot;Do laundry&quot;, &quot;Send off tax return&quot; ] } Loading... In this example, if there are any failures then allow will be false. Using contains makes it possible to build up failures incrementally. policy.rego package play default allow := false allow if count ( reasons ) == 0 reasons contains &quot;name must be set&quot; if { object . get ( input , &quot;name&quot; , &quot;&quot; ) == &quot;&quot; } reasons contains &quot;@example.com email blocked&quot; if { endswith ( input . email , &quot;@example.com&quot; ) } reasons contains message if { input . age &lt; 18 message := sprintf ( &quot;you must be %d year older&quot; , [ 18 - input . age ] , ) } Output { &quot;allow&quot;: false, &quot;reasons&quot;: [ &quot;@example.com email blocked&quot;, &quot;name must be set&quot;, &quot;you must be 1 year older&quot; ] } Loading... input.json { &quot;email&quot; : &quot;name@example.com&quot; , &quot;age&quot; : 17 } data.json { } Open in OPA Playground Validating lists of objects Using contains is also useful when building up more complicated data structures in policies. In this example, contains is used to set validation errors that are grouped by the item they refer to. policy.rego package play approval_min := 350 reasons [ item . id ] contains &quot;category must be set&quot; if { some item in input . items object . get ( item , &quot;category&quot; , &quot;&quot; ) == &quot;&quot; } reasons [ item . id ] contains message if { some item in input . items item . amount &gt; approval_min object . get ( item , &quot;approved_by&quot; , &quot;&quot; ) == &quot;&quot; message := sprintf ( &quot;items over %d must be approved&quot; , [ approval_min ] , ) } reasons [ item . id ] contains &quot;approver does not exist&quot; if { some item in input . items not data . approvers [ item . approved_by ] } Output { &quot;approval_min&quot;: 350, &quot;reasons&quot;: { &quot;1bd91655&quot;: [ &quot;category must be set&quot; ], &quot;226c3910&quot;: [ &quot;items over 350 must be approved&quot; ], &quot;db5a4b23&quot;: [ &quot;approver does not exist&quot; ] } } Loading... input.json { &quot;items&quot; : [ { &quot;id&quot; : &quot;1bd91655&quot; , &quot;name&quot; : &quot;Lunch with James&quot; , &quot;amount&quot; : 57.5 } , { &quot;id&quot; : &quot;226c3910&quot; , &quot;name&quot; : &quot;Flight to Berlin&quot; , &quot;amount&quot; : 389.78 , &quot;category&quot; : &quot;conferences&quot; } , { &quot;id&quot; : &quot;db5a4b23&quot; , &quot;name&quot; : &quot;Recurring SaaS Subscription&quot; , &quot;amount&quot; : 30 , &quot;category&quot; : &quot;saas&quot; , &quot;approved_by&quot; : &quot;90400852&quot; } ] } data.json { &quot;approvers&quot; : { &quot;7f619663&quot; : { &quot;name&quot; : &quot;Alice&quot; , &quot;email&quot; : &quot;alice@example.com&quot; } } } Open in OPA Playground Examples Open Policy Agent is a Cloud Native Computing Foundation Graduated project. © 2026 Open Policy Agent contributors.
