If Keyword ​ This keyword allows more expressive rule heads: input.json { &quot;token&quot; : &quot;secret&quot; } deny if input . token != &quot;secret&quot; Contains Keyword ​ This keyword allows more expressive rule heads for partial set rules: deny contains msg if { msg := &quot;forbidden&quot; } Some Keyword ​ The some keyword in Rego can be used in both the some ... in form or in a standalone way to declare free variables. Both forms are used in rules to check if a solution to the rule exists. For examples, here a rule checks a user&#x27;s roles for admin: allow if { some role in input . user . roles role . id == &quot;admin&quot; } some can also be used to declare variables upfront in a rule, without binding a value. During evaluation, Rego will search to see if a solution exists for the rule while adhering to the use of the variables as constraints. This is useful if the rule contains unification statements or references with variable operands (if variables contained in those statements are not declared using the assignment operator := ). Every Keyword ​ The every keyword allows policy authors to express &#x27;For All&#x27; constraints in their rules in a readable way. The keyword takes a key argument (optional) and value argument to be used for further checks, a domain to select items from, and a block of further statements to check (the &quot;body&quot;). package example import data . example . sites names_with_dev if { some site in sites site . name == &quot;dev&quot; every server in site . servers { endswith ( server . name , &quot;-dev&quot; ) } } Loading... The keyword is used to explicitly assert that its body is true for any element in the domain . It will iterate over the domain, bind its variables, and check that the body holds for those bindings. If one of the bindings does not yield a successful evaluation of the body, the overall statement is undefined. If the domain is empty, the overall statement is true. Evaluating every does not introduce new bindings into the rule evaluation. Used with the optional key argument, the index, or property name (for objects), comes into the scope of the body evaluation: package example array_domain if { every i , x in [ 1 , 2 , 3 ] { x - i == 1 } # array domain } object_domain if { every k , v in { &quot;foo&quot; : &quot;bar&quot; , &quot;fox&quot; : &quot;baz&quot; } { # object domain startswith ( k , &quot;f&quot; ) startswith ( v , &quot;b&quot; ) } } set_domain if { every x in { 1 , 2 , 3 } { x != 4 } # set domain } Loading... info Negating every is forbidden. If you need to express not every x in xs { p(x) } please use some x in xs; not p(x) instead. And and Or Keywords ​ The and and or keywords express conjunction and disjunction within a single rule body, without the need to extract a helper rule. Both require an import ( future.keywords.and / future.keywords.or , or rego.v2 ), and neither produces a value; an expression using them either succeeds or fails: package example import future . keywords . or allow if { input . user . admin or input . user . owner } or is not a replacement for expressing disjunction with incremental rules , which remains the idiom when the disjunction needs to contribute a value. See Rego Keyword Examples: and, or for precedence, scoping, and when to prefer each. With Keyword ​ The with keyword allows queries to programmatically specify values nested under the input document or the data document , or built-in functions . For example, given the simple authorization policy in the imports section, a query can check whether a particular request would be allowed: package authz import data . examples . allow result := true if { allow with input as { &quot;user&quot; : &quot;alice&quot; , &quot;method&quot; : &quot;POST&quot; } } Loading... package authz import data . examples . allow result := true if { allow with input as { &quot;user&quot; : &quot;bob&quot; , &quot;method&quot; : &quot;GET&quot; } } Loading... package authz import data . examples . allow result := true if { not allow with input as { &quot;user&quot; : &quot;bob&quot; , &quot;method&quot; : &quot;DELETE&quot; } } Loading... The with keyword acts as a modifier on expressions. A single expression is allowed to have zero or more with modifiers. The with keyword has the following syntax: &lt;expr&gt; with &lt;target-1&gt; as &lt;value-1&gt; [with &lt;target-2&gt; as &lt;value-2&gt; [...]] The &lt;target&gt; s must be references to values in the input document (or the input document itself) or data document, or references to functions (built-in or not). info When applied to the data document, the &lt;target&gt; must not attempt to partially define virtual documents. For example, given a virtual document at path data.foo.bar , the compiler will generate an error if the policy attempts to replace data.foo.bar.baz . The with keyword only affects the attached expression. Subsequent expressions will see the unmodified value. The exception to this rule is when multiple with keywords are in-scope like below: inner := [ x , y ] if { x := input . foo y := input . bar } middle := [ a , b ] if { a := inner with input . foo as 100 b := input } outer := result if { result := middle with input as { &quot;foo&quot; : 200 , &quot;bar&quot; : 300 } } When &lt;target&gt; is a reference to a function, like http.send , then its &lt;value&gt; can be any of the following: a value: with http.send as {&quot;body&quot;: {&quot;success&quot;: true }} a reference to another function: with http.send as mock_http_send a reference to another (possibly custom) built-in function: with custom_builtin as less_strict_custom_builtin a reference to a rule that will be used as the value . When the replacement value is a function, its arity needs to match the replaced function&#x27;s arity; and the types must be compatible. Replacement functions can call the function they&#x27;re replacing without causing recursion . See the following example: package mock f ( x ) := count ( x ) mock_count ( x ) := 0 if &quot;x&quot; in x mock_count ( x ) := count ( x ) if not &quot;x&quot; in x result := v if { v := f ( [ &quot;x&quot; , 2 , 3 ] ) with count as mock_count } Loading... Each replacement function evaluation will start a new scope: it&#x27;s valid to use with &lt;builtin1&gt; as ... in the body of the replacement function -- for example: package mocks f ( x ) := count ( x ) if { rule_using_concat with concat as &quot;foo,bar&quot; } Note that function replacement via with does not affect the evaluation of the function arguments: if running f(input.x), and input.x is undefined, the replacement of concat` does not change the result of the evaluation.
