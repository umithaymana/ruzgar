Some for arbitrary iteration The some keyword can also be used to instantiate variables used in arbitrary iteration. Rego Keyword: every | Open Policy Agent Skip to main content The 2026 OPA Community Survey is open - We need your input On this page Rego Keyword: every Rego rules and statements are existentially quantified by default. This means that if there is any solution then the rule is true, or a value is bound. Some policies require checking all elements in an array or object. The every keyword makes this universal quantification easier. The following two equivalent rules achieve universal quantification. Note how much easier to read the one using every is. package play allow1 if { every e in [ 1 , 2 , 3 ] { e &lt; 4 } } # without every, don&#x27;t do this! allow2 if { { r | some e in [ 1 , 2 , 3 ] ; r := e &lt; 4 } == { true } } allow2 works by generating a set of &#x27;results&#x27; testing elements from the array [1,2,3] . The resulting set is tested against {true} to verify all elements are true . every is a much better option! Partial evaluation ​ During partial evaluation , an every over a known collection of at most 32 elements is evaluated once per element, and the result is the conjunction of the body for each. That is what lets the Compile API turn it into a filter: with input.banned set to [&quot;a&quot;, &quot;b&quot;] , every x in input.banned { input.fruits.name != x } gives WHERE (fruits.name &lt;&gt; &#x27;a&#x27; AND fruits.name &lt;&gt; &#x27;b&#x27;) for the SQL targets. An empty collection leaves no condition: the every is true, and the query is true . If the body is false for one of the elements, the every is false, and no query remains. With more elements, or an unknown collection, the every stays in the result. Nested every s count together: unrolling stops once the elements of the enclosing ones multiplied by those of the inner collection exceed 32. Examples ​ Checking every feature flag The every keyword is used here to validate that an example session has all the required feature flags for a request. test_speedy_checkout is false in the input.json , this will need to be true for the user to be allowed to load the new checkout page. policy.rego package play default allow := false allow if { input . path == &quot;/new/checkout&quot; every feature in new_checkout_features { input . features [ feature ] == true } } new_checkout_features := { &quot;new_ui&quot; , &quot;test_speedy_checkout&quot; , } Output { &quot;allow&quot;: false, &quot;new_checkout_features&quot;: [ &quot;new_ui&quot;, &quot;test_speedy_checkout&quot; ] } Loading... input.json { &quot;features&quot; : { &quot;new_ui&quot; : true , &quot;test_speedy_checkout&quot; : false } , &quot;path&quot; : &quot;/new/checkout&quot; , &quot;email&quot; : &quot;alice@example.com&quot; } data.json { } Open in OPA Playground Enforcing meeting invite rules every can also be used to check an object&#x27;s keys and values.
