Backward-incompatible changes We do our best to avoid making changes to existing functionality that might unexpectedly impact your Home Assistant installation. Unfortunately, sometimes it is inevitable. We always make sure to document these changes to make the transition as easy as possible for you. This release has the following backward-incompatible changes: AdGuard Home The Query log switch of the AdGuard Home integration now requires AdGuard Home v0.107.30 or newer. On older versions, the switch becomes unavailable. If AdGuard Home forces HTTPS while the integration is set up without SSL, setup now fails instead of following the redirect to HTTPS. To fix this, remove the integration and add it again with SSL enabled. ( @frenck - #184349 ) ( AdGuard Home documentation ) Alert card The Alert card now shows its color and its pulse only while the entity An entity represents a sensor, actor, or function in Home Assistant. Entities are used to monitor physical properties or to control other entities. An entity is usually part of a device or a service. [Learn more] is in an alert state, and it supports alarm control panel, binary sensor, cover, and lock entities. The color option is renamed to alert_color , and a new clear_color option sets the color for the rest of the time. Without an alert_color , the card is red during an alert. Set alert_color: none to leave it uncolored. The card was made for the home and security dashboards, which are not affected. If you added it to a dashboard in YAML YAML is a human-readable data serialization language. It is used to store and transmit data in a structured format. In Home Assistant, YAML is used for configuration, for example in the configuration.yaml or automations.yaml files. [Learn more] yourself, update it to the new options. ( @timmo001 - frontend#54880 ) Apple iCloud Completed reminders are no longer fetched by default. The iCloud integration used to include completed reminders in every Reminders fetch, which on accounts with a very large history could block startup for a long time. To keep the old behavior, enable Include completed reminders during setup or afterward in the integration options under Settings &gt; Devices &amp; services &gt; Apple iCloud &gt; Options . ( @timlaing - #186175 ) ( Apple iCloud documentation ) Auth When you reach Home Assistant at an IP address that is not on a local network, such as a public address, a global IPv6 address, or a Tailscale address ( 100.64.0.0/10 ), the address in your browser now has to match the address Home Assistant sees the request coming in on. Scheme, host, and port all have to match. If they do not, logging in fails with “Invalid client id”. Previously, such an address was accepted without that check as soon as it had a port, because of a bug in the check. Most setups are not affected. Opening Home Assistant directly at such an address keeps working, and so does a reverse proxy that you have set up as a trusted proxy in the HTTP integration, because Home Assistant then uses the forwarded scheme and host. Domain names and local network IP addresses are accepted the same way as before. If you do run into “Invalid client id”, add your proxy to the trusted proxies of the HTTP integration, or reach Home Assistant through a domain name.
