Identity attacks make the same point beyond the operating system. The Midnight Blizzard (APT29) intrusion at Microsoft, detected in January 2024, began with a password spray against a legacy, non-production test account with no multi-factor authentication. No zero-day, no malware, a forgotten account missing one baseline control. MFA isn&rsquo;t an OS setting, so the relevant controls live elsewhere in the family: the CIS Microsoft 365 Foundations Benchmark had called for enforcing MFA and blocking legacy authentication for years beforehand. CIS publishes more than 150 Benchmarks for more than 25 vendor product families; hardening only the OS leaves the forgotten cloud tenant wide open. The Government&rsquo;s Own Red Teams Agree In October 2023, NSA and CISA published a joint advisory (AA23-278A) distilling years of red-team and incident-response engagements. The most common weakness on the list: default configurations, out-of-the-box settings nobody hardened, and the agencies were explicit that these gaps persist even in organizations with otherwise mature programs. The people paid to break into well-defended networks report that what lets them in is not the missing patch. It&rsquo;s the setting nobody changed. Why Configuration is the More Durable Investment A patch is tied to one specific defect. A secure configuration is tied to a capability, so it neutralizes every attack that depends on that capability, including ones that don&rsquo;t exist yet. Disabling SMBv1 didn&rsquo;t just stop WannaCry; it closed the same propagation path NotPetya reached for six weeks later, and every subsequent SMB worm after that. Patching addresses known-bad; configuration reduces the surface an attacker could abuse whether a defect has been found or not, which is why it doesn&rsquo;t decay when the next vulnerability drops. When Benchmark recommendations are mapped to MITRE ATT&amp;CK techniques, the striking thing is the continuity:&nbsp;the recommendations that would have blunted 2017&rsquo;s worms are the ones blunting today&rsquo;s ransomware crews. The threats iterate; the configuration barely has to. Why the Whole Profile Matters The examples above focus on only a handful of settings. Real baselines are much larger: 393 Level 1 recommendations for Windows 11 and 331 recommendations for a Windows Server 2025 Member Server. Given the hindsight problem we started with, "just do the important ones" really means "accurately predict next year's attacker tradecraft." That's the same race security teams are already losing. A CIS Benchmark works more like an index fund than a stock-picking strategy. You adopt the entire profile because you don't know in advance which controls will matter most. The value comes from inheriting hundreds of lessons already learned by others, without having to experience the incidents that taught them. Intrusions are also chains (initial access, privilege escalation, credential theft, lateral movement, etc.) and different settings break different links. NotPetya spread by credential theft as well as by EternalBlue, so environments that had addressed only one vector still burned. On any given day most of your settings are doing &ldquo;nothing&rdquo;; that redundancy is defense-in-depth by design, not waste. Level 1 recommendations are designed for minimal business impact, but not zero impact. Settings related to Store access, App Installer, OneDrive synchronization, and legacy authentication can still require legitimate business exceptions. The goal is to identify and document those exceptions during testing, rather than discovering them after deployment. What the profile provides is consistency. Exceptions become deliberate, documented decisions rather than hundreds of unnoticed gaps. And a word on cost: CIS Benchmarks are free to download. Tooling used to assess and enforce them at scale ranges from free solutions to commercial offerings, including CIS's own CIS-CAT Pro. What Secure Configuration Can't Do Configuration cannot fix a code-level flaw in a service you genuinely must run. Hardening also carries real implementation costs: testing against business applications, negotiating exceptions with the teams that own them, re-testing when the Benchmark revises, and watching for drift. None of that argues for doing less. It argues for treating configuration as an operational discipline (baselined, measured, monitored) rather than a one-time checkbox. Nor does configuration replace the rest of the security stack. EDR, a SIEM and the people watching it, and a practiced incident-response capability all handle what no baseline can: the attack that gets through anyway. Configuration makes those investments work better. The Benchmarks&rsquo; audit policy recommendations generate much of the Windows telemetry a SIEM ingests, and other settings keep built-in protections and logging enabled and tamper-resistant. A hardened fleet is a quieter one, so real signals stand out. The layers need each other. The same limitation applies to AI systems. Hardening the host an agent runs on, restricting what it can do, and controlling what it can access are configuration problems with configuration solutions. However, a model following a malicious instruction embedded in the data it processes, such as prompt injection, is the AI-era equivalent of a code-level vulnerability that no Benchmark setting can eliminate. Secure configuration can reduce the impact of such attacks by limiting what compromised systems can reach. It cannot prevent the model itself from being deceived. The Bottom Line Patch quickly. But be honest about what patching can never provide: protection before disclosure, protection before a fix exists, and protection for the systems that inevitably miss the update cycle.
