Stack and Memory Protections &para; /GS (Buffer Security Check): On by default; do not disable it. Places a security cookie before the return address (and, on x86, the exception handler address) of functions with vulnerable buffers; does not protect heap buffers or locals that the compiler does not treat as vulnerable. Control-Flow Integrity and Binary Layout &para; /guard:cf (Control Flow Guard): Mitigates control-flow hijacking by verifying that indirect call targets point to compiler-approved functions; must be enabled in both compiler and linker and does not protect return addresses on the stack. /guard:ehcont (Exception Handling (EH) Continuation Guard): Generates metadata listing valid exception handling continuation targets to prevent control-flow hijacking during exception unwinding. Pass it to both the compiler and the linker. Supported only for 64-bit processes and meant to work with CET shadow stacks; modules built without it are not protected. /DYNAMICBASE (Linker, on by default): Enables ASLR by instructing the operating system loader to randomize the binary load address; does not prevent memory disclosure attacks that reveal relocated base addresses. /HIGHENTROPYVA (Linker): Enables 64-bit high-entropy ASLR to increase address randomization space; applies only to 64-bit targets and requires /DYNAMICBASE . /NXCOMPAT (Linker, on by default): Marks the executable as compatible with Data Execution Prevention (DEP), preventing code execution from data pages; does not prevent code-reuse attacks executing from existing executable memory. /CETCOMPAT (Linker): Marks the executable image as compatible with CET shadow stack; x64 only, and requires a CET-capable processor and operating system. Warning Suppression &para; Strict warning levels produce some false positives because the compiler cannot know every runtime invariant. Suppress individual false positives in the code. Do not turn warnings off globally. Silencing spurious warnings lets you focus on the ones that matter. First is an unused parameter (for example, argc or argv ). In modern C++ (C++17 and later), prefer the standard [[maybe_unused]] attribute; in C or earlier standards, define an unused parameter macro or cast the parameter to void : #define UNUSED_PARAMETER(x) ((void)(x)) … int main ( int argc , char * argv []) { UNUSED_PARAMETER ( argc ); UNUSED_PARAMETER ( argv ); … } A potential minefield lies near "comparing unsigned and signed" values, and -Wconversion will catch it for you. This is because C/C++ promotion rules state the signed value will be promoted to an unsigned value and then compared. That means -1 &gt; 1 after promotion!
