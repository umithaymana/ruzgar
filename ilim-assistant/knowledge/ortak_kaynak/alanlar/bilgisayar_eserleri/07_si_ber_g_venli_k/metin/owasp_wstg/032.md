Home of ASD Plugin for ZAP Home of ASD Plugin for PortSwigger Burp OWASP Noir OWASP Noir is a command-line tool that finds the endpoints of a web application by analyzing its source code. For each endpoint it reports the HTTP method and the parameters read from the query string, request body, path, headers, and cookies. This includes endpoints that no page links to and parameters that the client-side code never sends, which a spider would miss. Noir supports many languages and frameworks, including Rails, Django, Express, Spring, and Laravel. See the supported languages and frameworks for the full list. Noir writes its results in many output formats , including plain text, JSON, OpenAPI, and curl commands. It can also replay the discovered endpoints through an intercepting proxy such as ZAP or Burp Suite, so they appear in the proxy history with the rest of the captured traffic. How to Use Install Noir by following the installation guide , then run the scan command against the root directory of the source code: noir scan &lt;source-code-path&gt; [flags] Here is an example of running the command against OWASP RailsGoat , the same application used in the Attack Surface Detector example above. Each entry lists the method, the path, and the parameters grouped by location ( path , body , cookies ). Some of these are easy to miss while browsing, such as the font cookie read by /dashboard/home . Change the output format with -f to feed the results into other tools. The curl format prints one request per endpoint, and -u sets the base URL: $ noir scan railsgoat --no-log -f curl -u http://localhost:3000 curl -i -X 'GET' 'http://localhost:3000/api/v1/mobile/1?class=' curl -i -X 'GET' 'http://localhost:3000/api/v1/mobile?class=' curl -i -X 'GET' 'http://localhost:3000/api/v1/users' curl -i -X 'GET' 'http://localhost:3000/api/v1/users/1' curl -i -X 'GET' 'http://localhost:3000/users/1/benefit_forms' curl -i -X 'GET' 'http://localhost:3000/users/1/messages' ... snipped ... To send every endpoint through an intercepting proxy for manual testing, add --probe-via with the proxy address: noir scan railsgoat -u http://localhost:3000 --probe-via http://127.0.0.1:8080 Noir can also export an OpenAPI document for import into ZAP or Burp Suite. See API Reconnaissance for an example. Application Entry Points The following are two examples on how to check for application entry points. GET Requests This example shows a GET request that would purchase an item from an online shopping application. GET /shoppingApp/buyme.asp?CUSTOMERID=100&amp;ITEM=z101a&amp;PRICE=62.50&amp;IP=x.x.x.x HTTP/1.1 Host: x.x.x.x Cookie: SESSIONID=Z29vZCBqb2IgcGFkYXdhIG15IHVzZXJuYW1lIGlzIGZvbyBhbmQgcGFzc3dvcmQgaXMgYmFy All the parameters of the request such as CUSTOMERID, ITEM, PRICE, IP, and the Cookie, which could just be encoded parameters or parameters used for session state. POST Requests This example shows a POST request that would log you into an application. POST /example/authenticate.asp?service=login HTTP/1.1 Host: x.x.x.x Cookie: SESSIONID=dGhpcyBpcyBhIGJhZCBhcHAgdGhhdCBzZXRzIHByZWRpY3RhYmxlIGNvb2tpZXMgYW5kIG1pbmUgaXMgMTIzNA==;CustomCookie=00my00trusted00ip00is00x.x.x.x00 user=admin&amp;pass=pass123&amp;debug=true&amp;fromtrustIP=true It can be noted that the parameters are sent in several locations: In the query string: service In the Cookie header: SESSIONID , CustomCookie In the request body: user , pass , debug , fromtrustIP Having a variety of injection locations provides the attacker with chaining possibilities that could improve the chances of finding a bug in the handling code.
