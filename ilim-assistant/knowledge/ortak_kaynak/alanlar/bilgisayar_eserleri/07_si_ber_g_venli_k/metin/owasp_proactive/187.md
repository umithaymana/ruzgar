For over-the-air (OTA) and workshop updates, verify signed metadata, image hashes, target hardware, freshness, and rollback policy. Follow Uptane's update verification requirements ; transport encryption alone cannot establish update authenticity. Plan safe recovery. Activate updates only under agreed safe vehicle conditions. Recover from interrupted installation using authenticated software, without bypassing rollback protections. Signatures do not establish that software is free of vulnerabilities; protect the software supply chain too. Restrict Access and Protect Data &para; Authorize each operation. Enforce authorization for the specific vehicle and action in backend services and vehicle command handlers. Separate owner, fleet, and service privileges. Revoke previous users' access when ownership or rental access ends. Protect service interfaces. Disable unnecessary production debug access; authenticate and restrict necessary diagnostic functions while preserving authorized repair. Physical access is not authorization. See NHTSA sections 7–8.4 . Protect keys and stored data. Avoid shared fleet-wide access secrets. Use hardware-backed key protection where available, with renewal and revocation procedures. Minimize retained location and personal data; encrypt sensitive storage with keys protected separately from the data. Encryption limits offline extraction, but software authorized to decrypt data can still expose it. Test and Maintain Security &para; Follow NHTSA's lifecycle practices, section 4.2 : Track component versions against deployed vehicles so vulnerabilities lead to targeted fixes. Agree with suppliers on patch ownership and support duration. Test rejected commands, malformed inputs, replay handling, and interrupted updates on isolated benches or simulators. Verify both security enforcement and safe failure behavior before vehicle deployment. Log authentication failures, privileged operations, and update results without secrets. Assign responsibility for reviewing events and responding to reports. For components that cannot be patched, restrict reachable interfaces and plan replacement. Gateway filtering reduces exposure but does not repair vulnerable firmware.
