Apprenez Vue avec des tutoriels vidéos sur VueMastery.com Qu&#39;est-ce que Vue? ​ Vue (/vjuː/ à prononcer comme en anglais: view ) est un framework JavaScript qui se repose sur les standards HTML, CSS et JavaScript. Il propose une manière efficace de déclarer des composants pour la construction d&#39;interfaces utilisateur de toute complexité. Voici un exemple simple : js import { createApp } from &#39;vue&#39; createApp ({ data () { return { count: 0 } } }). mount ( &#39;#app&#39; ) js import { createApp, ref } from &#39;vue&#39; createApp ({ setup () { return { count: ref ( 0 ) } } }). mount ( &#39;#app&#39; ) template &lt; div id = &quot;app&quot; &gt; &lt; button @ click = &quot; count ++ &quot; &gt; Le compteur est à {{ count }} &lt;/ button &gt; &lt;/ div &gt; Résultat Le compteur est à 0 Cet exemple illustre les deux principales fonctionnalités de Vue : Rendu déclaratif : Vue s&#39;appuie sur le standard HTML avec une syntaxe de type template qui permet de décrire de manière déclarative la structure HTML tout en étant basée sur un état JavaScript. Réactivité : Vue traque automatiquement tout changement d&#39;état JavaScript et met à jour efficacement le DOM en cas de changement. Il se peut que vous ayez déjà des questions - pas d&#39;inquiétude. Nous allons couvrir tous les petits détails dans la suite de la documentation. Une précédente expérience avec d&#39;autres frameworks vous aidera, mais n&#39;est pas strictement requise. Le Framework Évolutif ​ Vue est un framework et un écosystème qui couvre la plupart des fonctionnalités courantes nécessaires au développement front-end. Le Web est très diversifié; les choses que nous y construisons peuvent varier radicalement. C&#39;est pourquoi Vue a été conçu pour être flexible et adoptable de manière incrémentale. En fonction de votre cas d&#39;utilisation, Vue peut être utilisé de différentes manières : Extension du HTML statique sans étape de construction Intégration de Web Components (éléments personnalisés) sur n&#39;importe quelle page Application mono-page (SPA) Fullstack / Rendu côté serveur (SSR) JAMStack / Génération de sites statiques (SSG) Adapté pour l&#39;ordinateur de bureau, le mobile, pour le WebGL et même le terminal. Si vous trouvez ces concepts intimidants, ne vous inquiétez pas ! Le tutoriel et le guide ne requièrent que des connaissances de base en HTML et en JavaScript, et vous devriez pouvoir les suivre sans être un expert dans l&#39;un de ces domaines. Si vous êtes un développeur expérimenté et que vous souhaitez savoir comment intégrer au mieux Vue dans vos outils, ou si vous êtes curieux de savoir ce que ces termes signifient, nous en parlons plus en détail dans Les manières d&#39;utiliser Vue . Malgré la flexibilité, les connaissances de base sur le fonctionnement de Vue sont partagées dans tous ces cas d&#39;utilisation. Même si vous n&#39;êtes qu&#39;à vos débuts, les connaissances acquises en cours de route vous seront utiles pour atteindre des objectifs plus ambitieux à l&#39;avenir. Si vous avez un niveau expérimenté, vous pouvez choisir la manière optimale de tirer parti de Vue en fonction des problèmes que vous essayez de résoudre, tout en conservant la même productivité. C&#39;est pourquoi nous appelons Vue &quot;le framework évolutif&quot; : c&#39;est un framework qui peut grandir avec vous et s&#39;adapter à vos besoins. Composant monofichier (Single-File Components) ​ Dans la plupart des projets Vue dotés d&#39;outils de construction, nous créons des composants Vue en utilisant un format de fichier semblable à HTML appelé Composant monofichier , ou Single-File Component en anglais (également connu sous le nom de fichiers *.vue , abrégé en SFC ). Un SFC Vue, comme son nom l&#39;indique, encapsule la logique (JavaScript), le modèle (HTML) et les styles (CSS) du composant dans un seul fichier. Voici l&#39;exemple précédent, écrit au format SFC : vue &lt; script &gt; export default { data () { return { count: 0 } } } &lt;/ script &gt; &lt; template &gt; &lt; button @click = &quot;count++&quot; &gt;Le compteur est à {{ count }}&lt;/ button &gt; &lt;/ template &gt; &lt; style scoped &gt; button { font-weight : bold ; } &lt;/ style &gt; vue &lt; script setup &gt; import { ref } from &#39;vue&#39; const count = ref ( 0 ) &lt;/ script &gt; &lt; template &gt; &lt; button @click = &quot;count++&quot; &gt;Le compteur est à {{ count }}&lt;/ button &gt; &lt;/ template &gt; &lt; style scoped &gt; button { font-weight : bold ; } &lt;/ style &gt; Les SFC sont une fonctionnalité essentielle de Vue, et c&#39;est la manière recommandée de créer des composants Vue si votre usage justifie une configuration avancée (usant d&#39;outils de construction). Vous pouvez en savoir plus sur le comment et pourquoi faire des SFC dans la section qui lui est consacrée - mais pour l&#39;instant, sachez que Vue se chargera de la configuration des outils de construction pour vous. Styles d&#39;API ​ Les composants Vue peuvent être créés dans deux styles d&#39;API différents : l&#39; Options API et la Composition API . Options API ​ Avec l&#39;Options API, nous définissons la logique d&#39;un composant en utilisant un objet d&#39;options telles que data , methods , et mounted . Les propriétés définies par les options sont exposées sur this dans les fonctions, qui pointe sur l&#39;instance du composant : vue &lt; script &gt; export default { // état réactif data () { return { count: 0 } }, // Les méthodes sont des fonctions qui modifient l&#39;état et déclenchent des mises à jour // Elles peuvent être utilisées par des gestionnaires d&#39;événements dans le template. methods: { increment () { this .count ++ } }, // hooks de cycle de vie mounted () { console. log ( `La valeur initiale de count est ${ this . count }.` ) } } &lt;/ script &gt; &lt; template &gt; &lt; button @click = &quot;increment&quot; &gt;Count is: {{ count }}&lt;/ button &gt; &lt;/ template &gt; Essayer en ligne Composition API ​ Avec la Composition API, nous définissons la logique d&#39;un composant à l&#39;aide de fonctions API importées. Dans les SFC, la Composition API est généralement utilisée avec &lt;script setup&gt; . L&#39;attribut setup est une indication qui permet à Vue d&#39;effectuer des transformations au moment de la compilation, ce qui nous permet d&#39;utiliser la Composition API avec moins de code nécessaire aux déclarations. Par exemple, les importations et les variables / fonctions déclarées au niveau racine dans &lt;script setup&gt; sont directement utilisables dans le modèle. Voici le même composant, avec exactement le même modèle, mais en utilisant la Composition API et &lt;script setup&gt; à la place : vue &lt; script setup &gt; import { ref, onMounted } from &#39;vue&#39; // état réactif const count = ref ( 0 ) // fonctions qui modifient l&#39;état et déclenchent des mises à jour function increment () { count.value ++ } // hooks de cycle de vie onMounted (() =&gt; { console. log ( `La valeur initiale de count est ${ count . value }.` ) }) &lt;/ script &gt; &lt; template &gt; &lt; button @click = &quot;increment&quot; &gt;Count is: {{ count }}&lt;/ button &gt; &lt;/ template &gt; Essayer en ligne Laquelle choisir ? ​ Tout d&#39;abord, les deux styles d&#39;API sont parfaitement capables de couvrir les cas d&#39;utilisation courants. Il s&#39;agit de différentes interfaces alimentées par le même système sous-jacent. En fait, l&#39;Options API est implémentée par dessus la Composition API ! Les concepts fondamentaux et les connaissances sur Vue sont partagés entre les deux styles. L&#39;Options API est centrée sur le concept d&#39;une &quot;instance de composant&quot; ( this comme dans l&#39;exemple), qui s&#39;aligne généralement mieux sur un modèle mental basé sur les classes pour les utilisateurs issus de la POO. Elle est également plus adaptée aux débutants, car elle fait abstraction des détails de la réactivité et impose une organisation du code par le biais de groupes d&#39;options. La Composition API est centrée sur la déclaration de variables d&#39;état réactives directement dans la portée d&#39;une fonction, et sur la composition de l&#39;état de plusieurs fonctions pour gérer la complexité. Elle offre une plus grande liberté d&#39;écriture et nécessite une compréhension du fonctionnement de la réactivité dans Vue pour être utilisée efficacement. En retour, sa flexibilité permet des modèles plus puissants pour organiser et réutiliser la logique. Pour en savoir plus sur la comparaison entre les deux styles et les avantages potentiels de la Composition API, consultez la FAQ sur la Composition API . Si Vue est nouveau pour vous, voici notre recommandation générale : Pour l&#39;apprentissage, choisissez le style qui vous semble le plus facile à comprendre.
