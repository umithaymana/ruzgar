Starting in Vue 3.4, the recommended approach to achieve this is using the defineModel() macro: Child.vue vue &lt; script setup &gt; const model = defineModel () function update () { model.value ++ } &lt;/ script &gt; &lt; template &gt; &lt; div &gt;Parent bound v-model is: {{ model }}&lt;/ div &gt; &lt; button @click = &quot;update&quot; &gt;Increment&lt;/ button &gt; &lt;/ template &gt; The parent can then bind a value with v-model : Parent.vue template &lt; Child v-model = &quot; countModel &quot; /&gt; The value returned by defineModel() is a ref. It can be accessed and mutated like any other ref, except that it acts as a two-way binding between a parent value and a local one: Its .value is synced with the value bound by the parent v-model ; When it is mutated by the child, it causes the parent bound value to be updated as well. This means you can also bind this ref to a native input element with v-model , making it straightforward to wrap native input elements while providing the same v-model usage: vue &lt; script setup &gt; const model = defineModel () &lt;/ script &gt; &lt; template &gt; &lt; input v-model = &quot;model&quot; /&gt; &lt;/ template &gt; Try it in the playground Under the Hood ​ defineModel is a convenience macro. The compiler expands it to the following: A prop named modelValue , which the local ref&#39;s value is synced with; An event named update:modelValue , which is emitted when the local ref&#39;s value is mutated. This is how you would implement the same child component shown above prior to 3.4: Child.vue vue &lt; script setup &gt; const props = defineProps ([ &#39;modelValue&#39; ]) const emit = defineEmits ([ &#39;update:modelValue&#39; ]) &lt;/ script &gt; &lt; template &gt; &lt; input :value = &quot;props.modelValue&quot; @input = &quot;emit(&#39;update:modelValue&#39;, $event.target.value)&quot; /&gt; &lt;/ template &gt; Then, v-model=&quot;foo&quot; in the parent component will be compiled to: Parent.vue template &lt; Child : modelValue = &quot; foo &quot; @ update : modelValue = &quot; $event =&gt; (foo = $event) &quot; /&gt; As you can see, it is quite a bit more verbose. However, it is helpful to understand what is happening under the hood. Because defineModel declares a prop, you can therefore declare the underlying prop&#39;s options by passing it to defineModel : js // making the v-model required const model = defineModel ({ required: true }) // providing a default value const model = defineModel ({ default: 0 }) WARNING If you have a default value for defineModel prop and you don&#39;t provide any value for this prop from the parent component, it can cause a de-synchronization between parent and child components. In the example below, the parent&#39;s myRef is undefined, but the child&#39;s model is 1: Child.vue vue &lt; script setup &gt; const model = defineModel ({ default: 1 }) &lt;/ script &gt; Parent.vue vue &lt; script setup &gt; const myRef = ref () &lt;/ script &gt; &lt; template &gt; &lt; Child v-model = &quot;myRef&quot; &gt;&lt;/ Child &gt; &lt;/ template &gt; Also, when using withDefaults with defineProps , default values for mutable reference types (like arrays or objects) should be wrapped in functions in defineModel to avoid accidental modification and external side effects. First let&#39;s revisit how v-model is used on a native element: template &lt; input v-model = &quot; searchText &quot; /&gt; Under the hood, the template compiler expands v-model to the more verbose equivalent for us. So the above code does the same as the following: template &lt; input : value = &quot; searchText &quot; @ input = &quot; searchText = $event.target.value &quot; /&gt; When used on a component, v-model instead expands to this: template &lt; CustomInput : model-value = &quot; searchText &quot; @ update : model-value = &quot; newValue =&gt; searchText = newValue &quot; /&gt; For this to actually work though, the &lt;CustomInput&gt; component must do two things: Bind the value attribute of a native &lt;input&gt; element to the modelValue prop When a native input event is triggered, emit an update:modelValue custom event with the new value Here&#39;s that in action: CustomInput.vue vue &lt; script &gt; export default { props: [ &#39;modelValue&#39; ], emits: [ &#39;update:modelValue&#39; ] } &lt;/ script &gt; &lt; template &gt; &lt; input :value = &quot;modelValue&quot; @input = &quot;$emit(&#39;update:modelValue&#39;, $event.target.value)&quot; /&gt; &lt;/ template &gt; Now v-model should work perfectly with this component: template &lt; CustomInput v-model = &quot; searchText &quot; /&gt; Try it in the Playground Another way of implementing v-model within this component is to use a writable computed property with both a getter and a setter.
