Attribute Inheritance on Multiple Root Nodes ​ Unlike components with a single root node, components with multiple root nodes do not have an automatic attribute fallthrough behavior. If $attrs are not bound explicitly, a runtime warning will be issued. template &lt; CustomLayout id = &quot;custom-layout&quot; @ click = &quot; changeValue &quot; /&gt; If &lt;CustomLayout&gt; has the following multi-root template, there will be a warning because Vue cannot be sure where to apply the fallthrough attributes: template &lt; header &gt;...&lt;/ header &gt; &lt; main &gt;...&lt;/ main &gt; &lt; footer &gt;...&lt;/ footer &gt; The warning will be suppressed if $attrs is explicitly bound: template &lt; header &gt;...&lt;/ header &gt; &lt; main v-bind = &quot; $attrs &quot; &gt;...&lt;/ main &gt; &lt; footer &gt;...&lt;/ footer &gt; Accessing Fallthrough Attributes in JavaScript ​ If needed, you can access a component&#39;s fallthrough attributes in &lt;script setup&gt; using the useAttrs() API: vue &lt; script setup &gt; import { useAttrs } from &#39;vue&#39; const attrs = useAttrs () &lt;/ script &gt; If not using &lt;script setup&gt; , attrs will be exposed as a property of the setup() context: js export default { setup ( props , ctx ) { // fallthrough attributes are exposed as ctx.attrs console. log (ctx.attrs) } } Note that although the attrs object here always reflects the latest fallthrough attributes, it isn&#39;t reactive (for performance reasons). Watch a free video lesson on Vue School Slot Content and Outlet ​ We have learned that components can accept props, which can be JavaScript values of any type. But how about template content? In some cases, we may want to pass a template fragment to a child component, and let the child component render the fragment within its own template. For example, we may have a &lt;FancyButton&gt; component that supports usage like this: template &lt; FancyButton &gt; Click me! &lt;!-- slot content --&gt; &lt;/ FancyButton &gt; The template of &lt;FancyButton&gt; looks like this: template &lt; button class = &quot;fancy-btn&quot; &gt; &lt; slot &gt;&lt;/ slot &gt; &lt;!-- slot outlet --&gt; &lt;/ button &gt; The &lt;slot&gt; element is a slot outlet that indicates where the parent-provided slot content should be rendered. And the final rendered DOM: html &lt; button class = &quot;fancy-btn&quot; &gt;Click me!&lt;/ button &gt; Try it in the Playground Try it in the Playground With slots, the &lt;FancyButton&gt; is responsible for rendering the outer &lt;button&gt; (and its fancy styling), while the inner content is provided by the parent component. Another way to understand slots is by comparing them to JavaScript functions: js // parent component passing slot content FancyButton ( &#39;Click me!&#39; ) // FancyButton renders slot content in its own template function FancyButton ( slotContent ) { return `&lt;button class=&quot;fancy-btn&quot;&gt; ${ slotContent } &lt;/button&gt;` } Slot content is not just limited to text. It can be any valid template content. For example, we can pass in multiple elements, or even other components: template &lt; FancyButton &gt; &lt; span style = &quot;color:red&quot; &gt;Click me!&lt;/ span &gt; &lt; AwesomeIcon name = &quot;plus&quot; /&gt; &lt;/ FancyButton &gt; Try it in the Playground Try it in the Playground By using slots, our &lt;FancyButton&gt; is more flexible and reusable. We can now use it in different places with different inner content, but all with the same fancy styling. Vue components&#39; slot mechanism is inspired by the native Web Component &lt;slot&gt; element , but with additional capabilities that we will see later. Render Scope ​ Slot content has access to the data scope of the parent component, because it is defined in the parent. For example: template &lt; span &gt;{{ message }}&lt;/ span &gt; &lt; FancyButton &gt;{{ message }}&lt;/ FancyButton &gt; Here both {{ message }} interpolations will render the same content. Slot content does not have access to the child component&#39;s data. Expressions in Vue templates can only access the scope it is defined in, consistent with JavaScript&#39;s lexical scoping. In other words: Expressions in the parent template only have access to the parent scope; expressions in the child template only have access to the child scope. Note Because slot content is part of the parent&#39;s render scope, a &lt;style scoped&gt; block declared in the child component will not apply to it. If you need to style slotted content, do so from the parent component, or use the :deep() modifier in the child&#39;s scoped stylesheet (see Scoped CSS for details). Fallback Content ​ There are cases when it&#39;s useful to specify fallback (i.e. default) content for a slot, to be rendered only when no content is provided. For example, in a &lt;SubmitButton&gt; component: template &lt; button type = &quot;submit&quot; &gt; &lt; slot &gt;&lt;/ slot &gt; &lt;/ button &gt; We might want the text &quot;Submit&quot; to be rendered inside the &lt;button&gt; if the parent didn&#39;t provide any slot content. To make &quot;Submit&quot; the fallback content, we can place it in between the &lt;slot&gt; tags: template &lt; button type = &quot;submit&quot; &gt; &lt; slot &gt; Submit &lt;!-- fallback content --&gt; &lt;/ slot &gt; &lt;/ button &gt; Now when we use &lt;SubmitButton&gt; in a parent component, providing no content for the slot: template &lt; SubmitButton /&gt; This will render the fallback content, &quot;Submit&quot;: html &lt; button type = &quot;submit&quot; &gt;Submit&lt;/ button &gt; But if we provide content: template &lt; SubmitButton &gt;Save&lt;/ SubmitButton &gt; Then the provided content will be rendered instead: html &lt; button type = &quot;submit&quot; &gt;Save&lt;/ button &gt; Try it in the Playground Try it in the Playground Named Slots ​ There are times when it&#39;s useful to have multiple slot outlets in a single component. For example, in a &lt;BaseLayout&gt; component with the following template: template &lt; div class = &quot;container&quot; &gt; &lt; header &gt; &lt;!-- We want header content here --&gt; &lt;/ header &gt; &lt; main &gt; &lt;!-- We want main content here --&gt; &lt;/ main &gt; &lt; footer &gt; &lt;!-- We want footer content here --&gt; &lt;/ footer &gt; &lt;/ div &gt; For these cases, the &lt;slot&gt; element has a special attribute, name , which can be used to assign a unique ID to different slots so you can determine where content should be rendered: template &lt; div class = &quot;container&quot; &gt; &lt; header &gt; &lt; slot name = &quot;header&quot; &gt;&lt;/ slot &gt; &lt;/ header &gt; &lt; main &gt; &lt; slot &gt;&lt;/ slot &gt; &lt;/ main &gt; &lt; footer &gt; &lt; slot name = &quot;footer&quot; &gt;&lt;/ slot &gt; &lt;/ footer &gt; &lt;/ div &gt; A &lt;slot&gt; outlet without name implicitly has the name &quot;default&quot;. In a parent component using &lt;BaseLayout&gt; , we need a way to pass multiple slot content fragments, each targeting a different slot outlet. This is where named slots come in. To pass a named slot, we need to use a &lt;template&gt; element with the v-slot directive, and then pass the name of the slot as an argument to v-slot : template &lt; BaseLayout &gt; &lt; template v-slot:header &gt; &lt;!-- content for the header slot --&gt; &lt;/ template &gt; &lt;/ BaseLayout &gt; v-slot has a dedicated shorthand # , so &lt;template v-slot:header&gt; can be shortened to just &lt;template #header&gt; . Think of it as &quot;render this template fragment in the child component&#39;s &#39;header&#39; slot&quot;.
