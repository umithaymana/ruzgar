Read that first if you are new to components. Attribute Inheritance ​ A &quot;fallthrough attribute&quot; is an attribute or v-on event listener that is passed to a component, but is not explicitly declared in the receiving component&#39;s props or emits . Common examples of this include class , style , and id attributes. When a component renders a single root element, fallthrough attributes will be automatically added to the root element&#39;s attributes. For example, given a &lt;MyButton&gt; component with the following template: template &lt;!-- template of &lt;MyButton&gt; --&gt; &lt; button &gt;Click Me&lt;/ button &gt; And a parent using this component with: template &lt; MyButton class = &quot;large&quot; /&gt; The final rendered DOM would be: html &lt; button class = &quot;large&quot; &gt;Click Me&lt;/ button &gt; Here, &lt;MyButton&gt; did not declare class as an accepted prop. Therefore, class is treated as a fallthrough attribute and automatically added to &lt;MyButton&gt; &#39;s root element. class and style Merging ​ If the child component&#39;s root element already has existing class or style attributes, it will be merged with the class and style values that are inherited from the parent. Suppose we change the template of &lt;MyButton&gt; in the previous example to: template &lt;!-- template of &lt;MyButton&gt; --&gt; &lt; button class = &quot;btn&quot; &gt;Click Me&lt;/ button &gt; Then the final rendered DOM would now become: html &lt; button class = &quot;btn large&quot; &gt;Click Me&lt;/ button &gt; v-on Listener Inheritance ​ The same rule applies to v-on event listeners: template &lt; MyButton @ click = &quot; onClick &quot; /&gt; The click listener will be added to the root element of &lt;MyButton&gt; , i.e. the native &lt;button&gt; element. When the native &lt;button&gt; is clicked, it will trigger the onClick method of the parent component. If the native &lt;button&gt; already has a click listener bound with v-on , then both listeners will trigger. Nested Component Inheritance ​ If a component renders another component as its root node, for example, we refactored &lt;MyButton&gt; to render a &lt;BaseButton&gt; as its root: template &lt;!-- template of &lt;MyButton/&gt; that simply renders another component --&gt; &lt; BaseButton /&gt; Then the fallthrough attributes received by &lt;MyButton&gt; will be automatically forwarded to &lt;BaseButton&gt; . Note that: Forwarded attributes do not include any attributes that are declared as props, or v-on listeners of declared events by &lt;MyButton&gt; - in other words, the declared props and listeners have been &quot;consumed&quot; by &lt;MyButton&gt; . Forwarded attributes may be accepted as props by &lt;BaseButton&gt; , if declared by it. Disabling Attribute Inheritance ​ If you do not want a component to automatically inherit attributes, you can set inheritAttrs: false in the component&#39;s options. Since 3.3 you can also use defineOptions directly in &lt;script setup&gt; : vue &lt; script setup &gt; defineOptions ({ inheritAttrs: false }) // ...setup logic &lt;/ script &gt; The common scenario for disabling attribute inheritance is when attributes need to be applied to other elements besides the root node. By setting the inheritAttrs option to false , you can take full control over where the fallthrough attributes should be applied. These fallthrough attributes can be accessed directly in template expressions as $attrs : template &lt; span &gt;Fallthrough attributes: {{ $attrs }}&lt;/ span &gt; The $attrs object includes all attributes that are not declared by the component&#39;s props or emits options (e.g., class , style , v-on listeners, etc.). Some notes: Unlike props, fallthrough attributes preserve their original casing in JavaScript, so an attribute like foo-bar needs to be accessed as $attrs[&#39;foo-bar&#39;] . A v-on event listener like @click will be exposed on the object as a function under $attrs.onClick .
