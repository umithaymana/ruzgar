You can read better optimized documentation at /guide/essentials/template-refs.md for this page in Markdown format Template Refs ​ While Vue&#39;s declarative rendering model abstracts away most of the direct DOM operations for you, there may still be cases where we need direct access to the underlying DOM elements. To achieve this, we can use the special ref attribute: template &lt; input ref = &quot;input&quot; &gt; ref is a special attribute, similar to the key attribute discussed in the v-for chapter. It allows us to obtain a direct reference to a specific DOM element or child component instance after it&#39;s mounted. This may be useful when you want to, for example, programmatically focus an input on component mount, or initialize a 3rd party library on an element. Accessing the Refs ​ To obtain the reference with Composition API, we can use the useTemplateRef() helper: vue &lt; script setup &gt; import { useTemplateRef, onMounted } from &#39;vue&#39; // the first argument must match the ref value in the template const input = useTemplateRef ( &#39;my-input&#39; ) onMounted (() =&gt; { input.value. focus () }) &lt;/ script &gt; &lt; template &gt; &lt; input ref = &quot;my-input&quot; /&gt; &lt;/ template &gt; When using TypeScript, Vue&#39;s IDE support and vue-tsc will automatically infer the type of input.value based on what element or component the matching ref attribute is used on. Usage before 3.5 In versions before 3.5 where useTemplateRef() was not introduced, we need to declare a ref with a name that matches the template ref attribute&#39;s value: vue &lt; script setup &gt; import { ref, onMounted } from &#39;vue&#39; // declare a ref to hold the element reference // the name must match template ref value const input = ref ( null ) onMounted (() =&gt; { input.value. focus () }) &lt;/ script &gt; &lt; template &gt; &lt; input ref = &quot;input&quot; /&gt; &lt;/ template &gt; If not using &lt;script setup&gt; , make sure to also return the ref from setup() : js export default { setup () { const input = ref ( null ) // ... return { input } } } The resulting ref is exposed on this.$refs : vue &lt; script &gt; export default { mounted () { this .$refs.input. focus () } } &lt;/ script &gt; &lt; template &gt; &lt; input ref = &quot;input&quot; /&gt; &lt;/ template &gt; Note that you can only access the ref after the component is mounted. If you try to access $refs.input input in a template expression, it will be undefined null on the first render. This is because the element doesn&#39;t exist until after the first render! If you are trying to watch the changes of a template ref, make sure to account for the case where the ref has null value: js watchEffect (() =&gt; { if (input.value) { input.value. focus () } else { // not mounted yet, or the element was unmounted (e.g. by v-if) } }) See also: Typing Template Refs Ref on Component ​ This section assumes knowledge of Components . Feel free to skip it and come back later. ref can also be used on a child component. In this case the reference will be that of a component instance: vue &lt; script setup &gt; import { useTemplateRef, onMounted } from &#39;vue&#39; import Child from &#39;./Child.vue&#39; const childRef = useTemplateRef ( &#39;child&#39; ) onMounted (() =&gt; { // childRef.value will hold an instance of &lt;Child /&gt; }) &lt;/ script &gt; &lt; template &gt; &lt; Child ref = &quot;child&quot; /&gt; &lt;/ template &gt; Usage before 3.5 vue &lt; script setup &gt; import { ref, onMounted } from &#39;vue&#39; import Child from &#39;./Child.vue&#39; const child = ref ( null ) onMounted (() =&gt; { // child.value will hold an instance of &lt;Child /&gt; }) &lt;/ script &gt; &lt; template &gt; &lt; Child ref = &quot;child&quot; /&gt; &lt;/ template &gt; vue &lt; script &gt; import Child from &#39;./Child.vue&#39; export default { components: { Child }, mounted () { // this.$refs.child will hold an instance of &lt;Child /&gt; } } &lt;/ script &gt; &lt; template &gt; &lt; Child ref = &quot;child&quot; /&gt; &lt;/ template &gt; If the child component is using Options API or not using &lt;script setup&gt; , the The referenced instance will be identical to the child component&#39;s this , which means the parent component will have full access to every property and method of the child component. This makes it easy to create tightly coupled implementation details between the parent and the child, so component refs should be only used when absolutely needed - in most cases, you should try to implement parent / child interactions using the standard props and emit interfaces first. An exception here is that components using &lt;script setup&gt; are private by default : a parent component referencing a child component using &lt;script setup&gt; won&#39;t be able to access anything unless the child component chooses to expose a public interface using the defineExpose macro: vue &lt; script setup &gt; import { ref } from &#39;vue&#39; const a = 1 const b = ref ( 2 ) // Compiler macros, such as defineExpose, don&#39;t need to be imported defineExpose ({ a, b }) &lt;/ script &gt; When a parent gets an instance of this component via template refs, the retrieved instance will be of the shape { a: number, b: number } (refs are automatically unwrapped just like on normal instances). Note that defineExpose must be called before any await operation. Otherwise, properties and methods exposed after the await operation will not be accessible. See also: Typing Component Template Refs The expose option can be used to limit the access to a child instance: js export default { expose: [ &#39;publicData&#39; , &#39;publicMethod&#39; ], data () { return { publicData: &#39;foo&#39; , privateData: &#39;bar&#39; } }, methods: { publicMethod () { /* ... */ }, privateMethod () { /* ... */ } } } In the above example, a parent referencing this component via template ref will only be able to access publicData and publicMethod . Refs inside v-for ​ Requires v3.5 or above When ref is used inside v-for , the corresponding ref should contain an Array value, which will be populated with the elements after mount: vue &lt; script setup &gt; import { ref, useTemplateRef, onMounted } from &#39;vue&#39; const list = ref ([ /* ... */ ]) const itemRefs = useTemplateRef ( &#39;items&#39; ) onMounted (() =&gt; console. log (itemRefs.value)) &lt;/ script &gt; &lt; template &gt; &lt; ul &gt; &lt; li v-for = &quot;item in list&quot; ref = &quot;items&quot; &gt; {{ item }} &lt;/ li &gt; &lt;/ ul &gt; &lt;/ template &gt; Try it in the Playground Usage before 3.5 In versions before 3.5 where useTemplateRef() was not introduced, we need to declare a ref with a name that matches the template ref attribute&#39;s value. The ref should also contain an array value: vue &lt; script setup &gt; import { ref, onMounted } from &#39;vue&#39; const list = ref ([ /* ... */ ]) const itemRefs = ref ([]) onMounted (() =&gt; console. log (itemRefs.value)) &lt;/ script &gt; &lt; template &gt; &lt; ul &gt; &lt; li v-for = &quot;item in list&quot; ref = &quot;itemRefs&quot; &gt; {{ item }} &lt;/ li &gt; &lt;/ ul &gt; &lt;/ template &gt; When ref is used inside v-for , the resulting ref value will be an array containing the corresponding elements: vue &lt; script &gt; export default { data () { return { list: [ /* ... */ ] } }, mounted () { console. log ( this .$refs.items) } } &lt;/ script &gt; &lt; template &gt; &lt; ul &gt; &lt; li v-for = &quot;item in list&quot; ref = &quot;items&quot; &gt; {{ item }} &lt;/ li &gt; &lt;/ ul &gt; &lt;/ template &gt; Try it in the Playground It should be noted that the ref array does not guarantee the same order as the source array. Function Refs ​ Instead of a string key, the ref attribute can also be bound to a function, which will be called on each component update and gives you full flexibility on where to store the element reference. The function receives the element reference as the first argument: template &lt; input : ref = &quot; ( el ) =&gt; { /* assign el to a property or ref */ } &quot; &gt; Note we are using a dynamic :ref binding so we can pass it a function instead of a ref name string. When the element is unmounted, the argument will be null . You can, of course, use a method instead of an inline function.
