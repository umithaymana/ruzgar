Those types have two important things in common: they&rsquo;re immutable and they&rsquo;re small. Numbers are the largest, and they still fit into two 64-bit words. That&rsquo;s a small enough price that we can afford to pay it for all values, even Booleans and nils which don&rsquo;t need that much space. Strings, unfortunately, are not so petite. There&rsquo;s no maximum length for a string. Even if we were to artificially cap it at some contrived limit like 255 characters, that&rsquo;s still too much memory to spend on every single value. UCSD Pascal, one of the first implementations of Pascal, had this exact limit. Instead of using a terminating null byte to indicate the end of the string like C, Pascal strings started with a length value. Since UCSD used only a single byte to store the length, strings couldn&rsquo;t be any longer than 255 characters. We need a way to support values whose sizes vary, sometimes greatly. This is exactly what dynamic allocation on the heap is designed for. We can allocate as many bytes as we need. We&rsquo;ll eventually have a handful of heap-allocated types in clox: strings, instances, functions, you get the idea.
