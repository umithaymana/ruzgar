Hypothesis 6.x ¶ 6.170.15 - 2026-11-06 ¶ Hypothesis now has 100% type coverage of our public API, as checked by pyrefly . 6.170.14 - 2026-10-30 ¶ This patch adjusts coverage settings for new dependencies; there is no user-visible change. 6.170.13 - 2026-10-28 ¶ This patch fixes the codemod for deprecated characters() arguments, which previously raised an error when **kwargs were also passed. 6.170.12 - 2026-10-26 ¶ This patch reduces Hypothesis’ overhead for each test case. For simple properties and strategies, generating test cases takes up to a third less time and shrinking failing examples is up to twice as fast; most tests will see a smaller improvement. import hypothesis is also about 20% faster. 6.170.11 - 2026-10-26 ¶ This patch makes writing observability data to .hypothesis/observed cheaper when tests run in multiple threads, and defers cleaning up old observation files from import time until observations are first written. 6.170.10 - 2026-10-25 ¶ This patch fixes an internal error from lists() with unique=True , when the elements are a filtered sampled_from() with too few allowed values to reach min_size . It also ensures that domains() always generates at least one subdomain, even with a small max_length . We also fixed some internal bookkeeping that could go wrong when an exception was raised and caught during generation, for example by recursive() , which could make shrinking less effective. 6.170.9 - 2026-10-23 ¶ This release fixes a DeprecationWarning when importing hypothesis.extra.dateutil with dateutil 3.0 or higher ( issue #4934 ). 6.170.8 - 2026-10-22 ¶ This patch fixes a regression in version 6.170.1 , where unique collections of non-empty collections, such as st.sets(st.frozensets(st.integers(), min_size=1), min_size=1) , could fail the HealthCheck.large_base_example health check ( issue #4918 ). 6.170.7 - 2026-10-22 ¶ This improves type coverage of stateful testing . 6.170.6 - 2026-10-22 ¶ This patch adds PyPy 3.12 wheels to releases ( issue #4921 ). Hypothesis no longer mutates test cases by copying one element of a unique collection over another element of the same collection, and no longer probes for minimal examples by drawing every element at its simplest value - both of which were certain to be rejected, and could waste several times as many draws from the element strategy as were actually returned. 6.170.0 - 2026-10-15 ¶ This release substantially strengthens run_conformance_test() , which authors of alternative backends can use to test their provider. It can now test providers with required constructor arguments, runs many test cases against each provider, treats running out of entropy as expected control flow, and checks that providers are able to generate a representative range of values. These new checks catch two bugs in the provider underlying fuzz_one_input , which this release also fixes: integer draws could never generate negative values, and string draws from an empty alphabet consumed the whole buffer instead of returning the empty string. Verbose output for stateful tests now reads Test case: &lt;state machine&gt; rather than trailing off after the colon.
