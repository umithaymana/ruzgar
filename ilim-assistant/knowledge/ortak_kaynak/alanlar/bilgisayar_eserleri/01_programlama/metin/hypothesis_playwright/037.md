Hypothesis 6.x ¶ 6.170.15 - 2026-11-06 ¶ Hypothesis now has 100% type coverage of our public API, as checked by pyrefly . 6.170.14 - 2026-10-30 ¶ This patch adjusts coverage settings for new dependencies; there is no user-visible change. 6.170.13 - 2026-10-28 ¶ This patch fixes the codemod for deprecated characters() arguments, which previously raised an error when **kwargs were also passed. 6.170.12 - 2026-10-26 ¶ This patch reduces Hypothesis’ overhead for each test case. For simple properties and strategies, generating test cases takes up to a third less time and shrinking failing examples is up to twice as fast; most tests will see a smaller improvement. import hypothesis is also about 20% faster. 6.170.11 - 2026-10-26 ¶ This patch makes writing observability data to .hypothesis/observed cheaper when tests run in multiple threads, and defers cleaning up old observation files from import time until observations are first written. 6.170.10 - 2026-10-25 ¶ This patch fixes an internal error from lists() with unique=True , when the elements are a filtered sampled_from() with too few allowed values to reach min_size . It also ensures that domains() always generates at least one subdomain, even with a small max_length . We also fixed some internal bookkeeping that could go wrong when an exception was raised and caught during generation, for example by recursive() , which could make shrinking less effective. 6.170.9 - 2026-10-23 ¶ This release fixes a DeprecationWarning when importing hypothesis.extra.dateutil with dateutil 3.0 or higher ( issue #4934 ). 6.170.8 - 2026-10-22 ¶ This patch fixes a regression in version 6.170.1 , where unique collections of non-empty collections, such as st.sets(st.frozensets(st.integers(), min_size=1), min_size=1) , could fail the HealthCheck.large_base_example health check ( issue #4918 ). 6.170.7 - 2026-10-22 ¶ This improves type coverage of stateful testing . 6.170.6 - 2026-10-22 ¶ This patch adds PyPy 3.12 wheels to releases ( issue #4921 ). Thanks to @moreati for this contribution! 6.170.5 - 2026-10-20 ¶ This patch fixes a bug for users of our PrimitiveProvider interface, where draw_integer could incorrectly reuse weights from an earlier draw ( issue #4908 ). 6.170.4 - 2026-10-19 ¶ This fills in the missing type annotations for public-facing attributes of settings , such as settings.max_examples and settings.database . 6.170.3 - 2026-10-19 ¶ This patch fixes an internal error when the shrinker tried certain invalid values, for example when shrinking one_of() between text strategies with different alphabets ( issue #4905 ). 6.170.2 - 2026-10-19 ¶ Add support for Python 3.16, which is still in alpha. 6.170.1 - 2026-10-16 ¶ This patch makes generating unique collections, such as sets() or lists() with unique=True , considerably more efficient ( issue #4458 ). Hypothesis no longer mutates test cases by copying one element of a unique collection over another element of the same collection, and no longer probes for minimal examples by drawing every element at its simplest value - both of which were certain to be rejected, and could waste several times as many draws from the element strategy as were actually returned. 6.170.0 - 2026-10-15 ¶ This release substantially strengthens run_conformance_test() , which authors of alternative backends can use to test their provider. It can now test providers with required constructor arguments, runs many test cases against each provider, treats running out of entropy as expected control flow, and checks that providers are able to generate a representative range of values. These new checks catch two bugs in the provider underlying fuzz_one_input , which this release also fixes: integer draws could never generate negative values, and string draws from an empty alphabet consumed the whole buffer instead of returning the empty string. Verbose output for stateful tests now reads Test case: &lt;state machine&gt; rather than trailing off after the colon. Thanks to @reachsridhard for reporting the integers bug and prototyping these improvements. 6.169.4 - 2026-10-15 ¶ This release fixes an error when applying @given on Python 3.14 to functions with annotations referring to types that are only available during type checking, when explicit strategies are supplied ( issue #4897 ). Thanks to Arjun Aravind for this fix! 6.169.3 - 2026-10-15 ¶ The .seed() method of randoms() now accepts the same arguments as random.Random.seed() , such as a= and version= . Previously, it required exactly one positional argument. Calling .seed() without a seed now raises a clearer error. 6.169.2 - 2026-10-14 ¶ The Ghostwriter now raises a helpful error for functions which take no arguments, instead of writing a test with an invalid empty @given() decorator ( issue #4882 ). Thanks to deepak7lal for this fix! 6.169.1 - 2026-10-14 ¶ Calling .map() or .flatmap() on data() with a keyword argument now raises the intended error explaining that this is not supported, instead of a generic error about an unexpected keyword argument. 6.169.0 - 2026-10-11 ¶ This release drops support for Python 3.10, which reached end of life in October 2026 . 6.168.5 - 2026-10-05 ¶ This patch fixes the type annotation of from_field() , which claimed to return a strategy for instances of the field type rather than for values of the field. 6.168.4 - 2026-10-05 ¶ This patch adds support for PyPy 3.12. 6.168.3 - 2026-09-28 ¶ This patch fixes quadratic-time behaviour when summarising the statistics of a test run, which Hypothesis does for every test when running under pytest . This avoids an apparent hang after the last test case with a high number of test cases (&gt;100k). 6.168.2 - 2026-09-27 ¶ This patch makes writes to the cache of constants collected from local source files atomic. Previously, a concurrent process sharing the same .hypothesis directory, such as another pytest-xdist worker, could read a partially written cache file, which silently changed the data generated for a given @seed ( issue #4885 ). 6.168.1 - 2026-09-23 ¶ We now publish abi3 wheels for Linux s390x (manylinux) and Linux i686 (musllinux). 6.168.0 - 2026-09-08 ¶ datetimes() now generates “tricky” datetimes more often: values on or near daylight-saving and other utc-offset transitions of the drawn timezone - including imaginary wall times, and ambiguous ones with each value of fold - as well as times adjacent to leap seconds and to well-known datetimes like the millennium and the end of the signed 32-bit Unix epoch ( issue #69 ). This release also fixes some rare internal errors, where an error raised partway through updating an internal cache - for example by a deeply recursive strategy raising RecursionError - could leave that cache corrupted. 6.167.1 - 2026-08-30 ¶ This patch improves shrinking and generation for collection strategies which reject some drawn elements, such as lists() with unique=True . Rejected elements are now marked as discarded, so the shrinker can delete them wholesale and generation avoids revisiting choices that would be rejected again. 6.167.0 - 2026-08-30 ¶ Test case observations from observability now give more detail about why a test case failed or was abandoned ( issue #3845 ). metadata includes a new status_reason_location key: a filename:lineno location for the status_reason , if known - for example the location of a failing assume() call, the .filter() call whose predicate rejected the last drawn value, or the exception for failing tests. Test cases which exceeded the maximum allowed size now also report a nonempty status_reason . 6.166.0 - 2026-08-29 ¶ The Phase.explain phase now also varies interactive draws from data() , annotating each freely-variable Draw n: ... line with an # or any other generated value comment, just like @given arguments ( issue #4403 ). This release also fixes two explain-phase bugs: failing test cases found just as the set of possible inputs was fully enumerated were reported without running the Phase.shrink and Phase.explain phases, and the explain phase could fail to report that the commented parts can be varied together if the failing example ended with an uncommented part. 6.165.11 - 2026-08-29 ¶ This patch fixes the redistribute_numeric_pairs shrink pass, which incorrectly checked node1.type instead of node2.type when guarding against float precision loss above MAX_PRECISE_INTEGER . 6.165.10 - 2026-08-16 ¶ This patch fixes several from_regex() bugs ( issue #4857 , issue #4858 , and issue #4859 ): Character classes which combine a negative category with other members, like [\W_] , now match the union of their members instead of incorrectly excluding characters.
