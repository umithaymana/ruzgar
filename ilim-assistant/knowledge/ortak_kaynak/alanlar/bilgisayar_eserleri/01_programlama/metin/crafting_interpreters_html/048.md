We&rsquo;re at a fork in the road. We could add behavior first &mdash; methods &mdash; or we could start with state &mdash; properties. We&rsquo;re going to take the latter because, as we&rsquo;ll see, the two get entangled in an interesting way and it will be easier to make sense of them if we get properties working first. Lox follows JavaScript and Python in how it handles state. Every instance is an open collection of named values. Methods on the instance&rsquo;s class can access and modify properties, but so can outside code. Properties are accessed using a . syntax. Allowing code outside of the class to directly modify an object&rsquo;s fields goes against the object-oriented credo that a class encapsulates state. Some languages take a more principled stance. In Smalltalk, fields are accessed using simple identifiers &mdash; essentially, variables that are only in scope inside a class&rsquo;s methods. Ruby uses @ followed by a name to access a field in an object. That syntax is only meaningful inside a method and always accesses state on the current object. Lox, for better or worse, isn&rsquo;t quite so pious about its OOP faith. someObject . someProperty An expression followed by . and an identifier reads the property with that name from the object the expression evaluates to. An interesting edge case we need to handle is what happens if the instance doesn&rsquo;t have a property with the given name. We could silently return some dummy value like nil , but my experience with languages like JavaScript is that this behavior masks bugs more often than it does anything useful. Instead, we&rsquo;ll make it a runtime error. So the first thing we do is see if the instance actually has a field with the given name. Only then do we return it. Otherwise, we raise an error. Note how I switched from talking about &ldquo;properties&rdquo; to &ldquo;fields&rdquo;. There is a subtle difference between the two. Fields are named bits of state stored directly in an instance. Properties are the named, uh, things , that a get expression may return. Every field is a property, but as we&rsquo;ll see later , not every property is a field. Ooh, foreshadowing. Spooky!
