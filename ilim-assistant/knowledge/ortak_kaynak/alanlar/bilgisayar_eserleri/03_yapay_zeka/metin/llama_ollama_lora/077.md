DoRA training with FSDP should work (albeit at lower speed than LoRA). If combined with bitsandbytes (QDoRA), 4-bit quantization should also work, but 8-bit quantization has known issues and is not recommended. 6. With FSDP2, `set_adapter()` and `set_requires_grad()` reshard the FSDP2 modules inside the [`PeftModel`], including the `PeftModel` itself, so that `requires_grad` changes reach the sharded parameters. Exiting `disable_adapter()` only does so if FSDP2 replaced the registered parameter objects inside it, as a forward does with sharded parameters, or if re-enabling changes `requires_grad` from what it was on entry. FSDP2 modules that shard parameters of a merged adapter layer are not resharded, so unmerge before calling these methods. With `reshard_after_forward=False`, or for the root module with the default `None`, the next forward all-gathers again. FSDP2 modules that wrap the `PeftModel` are not resharded; call `reshard()` on them before these methods. Because these calls can leave the base weights sharded, merging right after them doesn't work correctly (see 1). Prompt learning methods and adaption prompt are not covered yet. 7. With FSDP2/HSDP, call `get_peft_model_state_dict()` or `save_pretrained()` on every participating rank: gathering distributed adapter tensors is a collective. For `save_pretrained()`, pass `is_main_process=True` only on the writing rank. Only selected adapter entries (including explicitly requested embeddings or `modules_to_save`) are gathered; unselected base-model weights remain sharded.
