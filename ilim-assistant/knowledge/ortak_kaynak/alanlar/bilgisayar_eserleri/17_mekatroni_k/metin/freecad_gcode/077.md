The main board flags an expansion board as timed out (raising an expansion-timeout event) when it has received no status report from it for half the connection timeout. The expansion board switches all of its heaters off when it had time sync with the main board and then received no time sync messages for the full connection timeout, so that heaters do not stay on unsupervised if the CAN connection fails. When the connection is restored, the expansion board announces itself again and the main board raises an expansion-reconnect event. If T is given, the value is stored on the main board and sent to the expansion board. The expansion board reverts to the default when it is reset, so M959 normally belongs in config.g. M959 with only the B parameter reports the timeout of that board; M959 without parameters reports the timeouts of all expansion boards. The current value is also available in the object model as boards[].timeout . Heater setpoints are not restored automatically when the board reconnects; the expansion-reconnect event macro can be used to do that. Its P parameter is 0 if the board announced itself after a reset, 1 if it reconnected with its configuration intact, or 3 if it reconnected with its configuration intact but switched its heaters off while disconnected. (RRF) 0 = disable, 1 = enable, one value per extruder In RepRapFirmware, phase stepping replaces step and direction with direct control of the motor phases. It is supported on Duet 3 MB6HC main board drivers from RRF 3.6, and after RRF 3.7.0-beta.3 also on the drivers of a CAN-connected Duet 3 Expansion 3HC. Main boards that do not support phase stepping (Duet 3 Mini 5+, MB6XD and Duet 2) do not implement M970 at all, so they cannot phase step the drivers of an attached expansion board either. The Duet 3 Expansion 1HCL and M23CL are closed loop boards and reject M970 with "Command is not supported"; their drivers can still be linearised with the sine table correction of M569.2. An axis or extruder must be driven either entirely by local drivers or entirely by CAN-connected drivers; enabling phase stepping on an axis that mixes the two is rejected. Stall detection is not supported while phase stepping is enabled. M970 with no parameters reports the step mode of every axis and extruder. Applies a sinusoidal correction to the commanded electrical angle of a motor, to compensate for motor and driver non-linearity. The correction only takes effect while that axis is in phase stepping mode, see M970. Up to 4 harmonics can be corrected per driver. M970.3 with only the P parameter reports the corrections in force, for example "Driver 0 waveform correction: S2 J1.500 O200.0", or "none" if the driver has none. Corrections are not saved over a reset, so they belong in config.g. The command waits for motion to stop before changing a correction. Supported on Duet 3 MB6HC main board drivers and on the drivers of a CAN-connected Duet 3 Expansion 3HC. Drivers that cannot phase step, including those on the Duet 3 Expansion 1HCL and M23CL, reject the command. For a motor in step/dir mode the equivalent is M569.2, which corrects the driver's sine table instead and is more restricted.
