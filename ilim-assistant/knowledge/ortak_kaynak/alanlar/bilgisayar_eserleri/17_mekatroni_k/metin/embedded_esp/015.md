then . /usr/share/bash-completion/bash_completion elif [ -f /etc/bash_completion ]; then . /etc/bash_completion fi EOF # 4) Reload shell exec bash Persistent (system-wide) # Writes to a system directory (affects all users) # Adjust path if your distro uses a different location eim completions bash | sudo tee /etc/bash_completion.d/eim &gt;/dev/null exec bash Note: If you usually run ./eim (relative path), it’s best to put eim on your PATH so completion matches the command name: mkdir -p ~/bin cp ./eim ~/bin/ echo 'export PATH="$HOME/bin:$PATH"' &gt;&gt; ~/.bashrc exec bash Zsh (macOs default, also Linux) Quick (current session only) # Loads completion just for this terminal # (zsh needs compinit and a function path) fpath+=(/tmp/eim-completions) mkdir -p /tmp/eim-completions eim completions zsh &gt; /tmp/eim-completions/_eim autoload -Uz compinit; compinit Persistent (per-user) # 1) Generate into a per-user completions dir mkdir -p ~/.zsh/completions eim completions zsh &gt; ~/.zsh/completions/_eim # 2) zsh requires "secure" dirs (no group/other write) chmod go-w ~ ~/.zsh ~/.zsh/completions # 3) Ensure zsh uses this directory (add to ~/.zshrc if missing) grep -q 'fpath+=(~/.zsh/completions)' ~/.zshrc || echo 'fpath+=(~/.zsh/completions)' &gt;&gt; ~/.zshrc grep -q 'compinit' ~/.zshrc || echo 'autoload -Uz compinit; compinit' &gt;&gt; ~/.zshrc # 4) Reload shell exec zsh Invoking as ./eim? zsh maps _eim → eim. If you insist on ./eim, add this to ~/.zshrc: compdef _eim ./eim=eim Troubleshooting (zsh) # If zsh warns about “insecure directories” compaudit # Then fix each listed path: chmod go-w &lt;each_path&gt; Fish (Linux / macOS) Quick (current session only) eim completions fish | source Persistent (per-user) mkdir -p ~/.config/fish/completions eim completions fish &gt; ~/.config/fish/completions/eim.fish # Open a new fish session or: exec fish Elvish Quick (current session only) # Elvish can `eval` the output in the current session eim completions elvish | elvish Persistent (per-user) # Save as a module and "use" it from rc mkdir -p ~/.elvish/lib eim completions elvish &gt; ~/.elvish/lib/eim.elv # Ensure your rc file imports it (usually ~/.elvish/rc.elv) # Add the following line if missing: # use eim PowerShell (Windows, macOS, Linux) Quick (current session only) eim completions powershell | Out-String | Invoke-Expression Persistent (per-user) # Ensure you have a profile file if (!(Test-Path -Path $PROFILE)) { New-Item -Type File -Path $PROFILE -Force | Out-Null } # Append the completion to your profile eim completions powershell &gt;&gt; $PROFILE # Reload profile for current session . $PROFILE On PowerShell 7+ , the profile is typically at: Windows: $HOME\Documents\PowerShell\Microsoft.PowerShell_profile.ps1 macOS/Linux: $HOME/.config/powershell/Microsoft.PowerShell_profile.ps1 Dash (Ubuntu’s /bin/sh) dash is a minimal shell focused on POSIX compatibility and does not support programmable completion like bash/zsh. To use tab completion with EIM on Ubuntu/Debian: Run your CLI from bash (or zsh/fish): bash -lc "eim &lt;TAB&gt;" Or switch your interactive shell to bash: chsh -s /bin/bash # log out and back in Updating Completions After updating EIM or its CLI options, regenerate the script: # bash (per-user) eim completions bash &gt; ~/.local/share/bash-completion/completions/eim # zsh eim completions zsh &gt; ~/.zsh/completions/_eim # fish eim completions fish &gt; ~/.config/fish/completions/eim.fish # elvish eim completions elvish &gt; ~/.elvish/lib/eim.elv # PowerShell eim completions powershell &gt; $PROFILE; . $PROFILE If you change how you invoke the binary (e.g., rename it), regenerate the completion with the new name and reinstall it. We are committed to transparency and want you to be fully informed about what data we collect and how to opt-out. What data do we collect? We collect the following information to understand how the installer is used and to identify areas for improvement: Environment / System Info OS &amp; version (Windows, macOS, Linux distribution) Architecture (x64, ARM, etc.) and kernel version App version (EIM version) Whether the system is already running elevated Install context Which installation flow was used: wizard , simple , offline , fix , or cli (incl. whether the GUI or CLI was used) Requested ESP-IDF version(s) (e.g. v5.3.1 ) — public, released tags Counts of selected features, tools, and targets (not the names) Whether the run was interactive and whether an existing IDF directory was reused A per-run session ID and per-version installation ID for correlation between the start and finish of an install Outcome Whether the install succeeded or failed Duration of the install (in seconds) Error &amp; Failure Tracking A coarse error kind (network, filesystem, git, python, dependency, disk space, permissions, invalid archive, configuration, failed prerequisite check, user-cancelled, app closed, unknown) A failure class that says who can act on the failure: environment (something on the machine, such as a missing prerequisite or no network), installer (a bug or limitation in EIM itself), user (the install was cancelled or the app was closed), or unknown (we could not tell, and it is not counted as an installer defect) The stage the install was in when it failed (checking, prerequisites, download, extract, tools, python, configure) For missing-prerequisite failures, the names of the prerequisites that were missing (e.g. git , cmake ) — these are fixed, well-known tool names, never paths or versions from your machine A short 16-character fingerprint (SHA-256 prefix) of the error text, used to group recurring failures.
