Alertmanager events (process start and shutdown, alert lifecycle transitions, silence creation, notification delivery, and mute/inhibit suppressions) and fans them out to one or more destinations. Each event is encoded as a structured payload that includes a timestamp, the producing instance&#x27;s hostname, the cluster position (when HA clustering is enabled), and the event-specific data. The recorder is gated behind the event-recorder feature flag — pass --enable-feature=event-recorder on the command line to activate it. When the flag is not set, the recorder silently discards all events. Event recording is configured under the top-level event_recorder key. &lt;event_recorder_config&gt; Outputs are grouped by type, one list per destination kind (mirroring the way receivers group their integrations). Every recorded event is sent to every output across all lists. Every output requires a name, which is used with its type as the output identifier in metrics and logs (for example, webhook:primary ). Destination configuration such as paths, URLs, brokers, and topics is not included in metric labels. URLs, brokers, and topics are also omitted from logs; file paths remain in file-output error logs for troubleshooting. Names must be non-empty, valid UTF-8, and unique within each output type. # JSONL file outputs. file_outputs : [ - &lt;file_output&gt; ... ] # Webhook outputs. webhook_outputs : [ - &lt;webhook_output&gt; ... ] # Kafka outputs. kafka_outputs : [ - &lt;kafka_output&gt; ... ] # Stdout outputs. stdout_outputs : [ - &lt;stdout_output&gt; ... ] Every output uses the schema in proto/eventrecorder/events/v2/events.proto . Alert labels, alert annotations, group labels, silence annotations, and muted-alert labels are encoded as maps. Protobuf consumers must use the Go package github.com/prometheus/alertmanager/eventrecorder/events/v2 or bindings generated from that schema. &lt;file_output&gt; Writes each event as a single JSON line to a file. The file is reopened when the parent directory observes a rename/remove/create on the target path (for compatibility with logrotate and similar tools). # Name used to identify this output in metrics and logs. name : &lt;string&gt; # Path to the JSONL output file. Will be created if it does not exist. path : &lt;filepath&gt; &lt;webhook_output&gt; POSTs each event as a JSON body to an HTTP endpoint. Delivery is performed by a bounded worker pool with bounded retries and exponential backoff. Retries resend the entire event or batch, so receivers should tolerate duplicate events after ambiguous failures. With multiple workers, requests may complete out of order; set workers: 1 when request ordering matters. # Name used to identify this output in metrics and logs. name : &lt;string&gt; # URL to POST events to. url : &lt;secret&gt; # HTTP client configuration (TLS, basic auth, OAuth, proxies, ...). [ retry_backoff : &lt;duration&gt; | default = 500ms ] # Send events in JSON arrays instead of posting each event as an individual # JSON object. Records use the producing Alertmanager instance&#x27;s hostname as the message key, which keeps all events from a single instance on the same partition and preserves their relative ordering. Delivery is asynchronous and bounded: when the local buffer is full, events are dropped. A failure to reach the Kafka brokers at startup is logged at warn level but does not prevent Alertmanager from starting; the underlying client retries connections in the background. The target topic must already exist (or the brokers must be configured to auto-create topics); Alertmanager does not create it. # Name used to identify this output in metrics and logs. name : &lt;string&gt; # Seed broker list (host:port).
