Use it in CI, where the //host/:_authToken key cannot be an environment variable name on some runners. pnpm reads _auth from two places only: the global config.yaml the pnpm_config__auth environment variable, as JSON pnpm ignores _auth in pnpm-workspace.yaml and .npmrc . In the global config.yaml : config.yaml _auth: https://registry.npmjs.org: "@": authToken: npm-token "@org": authToken: org-token The same value as an environment variable: export pnpm_config__auth = '{"https://registry.npmjs.org":{"@":{"authToken":"npm-token"},"@org":{"authToken":"org-token"}}}' pnpm also reads PNPM_CONFIG__AUTH , the all-caps name some CI runners use. If both are set, the lowercase one wins unless it is empty. The value follows these rules: Each top-level key is an http or https registry URL, with no credentials, query string, or fragment. Under a URL, "@" holds the token for the whole registry. "@org" holds the token for packages in the @org scope. authToken is the only credential field. It is a bearer token. authToken can reference an environment variable as ${NAME} . Each entry also routes packages to its URL. "@" makes the URL the default registry, and "@org" sends @org/* packages there. The priority of this routing depends on where the entry comes from: --registry and --@scope:registry on the command line win. Entries from pnpm_config__auth override the registry and registries settings. CI can use this to force a proxy registry. Entries from the global config.yaml apply only where no registry or registries setting chooses a registry. The token is still sent to its own URL. From v12.1.0 to v12.15.0, pnpm login saved tokens here. Since v12.16.0 it saves them in auth.ini and removes the token it replaces from _auth . pnpm logout removes tokens from both files.
