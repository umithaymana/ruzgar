In other words, the return value is x in x = f x . f must be a lazy function. This means that x must be a value that can be partially evaluated, such as an attribute set, a list, or a function. This way, f can use one part of x to compute another part. Relation to syntactic recursion This section explains fix by refactoring from syntactic recursion to a call of fix instead. For context, Nix lets you define attributes in terms of other attributes syntactically using the rec { } syntax . nix-repl&gt; rec { foo = &quot;foo&quot;; bar = &quot;bar&quot;; foobar = foo + bar; } { bar = &quot;bar&quot;; foo = &quot;foo&quot;; foobar = &quot;foobar&quot;; } This is convenient when constructing a value to pass to a function for example, but an equivalent effect can be achieved with the let binding syntax: nix-repl&gt; let self = { foo = &quot;foo&quot;; bar = &quot;bar&quot;; foobar = self.foo + self.bar; }; in self { bar = &quot;bar&quot;; foo = &quot;foo&quot;; foobar = &quot;foobar&quot;; } But in general you can get more reuse out of let bindings by refactoring them to a function. nix-repl&gt; f = self: { foo = &quot;foo&quot;; bar = &quot;bar&quot;; foobar = self.foo + self.bar; } This is where fix comes in, it contains the syntactic recursion that’s not in f anymore. nix-repl&gt; fix = f: let self = f self; in self; By applying fix we get the final result. nix-repl&gt; fix f { bar = &quot;bar&quot;; foo = &quot;foo&quot;; foobar = &quot;foobar&quot;; } Such a refactored f using fix is not useful by itself.
