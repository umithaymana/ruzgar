Certificate Fingerprint Matching It is possible to provide the 'SHA256' certificate fingerprint of the TLS certificate. This is useful in the following situations: the URL is using an IP address instead of a FQDN a self-signed certificate is used which the installer does not trust added security by pinning the known certificate of the server There are three ways to provide the 'SHA256' fingerprint to the installer: Fingerprint defined in the ISO as a DHCP option ( 251 ) via a DNS TXT record The DNS TXT record must be located at proxmox-auto-installer-cert-fingerprint.{search domain} , where {search domain} is the search domain provided by the DHCP server. ℹ️ Note : Fetching the fingerprint via DHCP or DNS records is only done if the same method is used to retrieve the URL! Authorization Token If the answer server requires the installer to authenticate itself, for example when Proxmox Datacenter Manager hands out per-host answer files, an authorization token can be embedded into the ISO: proxmox-auto-install-assistant prepare-iso /path/to/source.iso --fetch-from http --url &quot;https://10.0.0.100/answer&quot; --answer-auth-token &quot;myhost:s3cr3t&quot; The token must be of the form &lt;name&gt;:&lt;secret&gt; . When set, the installer adds an Authorization: Bearer &lt;name&gt;:&lt;secret&gt; header to the HTTP POST request used to fetch the answer file. ℹ️ Note : The token is stored in plain text inside the prepared ISO and is visible to anyone with access to it. Treat the ISO accordingly. Example Similarly, it is possible to specify the URL from which the installer should fetch an answer file as well as the TLS certificate fingerprint. For example, to specify both: proxmox-auto-install-assistant prepare-iso /path/to/source.iso --fetch-from http --url &quot;https://10.0.0.100/get_answer/&quot; --cert-fingerprint &quot;04:42:97:27:F6:29:2F:9F:3D:7F:13:11:C8:E2:F5:5F:84:03:95:D9:F5:14:72:7C:9E:90:47:03:D2:96:2B:EC&quot; Network Booting via PXE Instead of writing the prepared ISO to a physical medium, you can boot the automatic installer over the network via PXE . Pass --pxe to split the prepared image into the vmlinuz kernel and initrd.img files needed for network booting, instead of producing an ISO file. In this mode, --output must point to a directory to place the files in, rather than a file name. proxmox-auto-install-assistant prepare-iso /path/to/source.iso --fetch-from http --url &quot;https://10.0.0.100/answer&quot; --pxe --output /srv/tftp/proxmox-auto/ To additionally generate a configuration snippet for a specific loader, pass --pxe-loader . Currently the only supported value is ipxe ; specifying it implies --pxe . The answer file is still retrieved according to the chosen --fetch-from mode. Fetching it via HTTP is the natural fit for a fully network-based provisioning workflow. Answer File Format The answer file is expected in TOML format. The following example shows an answer file with all possible sections. It uses the DHCP-provided network settings, network interface name pinning, and will use ZFS in a RAID-1 on disks sda and sdb . It also has a subscription key, a post-installation webhook and a first-boot hook configured: [global] keyboard = &quot;de&quot; country = &quot;at&quot; fqdn = &quot;pveauto.testinstall&quot; mailto = &quot;mail@no.invalid&quot; timezone = &quot;Europe/Vienna&quot; root-password = &quot;12345678&quot; root-ssh-keys = [ &quot;ssh-ed25519 AAAA...&quot; ] subscription-key = &quot;pve1c-0123456789&quot; [network] source = &quot;from-dhcp&quot; [network.interface-name-pinning] enabled = true [network.interface-name-pinning.mapping] &quot;24:8a:07:1e:05:bc&quot; = &quot;lan0&quot; &quot;24:8a:07:1e:05:bd&quot; = &quot;lan1&quot; &quot;b4:2e:99:ac:ad:b4&quot; = &quot;mgmt&quot; [disk-setup] filesystem = &quot;zfs&quot; zfs . raid = &quot;raid1&quot; disk-list = [ &quot;sda&quot; , &quot;sdb&quot; ] [post-installation-webhook] url = &quot;https://my.endpoint.local/postinst&quot; cert-fingerprint = &quot;AA:E8:CB:95:B1:...&quot; auth-token = &quot;secret-token&quot; [first-boot] source = &quot;from-iso&quot; ordering = &quot;before-network&quot; Global Section This section contains the following keys: keyboard -- The keyboard layout with the following possible options: de de-ch dk en-gb en-us es fi fr fr-be fr-ca fr-ch hu is it jp lt mk nl no pl pt pt-br se si tr country -- The country code in the two letter variant. For example, at , us or fr . fqdn -- Specifies the fully-qualified domain name of the host or the method to retrieve it dynamically. If set to a string, it will be set as fully-qualified domain name of the target. The domain part will be used as the search domain. Alternatively, two sub keys are available. See also the example section for a usage example. source -- Must be set to from-dhcp . Retrieves the host name (option 12) and, if available, domain name (option 15) from the DHCP lease configuration. In this mode, the DHCP server must provide a host name, otherwise the installation will fail. domain -- Fallback (search) domain name to use if the DHCP server does not provide one. mailto -- The default email address for the user root . timezone -- The timezone in tzdata format. For example, Europe/Vienna or America/New_York . root-password -- The password for the root user. root-password-hashed -- The pre-hashed password for the root user, which will be written verbatim to /etc/passwd . May be used instead of root-password and can be generated using the mkpasswd tool, for example. root-ssh-keys -- Optional. SSH public keys to add to the authorized_keys file of the root user after the installation. reboot-on-error -- Optional. If set to true , the installer will reboot automatically when an error is encountered. Defaults to false , giving the administrator a chance to investigate why an installation failed. reboot-mode -- Optional. Specifies whether the target machine should be rebooted or powered off after a successful installation. Options are reboot (default) and power-off . subscription-key -- Optional. A Proxmox subscription key for the installed product. The key is staged during the installation and activated automatically on the first boot, once network connectivity is available. This avoids a manual registration step for an otherwise unattended install. Only Proxmox VE, Proxmox Backup Server and Proxmox Mail Gateway keys are accepted; the matching activation tool is selected based on the key. Setting this option implies installing the proxmox-first-boot package (see the first-boot hook section ). ℹ️ Note : The staged key is removed again after the first activation attempt, regardless of its outcome. If activation fails, for example because the host has no internet access yet, the corresponding service is left in a failed state and the full context is logged to the journal for manual follow-up. Either root-password or root-password-hashed must be set. Setting none or both will result in a validation error. Network Section This section contains the following keys: source -- Where to source the static network configuration from. This can be from-dhcp or from-answer . If set to from-dhcp the other network options must not be set. The installer will then use the active NIC and the DHCP settings received during installation to write out a static network configuration. cidr -- The IP address in CIDR notation. For example, 192.168.1.10/24 . dns -- The IP address of the DNS server. gateway -- The IP address of the default gateway. filter -- Filter against the UDEV properties to select the network card. See filters . ℹ️ Note : The cidr , gateway and dns values may each be either an IPv4 or an IPv6 address. When using from-dhcp , the installer also picks up IPv6 addresses assigned via SLAAC or DHCPv6 and supports IPv6-only environments. Network Interface Name Pinning This subsection contains the following keys: enabled -- Whether network interface pinning is enabled. Without additional configuration, every interface will be assigned a name nic0 , nic1 , nic2 , etc. Interface Naming Pinning - Mapping This subsection contains the mappings from MAC addresses of the attached network devices to interface names in the following format: "&lt;mac&gt;" = "&lt;interface name&gt;" Disk Setup Section This section contains the following keys: filesystem -- One of the following options: ext4 , xfs , zfs , or btrfs . btrfs is only available for Proxmox VE installations. disk-list -- List of disks to use. Useful if you are sure about the disk names. For example: disk-list = ["sda", "sdb"] . ℹ️ Note : The content of disk-list is only a list of disks to be considered, but not required for the installer. If disks are listed but not accessible, the installer will still continue, given that enough disks from the list can be used for the selected filesystem or RAID mode. filter -- Filter against UDEV properties to select the disks for the installation. See filters . ℹ️ Note : Use either disk-list or filter . Defining both is not allowed. filter-match -- Can be &quot;any&quot; or &quot;all&quot;. Decides if a match of any filter is enough or if all filters need to match for a disk to be selected. The default is &quot;any&quot;. zfs -- Defines ZFS-specific properties. See ZFS Advanced Options of our documentation.
