datacenter.cfg(5) ☰ datacenter.cfg(5) Proxmox Server Solutions GmbH &lt; support@proxmox.com &gt; version 9.2.13, Thu Sep 24 19:51:15 CEST 2026 ↑ NAME datacenter.cfg - Proxmox VE Datacenter Configuration SYNOPSIS /etc/pve/datacenter.cfg DESCRIPTION The file /etc/pve/datacenter.cfg is a configuration file for Proxmox VE. It contains cluster wide default values used by all nodes. File Format The file uses a simple colon separated key/value format. Each line has the following format: OPTION: value Blank lines in the file are ignored, and lines starting with a # character are treated as comments and are also ignored. Options bwlimit : [clone=&lt;LIMIT&gt;] [,default=&lt;LIMIT&gt;] [,migration=&lt;LIMIT&gt;] [,move=&lt;LIMIT&gt;] [,restore=&lt;LIMIT&gt;] Set I/O bandwidth limit for various operations (in KiB/s). clone = &lt;LIMIT&gt; bandwidth limit in KiB/s for cloning disks default = &lt;LIMIT&gt; default bandwidth limit in KiB/s migration = &lt;LIMIT&gt; bandwidth limit in KiB/s for migrating guests (including moving local disks) move = &lt;LIMIT&gt; bandwidth limit in KiB/s for moving disks restore = &lt;LIMIT&gt; bandwidth limit in KiB/s for restoring guests from backups consent-text : &lt;string&gt; Consent text that is displayed before logging in. console : &lt;applet | html5 | vv | xtermjs&gt; Select the default Console viewer. You can either use the builtin java applet (VNC; deprecated and maps to html5), an external virt-viewer comtatible application (SPICE), an HTML5 based vnc viewer (noVNC), or an HTML5 based console client (xtermjs). If the selected viewer is not available (e.g. SPICE not activated for the VM), the fallback is noVNC. crs : [ha=&lt;basic|static|dynamic&gt;] [,ha-auto-rebalance=&lt;1|0&gt;] [,ha-auto-rebalance-hold-duration=&lt;number&gt;] [,ha-auto-rebalance-margin=&lt;number&gt;] [,ha-auto-rebalance-method=&lt;bruteforce|topsis&gt;] [,ha-auto-rebalance-threshold=&lt;number&gt;] [,ha-rebalance-on-start=&lt;1|0&gt;] Cluster resource scheduling settings. ha = &lt;basic | dynamic | static&gt; ( default = basic ) Configures how the HA Manager should select nodes to start or recover services: with basic , only the number of services is used, with static , static CPU and memory configuration of services are considered, with dynamic , static and dynamic CPU and memory usage of services are considered. ha-auto-rebalance = &lt;boolean&gt; ( default = 0 ) Whether to use CRS for balancing HA resources automatically depending on the current node imbalance. ha-auto-rebalance-hold-duration = &lt;number&gt; (0 - N) ( default = 3 ) The number of HA rounds for which the cluster node imbalance threshold must be exceeded before triggering an automatic resource balancing migration. Requires option(s): ha-auto-rebalance ha-auto-rebalance-margin = &lt;number&gt; (0 - 100) ( default = 10 ) The minimum relative improvement in cluster node imbalance, in percent, to commit to a resource balancing migration. Requires option(s): ha-auto-rebalance ha-auto-rebalance-method = &lt;bruteforce | topsis&gt; ( default = bruteforce ) The method to use for the scoring of balancing migrations. This is saved as comment inside the configuration file. email_from : &lt;string&gt; Specify email address to send notification from (default is root@$hostname) fencing : &lt;both | hardware | watchdog&gt; ( default = watchdog ) Set the fencing mode of the HA cluster. With both all two modes are used. hardware and both are EXPERIMENTAL &amp; WIP ha : shutdown_policy=&lt;enum&gt; Cluster wide HA settings. shutdown_policy = &lt;conditional | failover | freeze | migrate&gt; ( default = conditional ) Describes the policy for handling HA services on poweroff or reboot of a node. Freeze will always freeze services which are still located on the node on shutdown, those services won&#8217;t be recovered by the HA manager. Failover will not mark the services as frozen and thus the services will get recovered to other nodes, if the shutdown node does not come up again quickly (&lt; 1min). conditional chooses automatically depending on the type of shutdown, i.e., on a reboot the service will be frozen but on a poweroff the service will stay as is, and thus get recovered after about 2 minutes. Migrate will try to move all running services to another node when a reboot or shutdown was triggered. The poweroff process will only continue once no running services are located on the node anymore. If the node comes up again, the service will be moved back to the previously powered-off node, at least if no other migration, reloaction or recovery took place. http_proxy : http://.* Specify external http proxy which is used for downloads (example: http://username:password@host:port/ ) keyboard : &lt;da | de | de-ch | en-gb | en-us | es | fi | fr | fr-be | fr-ca | fr-ch | hu | is | it | ja | lt | mk | nl | no | pl | pt | pt-br | sl | sv | tr&gt; Default keybord layout for vnc server. language : &lt;ar | ca | da | de | en | es | eu | fa | fr | he | hr | it | ja | ka | kr | nb | nl | nn | pl | pt_BR | ru | sl | sv | tr | ukr | zh_CN | zh_TW&gt; Default GUI language. location : latitude=&lt;number&gt; ,longitude=&lt;number&gt; [,name=&lt;name&gt;] The location of the cluster. latitude = &lt;number&gt; (-90 - 90) The latitude of the nodes location in degrees. longitude = &lt;number&gt; (-180 - 180) The longitude of the nodes location in degrees. name = &lt;name&gt; The name of the location of this node mac_prefix : &lt;string&gt; ( default = BC:24:11 ) Prefix for the auto-generated MAC addresses of virtual guests. The default BC:24:11 is the Organizationally Unique Identifier (OUI) assigned by the IEEE to Proxmox Server Solutions GmbH for a MAC Address Block Large (MA-L). You&#8217;re allowed to use this in local networks, i.e., those not directly reachable by the public (e.g., in a LAN or NAT/Masquerading). Note that when you run multiple cluster that (partially) share the networks of their virtual guests, it&#8217;s highly recommended that you extend the default MAC prefix, or generate a custom (valid) one, to reduce the chance of MAC collisions. For example, add a separate extra hexadecimal to the Proxmox OUI for each cluster, like BC:24:11:0 for the first, BC:24:11:1 for the second, and so on.
