Integrate with AI agents to automate Terraform management. The tfctl CLI is a command-line tool for managing HCP Terraform and Terraform Enterprise resources. It simplifies authentication, workspace management, and API interactions, allowing you to integrate HCP Terraform and Terraform Enterprise into your automation pipelines and development workflows. Integrate tfctl with your AI agent to inspect and use the HCP Terraform or Terraform Enterprise API on your behalf. How does tfctl work? tfctl wraps the HCP Terraform and Terraform Enterprise API to provide both high-level convenience commands and direct API access. When you run a tfctl command, it authenticates using a token stored in your active profile. Then it resolves context from your profile and existing Terraform configuration, if any. Next tfctl makes API calls on your behalf, handling authentication, request formatting, and response parsing. Command levels The tfctl CLI provides three levels of abstraction: High-level commands such as tfctl variable import and tfctl run start for common operations. Generic commands such as tfctl create and tfctl get that work with any resource type. Direct API access using the tfctl api command group for operations not covered by convenience commands. Why tfctl? tfctl streamlines authentication to Terraform APIs by handling token generation through your browser or reuses existing Terraform CLI tokens. The CLI provides built-in skills for coding assistants such as Claude Code, GitHub Copilot, and IBM Bob, allowing you to manage Terraform workloads with your agent through full access to the HCP Terraform or Terraform Enterprise API. You can manage multiple organizations using tfctl&#x27;s profile-based configuration. For example, you can create separate profiles for development, staging, and production environments. Get started Complete these steps to start using tfctl: Install the CLI on your system. Refer to Install tfctl for instructions. Authenticate tfctl to your HCP Terraform account. Refer to Authenticate with HCP Terraform for instructions. Configure your environment by setting your default organization. Replace &lt;ORGANIZATION_NAME&gt; with the name of your HCP Terraform or Terraform Enterprise organization. $ tfctl profile set default_organization &lt; ORGANIZATION_NAME &gt; Test your configuration by listing workspaces for your organization. $ tfctl get workspaces AI agent integration The tfctl CLI is designed to work with AI agents such as Claude, GitHub Copilot, IBM Bob, and others. When you install the tfctl skill for your agent, you can use it to manage HCP Terraform resources with natural language, create automation for complex workflows across workspaces, organizations, and instances of HCP Terraform or Terraform Enterprise, and provide context-aware suggestions for Terraform operations. The skill provides your agent with documentation and examples, a requirement to get confirmation for destructive operations, and structured output for parsing and decision-making. To enable AI agent integration, refer to Install AI agent skill . Next steps For example use cases, review the examples for tfctl. To learn more about tfctl commands, refer to the CLI reference documentation . To learn how to manage tfctl configuration profiles, refer to tfctl profiles . Contributing The tfctl CLI is open source. To contribute to the project or build from source, visit the tfctl-cli repository on GitHub . The repository includes detailed developer documentation, contribution guidelines, and instructions for building from source. Terraform is logically split into two main parts: Terraform Core : This is the Terraform binary that communicates with plugins to manage infrastructure resources. It provides a common interface that allows you to leverage many different cloud providers, databases, services, and in-house solutions. Terraform Plugins : Plugins are executable binaries written in Go that communicate with Terraform Core over an RPC interface. Terraform currently supports one type of plugin called providers . Each provider plugin exposes an implementation for a specific service or tool, such as the AWS provider or the cloud-init provider . The Terraform Registry is an interactive resource for discovering a wide selection of integrations (providers), configuration packages (modules), and security rules (policies) for use with Terraform. The Registry includes solutions developed by HashiCorp, third-party vendors, and our Terraform community. Our goal with the Registry is to provide plugins to manage any infrastructure API, pre-made modules to quickly configure common infrastructure components, and examples of how to write quality Terraform code. The Terraform Registry is integrated directly into Terraform so you can directly specify providers and modules. Anyone can publish and consume providers, modules, and policies on the public Terraform Registry . To publish private modules within your organization, you can use a private registry or reference repositories and other sources directly . Use the navigation to the left to learn more about using the Terraform Registry. Navigating the Registry The registry has a number of different categories for modules, providers, and policies to help with navigating the large number of available options. Select a provider or module card to learn more, filter results to a specific tier , or use the search field at the top of the Registry. Search supports keyboard navigation. User Account Individuals interested in publishing can use a GitHub account to sign in to the Terraform Registry. Click the Sign-in button, and follow the login prompts to authorize the use of your GitHub account and sign in. Refer to the specific instructions for publishing modules , providers , and policy libraries . If you are an HCP Terraform user and want to publish and manage modules or providers in the public registry, you can connect a GitHub account to an HCP Terraform organization, letting members collectively manage that account’s public registry artifacts. Refer to Namespaces for more information. Getting Help The providers, modules, and policies available on the Terraform Registry are maintained either directly by HashiCorp, by trusted HashiCorp partners, or members of the Terraform community Refer to Provider Tiers and Namespaces for details. To create issues and contributions in GitHub, click the Report an issue link on the provider, module, or policy library&#x27;s details page: If you are having trouble publishing new content to the Terraform Registry, refer to the Publishing FAQ for answers to some of the most commonly-encountered problems. If you have general questions or issues about using the Terraform Registry, you may submit a request . Note that there is currently a delay in response times, and we are unable to guarantee a response to all requests. If you are a HashiCorp Technology Partner, our Alliances team will get back to you with a timeline.
