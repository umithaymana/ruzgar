HCP Terraform docs: Permissions Plan (verb) Also &quot;queue plan&quot;. To start a new run , which begins by running a Terraform plan (noun) . HCP Terraform docs: About Runs Plan (noun, 1) One of the stages of a run , in which Terraform compares the managed infrastructure&#x27;s real state to the configuration and variables , determines which changes are necessary to make the real state match the desired state, and presents a human-readable summary to the user. The counterpart of an apply . In Terraform&#x27;s CLI, plans are performed by all of the following commands: terraform plan , which only performs a plan. It can optionally output a plan file , which terraform apply can use to perform that exact set of planned changes. terraform apply , which performs a plan and then, if a user approves, immediately applies it. terraform destroy , which is similar to terraform apply but uses a desired state in which none of the managed resources exist; if the plan is approved, those resources are destroyed. In HCP Terraform, plans are performed by committing changes to a workspace&#x27;s configuration, running terraform plan or terraform apply with the remote backend enabled, manually queueing a plan, or uploading a configuration via the API. HCP Terraform&#x27;s workflow always creates a plan file , which can be auto-applied or can wait for a user&#x27;s approval. HCP Terraform also supports speculative plans , which are for informational purposes only and cannot be applied. A binary artifact optionally produced by the terraform plan command, which terraform apply can use to carry out the exact changes that were decided at the time of the plan . HCP Terraform always uses a saved plan as the input to an apply , so that applies never make changes that weren&#x27;t shown to the user after the plan (in cases where the config or the variables changed in the meantime). Wikipedia: Repository (version control) Resource Also &quot;infrastructure resource&quot;. In Terraform&#x27;s configuration language: A block that describes one or more infrastructure objects. Resources can be things like virtual networks, compute instances, or higher-level components such as DNS records. In other Terraform-related contexts: An infrastructure object of a type that could be managed by Terraform. A resource block in a configuration instructs Terraform to manage the described resource — during a run, Terraform will create a matching real infrastructure object if one doesn&#x27;t already exist, and will modify the existing object if it doesn&#x27;t match the desired configuration. Terraform uses state to keep track of which real infrastructure objects correspond to resources in a configuration. Terraform uses cloud provider APIs to create, edit, and destroy resources. Terraform providers are responsible for defining resource types and mapping transitions in a resource&#x27;s state to a specific series of API calls that will carry out the necessary changes.
