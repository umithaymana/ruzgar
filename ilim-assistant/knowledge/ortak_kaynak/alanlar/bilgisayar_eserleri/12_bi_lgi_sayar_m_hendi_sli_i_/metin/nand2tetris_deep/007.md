--> Project 07 | nand2tetris top of page From Nand to Tetris Building a Modern Computer From First Principles Project 7: Virtual Machine I - Stack Arithmetic Background Java (or C#) compilers generate code written in an intermediate language called&nbsp;bytecode&nbsp;(or&nbsp;IL). This code is designed to run on a virtual machine architecture like the JVM (or CLR). One way to implement such VM programs is to translate them further into lower-level programs written in the machine language of some concrete (rather than virtual) host computer. In projects 7 and 8 we build such a&nbsp;VM translator, designed to translate programs written in the VM language into programs written in the Hack assembly language. The VM language, abstraction, and translation process are described in chapters 7 and 8 of the book. For the purpose of this project, chapter 8 can be ignored. Objective Build a basic&nbsp;VM translator, focusing on the implementation of the VM language&#39;s&nbsp;stack arithmetic&nbsp;and&nbsp;memory accesscommands. In Project 8, this basic translator will be extended into a full-scale VM translator. Contract Write a VM-to-Hack translator, conforming to the&nbsp;VM Specification, Part I&nbsp;(book section 7.2) and to the&nbsp;Standard VM-on-Hack Mapping, Part I&nbsp;(book section 7.3.1). Use your VM translator to translate the VM files supplied below, yielding corresponding programs written in the Hack assembly language. When executed on the supplied&nbsp;CPU emulator, the translated code generated by your translator should deliver the results mandated by the test scripts and compare files supplied below. Usage Depending on the programming language that you use, the VM translator should be invoked using something like &quot;VMTranslator&nbsp;fileName.vm&quot; , where the string&nbsp;fileName.vm&nbsp;is the translator&#39;s input, i.e. the name of a text file containing VM commands. The translator creates an output file named&nbsp;fileName.asm, which is stored in the same directory of the input file. The name of the input file may contain a file path. Resources The relevant reading for this project is chapter 7. You will need two tools: the programming language with which you will implement your VM translator, and the supplied&nbsp;CPU emulator. This emulator allows executing, and testing, on your PC, the machine code generated by your VM translator. Another tool that comes handy in this project is the supplied&nbsp;VM emulator. The VM emulator (described at the bottom of this page) allows experimenting with the supplied VM programs before setting out to write your VM translator. Proposed Implementation We propose implementing the basic VM translator API described in chapter 7 in two stages. This will allow you to unit-test your implementation incrementally, using the test programs supplied below. In what follows, when we say &quot;your VM translator should implement some VM command&quot; we mean &quot;your VM translator should translate the given VM command into a sequence of Hack assembly commands that accomplish the same task&quot;. &nbsp; Stage I: Handling stack arithmetic commands: &nbsp;The first version of your basic VM translator should implement the nine arithmetic / logical commands of the VM language as well as the VM command&nbsp;push&nbsp;constant&nbsp;x. &nbsp; The latter command is the generic&nbsp;push&nbsp;command for which the first argument is&nbsp;constant&nbsp;and the second argument is some non-negative integer x. This command comes handy at this early stage, since it helps provide values for testing the implementation of the arithmetic / logical VM commands. For example, in order to test how your VM translator handles the VM&nbsp;add&nbsp;command, we can test how it handles the VM code&nbsp;push&nbsp;constant&nbsp;3,&nbsp;pushconstant&nbsp;5,&nbsp;add. The other arithmetic and logical commands are tested similarly. &nbsp; Stage II: Handling memory access commands: &nbsp;The next version of your basic VM translator should include a full implementation of the VM language&#39;s&nbsp;push&nbsp;and&nbsp;pop&nbsp;commands, handling the eight memory segments described in chapter 7.
