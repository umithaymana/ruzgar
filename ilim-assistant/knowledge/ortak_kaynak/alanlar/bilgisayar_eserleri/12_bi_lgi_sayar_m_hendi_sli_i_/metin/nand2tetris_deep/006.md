--> Project 07 | nand2tetris top of page From Nand to Tetris Building a Modern Computer From First Principles Project 7: Virtual Machine I - Stack Arithmetic Background Java (or C#) compilers generate code written in an intermediate language called&nbsp;bytecode&nbsp;(or&nbsp;IL). This code is designed to run on a virtual machine architecture like the JVM (or CLR). One way to implement such VM programs is to translate them further into lower-level programs written in the machine language of some concrete (rather than virtual) host computer. In projects 7 and 8 we build such a&nbsp;VM translator, designed to translate programs written in the VM language into programs written in the Hack assembly language. The VM language, abstraction, and translation process are described in chapters 7 and 8 of the book. For the purpose of this project, chapter 8 can be ignored. Objective Build a basic&nbsp;VM translator, focusing on the implementation of the VM language&#39;s&nbsp;stack arithmetic&nbsp;and&nbsp;memory accesscommands. In Project 8, this basic translator will be extended into a full-scale VM translator. Contract Write a VM-to-Hack translator, conforming to the&nbsp;VM Specification, Part I&nbsp;(book section 7.2) and to the&nbsp;Standard VM-on-Hack Mapping, Part I&nbsp;(book section 7.3.1). Use your VM translator to translate the VM files supplied below, yielding corresponding programs written in the Hack assembly language. When executed on the supplied&nbsp;CPU emulator, the translated code generated by your translator should deliver the results mandated by the test scripts and compare files supplied below. Usage Depending on the programming language that you use, the VM translator should be invoked using something like &quot;VMTranslator&nbsp;fileName.vm&quot; , where the string&nbsp;fileName.vm&nbsp;is the translator&#39;s input, i.e. the name of a text file containing VM commands. The translator creates an output file named&nbsp;fileName.asm, which is stored in the same directory of the input file. The name of the input file may contain a file path. Resources The relevant reading for this project is chapter 7. You will need two tools: the programming language with which you will implement your VM translator, and the supplied&nbsp;CPU emulator. This emulator allows executing, and testing, on your PC, the machine code generated by your VM translator. Another tool that comes handy in this project is the supplied&nbsp;VM emulator. The VM emulator (described at the bottom of this page) allows experimenting with the supplied VM programs before setting out to write your VM translator. Proposed Implementation We propose implementing the basic VM translator API described in chapter 7 in two stages. This will allow you to unit-test your implementation incrementally, using the test programs supplied below. In what follows, when we say &quot;your VM translator should implement some VM command&quot; we mean &quot;your VM translator should translate the given VM command into a sequence of Hack assembly commands that accomplish the same task&quot;. &nbsp; Stage I: Handling stack arithmetic commands: &nbsp;The first version of your basic VM translator should implement the nine arithmetic / logical commands of the VM language as well as the VM command&nbsp;push&nbsp;constant&nbsp;x. &nbsp; The latter command is the generic&nbsp;push&nbsp;command for which the first argument is&nbsp;constant&nbsp;and the second argument is some non-negative integer x. This command comes handy at this early stage, since it helps provide values for testing the implementation of the arithmetic / logical VM commands. For example, in order to test how your VM translator handles the VM&nbsp;add&nbsp;command, we can test how it handles the VM code&nbsp;push&nbsp;constant&nbsp;3,&nbsp;pushconstant&nbsp;5,&nbsp;add. The other arithmetic and logical commands are tested similarly. &nbsp; Stage II: Handling memory access commands: &nbsp;The next version of your basic VM translator should include a full implementation of the VM language&#39;s&nbsp;push&nbsp;and&nbsp;pop&nbsp;commands, handling the eight memory segments described in chapter 7. We suggest breaking this stage into the following sub-stages: ​ You have already handled the&nbsp;constant&nbsp;segment; Next, handle the segments&nbsp;local,&nbsp;argument,&nbsp;this, and&nbsp;that; Next, handle the&nbsp;pointer&nbsp;and&nbsp;temp&nbsp;segments, in particular allowing modification of the bases of the&nbsp;this and&nbsp;that&nbsp;segments. Finally, handle the&nbsp;static&nbsp;segment. Testing We supply five VM programs, designed to unit-test the staged implementation proposed above. For each program&nbsp;Xxxwe supply four files. The&nbsp;Xxx.vm&nbsp;file contains the program&#39;s VM code. The&nbsp;XxxVME.tst&nbsp;script allows running the program on the supplied&nbsp;VM emulator, to experiment with the program&rsquo;s intended operation. After translating the program using your VM translator, the supplied&nbsp;Xxx.tst&nbsp;script and&nbsp;Xxx.cmp&nbsp;compare file allow testing the translated assembly code on the supplied&nbsp;CPU emulator. ​ Testing how the VM translator handles&nbsp;arithmetic commands: Program Program SimpleAdd.vm Program StackTest.vm Description Test Scripts Description Pushes two constants onto the stack and adds them up. In addition, the virtual memory segments must be mapped on selected areas in the host RAM. The bootstrap code and the memory mappings are described in chapter 8 and handled by the final version of the VM translator, implemented in the next project. In the current project you should worry about none of these issues, since all the necessary VM initializations and memory mappings are handled by the supplied test scripts. In other words, the assembly code that your translator generates should contain the translation of the VM commands found in the input file, and nothing else. ​ Steps: ​ For each one of the five test programs supplied above, follow these steps: ​ To get acquainted with the intended behavior of the supplied test program&nbsp;Xxx.vm, run it on the supplied&nbsp;VM emulator&nbsp;using the supplied&nbsp;XxxVME.tst&nbsp;script. Use your VM translator to translate the supplied&nbsp;Xxx.vm&nbsp;file. The result should be a new text file containing Hack assembly code, named&nbsp;Xxx.asm. Inspect the&nbsp;Xxx.asm&nbsp;program generated by your VM translator. If there are visible syntax (or any other) errors, debug and fix your VM translator. To check if the generated code performs properly, use the supplied&nbsp;Xxx.tst&nbsp;and&nbsp;Xxx.cmp&nbsp;files to run the&nbsp;Xxx.asm&nbsp;program on the supplied&nbsp;CPU emulator. If there are any problems, debug and fix your VM translator. &nbsp; Implementation Order: &nbsp;The supplied test programs were carefully planned to test the incremental features introduced by each development stage of your basic VM translator. Therefore, it&#39;s important to implement your translator in the proposed order, and to test it using the appropriate test programs at each stage. Implementing a later stage before an early one may cause the test programs to fail. &nbsp; When you are done with this project , be sure to save a copy of your VM translator. In the next project you will be asked to modify and extend this program, adding the handling of more VM commands. If your project 8 modifications will end up breaking some of the working code developed in project 7, you&rsquo;ll be able to resort to a clean backup version. Tools Before setting out to develop your VM translator, we recommend getting acquainted with the virtual machine architecture model and language. As mentioned above, this can be done by running, and experimenting with, the supplied&nbsp;.vm&nbsp;test programs using the supplied&nbsp;VM emulator. ​ The VM emulator: &nbsp;This Java program, located in your&nbsp;nand2tetris/tools&nbsp;directory, is designed to execute VM programs in a direct and visual way, without having to first translate them into machine language. For example, you can use the supplied VM emulator to see - literally speaking - how&nbsp;push&nbsp;and&nbsp;pop&nbsp;commands effect the stack. And, you can use the simulator to execute any one of the supplied&nbsp;.vm&nbsp;test programs.
