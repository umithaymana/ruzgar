--> Project 03 | nand2tetris top of page From Nand to Tetris Building a Modern Computer From First Principles Project 3: Memory Background The computer&#39;s main memory, also called&nbsp;Random Access Memory, or&nbsp;RAM, is an addressable sequence of&nbsp;n-bit registers, each designed to hold an&nbsp;n-bit value. In this project you will gradually build a RAM unit. This involves two main issues: (i) how to use gate logic to store bits persistently, over time, and (ii) how to use gate logic to locate (&quot;address&quot;) the memory register on which we wish to operate. Objective Build all the chips described in Chapter 3 (see list below), leading up to a&nbsp;Random Access Memory&nbsp;(RAM) unit. Resources See&nbsp; Chapter 3 , the HDL Guide , and the Hack Chip Set . For each chip, we supply a skeletal .hdl file with a missing implementation part. In addition, for each chip we supply a .tst script that instructs the hardware simulator how to test it, and a .cmp (&quot;compare file&quot;) containing the correct output that this test should generate. Your job is to complete and test the supplied skeletal .hdl files. The tools that you need for this project are the supplied hardware simulator and the files listed above. If you&#39;ve downloaded the Nand2Tstris Software Suite, these files are stored in your projects/03 folder. The folder is further partitioned into two sub-folders, for reasons described below. Tips The Data Flip-Flop (DFF) gate &nbsp;is considered primitive and thus there is no need to build it: when the simulator encounters a DFF chip part in an HDL program, it automatically invokes the built-in nand2tetris/tools/builtInChips/DFF.hdl&nbsp;implementation. ​ Built-in chips: &nbsp;When constructing RAM chips from lower-level RAM chip-parts, we recommend using built-in versions of the latter. Otherwise, the simulator will recursively generate numerous memory-resident software objects, one for each one of the many chip parts that make up a typical RAM unit. This may cause the simulator to run slowly, or, worse, out of memory. i.e. out of the memory of the computer on which the simulator is running.&nbsp; To avert this problem, we&#39;ve partitioned the RAM chips that you have to build in this project into two sub-directories, named&nbsp;projects/03/a&nbsp;and&nbsp;projects/03/b. This partition is superficial, and is done with one purpose only: when building the chips stored in&nbsp;b, the simulator is forced to use built-in implementations of the lower-level chip parts whose&nbsp;.hdl&nbsp;programs are stored in&nbsp;a&nbsp;but not in&nbsp;b. Tools All the chips mentioned projects 0-5 can be implemented and tested using the supplied hardware simulator.
