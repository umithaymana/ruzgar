These tools enable the completion and testing of all the projects described in the courses and in the book. The tools are available in one package that comes in two versions: &nbsp; Nand to Tetris Online IDE: This new Integrated Development Environment is web-based, meaning that you don&rsquo;t have to download anything: All the tools and files necessary for completing all the projects are available from your browser. The files that you&rsquo;ll develop using this IDE will be saved automatically in your browser&rsquo;s memory, and you&rsquo;ll be able to download them to your local PC, as needed. &nbsp; Nand to Tetris Software package : In this legacy &ldquo;desktop version&rdquo;, the tools are implemented as Java programs that run on your local PC. In order to use this version of the&nbsp; tools, you must download a zip file to your PC, and extract it. Also, your PC should be able to run Java programs. ​ We recommend using the&nbsp; new IDE, which is easy to use and requires no installation. The desktop version is provided mainly for backward compatibility. ​ All the software tools, in both versions, are supplied freely, in open source. About the Software The Nand2tetris Software Suite consists of two folders:&nbsp; projects , and&nbsp; tools . &nbsp; The projects folder is divided into 14 project folders named 00, 01, ..., 13. These folders contain files that you have to modify and complete as you work on various nand2tetris projects. &nbsp; The tools folder contains the nand2tetris software tools. It&#39;s a collection of programs and files that will be explained as you follow the various projects. &nbsp; The remainder of this section should be used as reference; there is no need to read what follows until you will be asked to use a particular software tool. &nbsp; The .bat and .sh files &nbsp;are batch and script files, used to invoke the nand2tetris software tools. These files are explained in detail below. &nbsp; The bin folder &nbsp;contains the code of the nand2tetris software tools. It consists of several sub-folders containing Java class files and supporting files. &nbsp; The builtInChips and the builtInVMCode folders &nbsp;contain files that are used by the supplied Hardware Simulator and VM Emulator, respectively. &nbsp; The OS folder &nbsp;contains a compiled version of the Jack operating system. VM Emulator Tutorial: Test Scripts Running a VM program press to zoom Tool Assembler Description Translates programs from the Hack assembly language to Hack binary code. The resulting code can be executed directly on the&nbsp;Computer chip&nbsp;(in the hardware simulator), or emulated on the supplied&nbsp;CPU Emulator&nbsp;(much faster and more convenient). Assembler Tutorial: Test Scripts Using a compare file press to zoom press to zoom Tool Compiler Description Translates programs written in Jack (a simple, Java-like object-based language) into VM code. Alternatively, the VM code can be translated further by the supplied&nbsp;VM translatorinto Hack assembly code that can then be executed on the supplied&nbsp;CPU Emulator. Test Scripts (A GUI-less, command-level program) Translating Running the Software Tools The supplied software tools are designed to be run from your computer&#39;s command-line environment (also known as &quot;terminal&quot;, or &quot;shell&quot;). Command-line environments vary from one operating system to another, and working in them requires some knowledge of various OS shell commands. ​ In order to eliminate this overhead, we supply batch files (for Windows) and scripts (for Unix and Mac OS), developed by Mark Armbrust. These batch and script files enable invoking the supplied nand2tetris tools from the command line on your computer, painlessly. They can be used from any folder on your computer, without requiring full paths to the files on which they operate. Further, they accept spaces in folder and file names, so they will work if nand2tetris is installed under a folder named, say, &quot;My Documents&quot;. ​ Mac and Linux users &nbsp; Before running the scripts, you must first change their file attributes to include &quot;executable&quot;. You can then run the scripts by typing their name, as well as the .sh extension, in the terminal environment. &nbsp; If you want to avoid typing the &#39;sh&#39; extensions, you can create (once and for all) symbolic links in your ~/bin folder. Here is an example how to do it for, say, the HardwareSimulator tool: &nbsp; ln -s ~/nand2tetris/tools/HardwareSimulator.sh HardwareSimulator chmod +x HardwareSimulator ​ Windows users ​ For the batch files to work from the command line, you must add (once and for all) the nand2tetris/tools folder to your PATH variable. ​ To run a batch file from command-line, type its name, without the .bat extension. ​ If you use Windows 7 64-bit you need to install the 64-bit version of Java so that 64-bit cmdexe can run Java commands in batch files. If you get the output &quot;&#39;java&#39; is not recognized...&quot; you likely only have the 32-bit Java installed on your computer. ​ You can create desktop icons and use them to invoke the interactive versions of the following supplied tools: HardwareSimulator, Assembler, CPUEmulator and VMEmulator. This can be done by finding the disk locations of the respective batch files, right-clicking on them and picking &quot;Send to &gt; Desktop.&quot; Edit the shortcuts&#39; properties and set &quot;Run&quot; to &quot;minimized.&quot; ​ Usage ​ Hardware Simulator : To invoke the hardware simulator in interactive mode, type &quot;HardwareSimulator&quot; in the command line. For example: ​ C:\...\projects\02&gt; HardwareSimulator (a window will open up, running the interactive version of the Hardware Simulator) ​ To invoke the hardware simulator in batch (shell/cmd) mode, type &quot;HardwareSimulator&quot; in the command line. For example: ​ C:\...\projects\02&gt;HardwareSimulator ALU.tst (invokes the simulator, loads the given test script, executes it, and reports the result). Note that the simulator&#39;s interactive mode also enables loading and executing test scripts. &nbsp; Successful test (example): ​ C:\...\projects\02&gt; HardwareSimulator ALU.tst End of script - Comparison ended successfully &nbsp; Failed test (example): ​ C:\...\projects\02&gt; HardwareSimulator ALU.tst Comparison failure at line 24 &nbsp; Error in the associated HDL file: ​ C:\...\projects\02&gt; HardwareSimulator ALU.tst In HDL file C:\...\projects\02\ALU.hdl, Line 60, out[16]: the specified sub bus is not in the bus range: load ALU.hdl ​ CPU Emulator and VM Emulator : The operations of these tools follow the same convention described above. If you invokve either tool without a parameter, the tool will work in interactive mode; if you supply a parameter (test script), the tool will run batch-style. ​ Assembler : Typing &quot;Assembler&quot; will start the supplied assembler in interactive mode.
