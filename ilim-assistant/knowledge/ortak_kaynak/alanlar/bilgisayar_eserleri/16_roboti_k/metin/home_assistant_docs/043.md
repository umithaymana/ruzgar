See also MQTT Discovery section Birth and last will messages Home Assistant’s MQTT integration supports so-called Birth and Last Will and Testament (LWT) messages. The former is used to send a message after the service has started, and the latter is used to notify other clients about a disconnected client. Note that the LWT message will be sent both in case of a clean disconnect (for example, Home Assistant shutting down) and in case of an unclean disconnect (for example, Home Assistant crashing or losing its network connection). If a disabled entity is enabled and added after 30 seconds, the MQTT integration will be reloaded and will cause all discovered MQTT entities to be unloaded. When MQTT starts up, all existing MQTT devices, entities, tags, and device triggers, will be unavailable until a discovery message is received and processed. A device or service that exposes the MQTT discovery should subscribe to the Birth message and use this as a trigger to send the discovery payload . To avoid high IO loads on the MQTT broker, adding some random delay in sending the discovery payload is recommended. Alternative approaches: Retaining the discovery payload : This will store the discovery payload at the MQTT broker, and offer it to the MQTT integration as soon as it subscribes for MQTT discovery. When there are a lot of entities, this can cause high IO loads. Periodically resending the discovery payload: This can cause some delay, or a lot of IO if there are a lot of MQTT discovery messages. By default, Home Assistant sends online and offline to homeassistant/status . MQTT Birth and Last Will messages can be customized or disabled from the UI. To do this, select Configure on the integration page in the UI, then Re-configure MQTT , and then Next . If the unique_id option is configured, you can change the entity_id after creation, and the changes are stored in the Entity Registry. The entity_id is generated when an item is loaded the first time. If the default_entity_id option is set, then this will be used to generate the entity_id . If, for example, we have configured a sensor , and we have set default_entity_id to sensor.test , then Home Assistant will try to assign sensor.test as entity_id . If sensor.test already exists, Home Assistant will append a suffix to make it unique, for example, sensor.test_2 . This means any MQTT entity which is part of a device will automatically have its friendly_name attribute prefixed with the device name Unnamed binary_sensor , button , number , and sensor entities will now be named by their device class instead of being named “MQTT binary sensor” and similar. It’s allowed to set an MQTT entity’s name to None (use null in YAML) to mark it as the main feature of a device. Note that on each MQTT entity, the has_entity_name attribute will be set to True . More details can be found here . MQTT device configuration MQTT entities, device triggers, and tags can be linked to a device in the device registry . With YAML and MQTT discovery, the device information is set with the device mapping, which can be abbreviated as dev in discovery messages. With subentries, the device information is set in the UI. At least one of identifiers or connections must be set to identify the device. For entities, the device information is only used when the entity has a unique_id . Entities, device triggers, and tags that use the same identifiers or connections are linked to the same device. When a device is shared, it is enough to set the shared identifiers or connections for the other items. It is recommended to always include the device name . When the device information of an entity changes to another device, for example with a discovery update or a changed YAML configuration, the entity is moved to the new device. The previous device is removed when no other entities, device triggers, or tags use it. A child device can’t be moved to another parent device, see child devices . How the device information is set depends on the configuration method. Child devices A physical device can be split into child devices, for example, the outlets of a power strip, or the channels of a multi-channel switch. A child device is a part of its parent device, and has its own name and entities. A child device uses the area of its parent device, unless another area is assigned to it, and is removed together with its parent device. With YAML and single component discovery, a child device is set with the child_device mapping, which can be abbreviated as cdev in discovery messages. The device mapping then describes the parent device. With device discovery, child devices are listed in child_devices ( cdevs ), together with their components, see device configuration with device discovery . Only identifiers and name can be set for a child device. The identifiers are required. Other device information, like the manufacturer , belongs to the parent device. A child device requires the entity to have a unique_id . Child devices are not supported for device triggers, tags, and subentries. A child device can’t be used as the via_device of another device. When the child_device of an entity is added, changed, or removed, the entity is moved to the new device in the same way, and a child device that is no longer used is removed. When discovered items are removed, a parent device is kept as long as it has child devices, and is removed after its last child device when no other items use it. When the identifiers of an existing MQTT device are used for a child device, the existing device is converted into a child device. It keeps its device ID, so automations that use the device keep working. If the existing device is still in use as a regular device, the conversion fails. An entity with that child device is then not added, and an error is logged. With a discovery update, the update is canceled, the entity keeps its current configuration and device, and a warning is logged. In that case, update the configuration of all items that use the device, and reload the MQTT integration. A child device can’t be moved to another parent device. When the parent device of a child device changes, the same happens as when a conversion fails. To move a child device to another parent device, remove the child device in Home Assistant, and reload the MQTT integration. The child device is then added again with its new parent device, and keeps its device ID. With single component discovery, removing the child device can also clear the discovery payloads of its entities. The publisher then has to send them again. Device configuration in YAML Add a device mapping to the configuration of each entity that is part of the device.
