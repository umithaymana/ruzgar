You can add another target by selecting Add target again. Select Save . Automations as entities Each automation is also an entity An entity represents a sensor, actor, or function in Home Assistant. Entities are used to monitor physical properties or to control other entities. An entity is usually part of a device or a service. [Learn more] , with an entity ID such as automation.turn_on_porch_light . Automation entities are listed with all other entities under Settings &gt; Devices &amp; services &gt; Entities . Like other entities, you can show an automation entity on a dashboard, or use it in other automations and scripts A script is a saved list of steps that runs when you start it, for example, from a dashboard, with Assist, or from an automation. Unlike an automation, a script has no triggers, so it doesn’t start by itself. [Learn more] . Automation states The state The state holds the information of interest of an entity, for example, if a light is on or off. Each entity has exactly one state and the state only holds one value at a time. However, entities can store attributes related to that state such as brightness, color, or a unit of measurement. Automation attributes The attributes tell you more about an automation, such as when it last ran, or whether it’s running right now. You can use them to check an automation without opening it, or to make another automation depend on it. You can see and use the attributes in different places: In the entities list or on a dashboard, select the automation entity, and then select Menu &gt; Details . In an automation or a script, select an attribute in the Attribute field of a State trigger or condition. In templates, use state_attr() . For example, state_attr('automation.turn_on_porch_light', 'last_triggered') . Automations have the following automation-specific attributes. Max running automations and ID are only present in some cases, as described in the list. If an automation is unavailable, ID is the only automation-specific attribute it can have. You can use them in automations and scripts. If a condition is not met, the actions that come after it in the same sequence do not run. Running automations ( current ): How many runs of the automation there are right now. In Queued mode, this includes the runs that are waiting in the queue. Usually, this is 0 . Use it to wait until an automation has finished, or to skip something while it’s still running. Run mode ( mode ): What happens when a trigger reacts while the automation is still running: Single , Restart , Queued , or Parallel . For details, refer to Automation modes . Max running automations ( max ): How many runs there can be at the same time, including runs that are waiting. Only automations in Queued or Parallel mode have this attribute. When Running automations reaches this number, the next time a trigger reacts, no new run is added. For details, refer to I see an “Already running” warning in the logs . ID ( id ): The unique ID of the automation. It connects the entity to the configuration of the automation. Automations that you create in the editor always have one. Automations in YAML only have one if you set id . Actions for automations To control an automation from another automation or a script, use these actions An action makes Home Assistant do something, for example, turn on a light, send a notification, or activate a scene. Automations and scripts run a list of actions. [Learn more] : Turn on automation : Sets the state to On . Turn off automation : Sets the state to Off . By default, it also stops the actions that are running. Toggle automation : Switches the state between On and Off . Trigger automation : Runs the actions right away, without waiting for a trigger.
