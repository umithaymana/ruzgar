Standard percent-encoding (and using the plus sign for space) can be used to escape keys and values. Options can also can be specified via command line options (or in code via AVOption s). The TLS backend is selected at build time. The available backends are GnuTLS, OpenSSL, mbedTLS, libtls, SChannel (Windows) and Secure Transport (Apple platforms). Only one backend can be linked into a build. On Apple platforms, configure autodetects Secure Transport when no other TLS library is enabled. Apple has deprecated Secure Transport in favor of Network.framework and it does not support TLS 1.3, so such a build cannot connect to servers that require TLS 1.3. configure therefore emits a warning when it selects Secure Transport automatically; building with --enable-gnutls or --enable-openssl is recommended instead. Passing --enable-securetransport explicitly marks the backend as requested and suppresses the warning. This is also needed with --fatal-warnings , since any warning makes configure fail. The list of supported options follows. ca_file, cafile= filename A file containing certificate authority (CA) root certificates to treat as trusted. If the linked TLS library contains a default this might not need to be specified for verification to work, but not all libraries and setups have defaults built in. The file must be in OpenSSL PEM format. When no file is given, Windows builds using OpenSSL 3.2 or later with Windows certificate store support also use certificates from the system ROOT store.
