If this is too slow, or if exactly reproducible frame-perfect results are needed, it&rsquo;s recommended to turn this feature off. peak_detect Enable HDR peak detection. Ignores static MaxCLL/MaxFALL values in favor of dynamic detection from the input. Note that the detected values do not get written back to the output frames, they merely guide the internal tone mapping process. Enabled by default. smoothing_period Peak detection smoothing period, between 0.0 and 1000.0 . Higher values result in peak detection becoming less responsive to changes in the input. Defaults to 20.0 . scene_threshold_low scene_threshold_high Lower and upper thresholds for scene change detection. Expressed in a logarithmic scale between 0.0 and 100.0 . Default to 1.0 and 3.0 , respectively. Setting either to a negative value disables this functionality. percentile Which percentile of the frame brightness histogram to use as the source peak for tone-mapping. Defaults to 99.995 , a fairly conservative value. Setting this to 100.0 disables frame histogram measurement and instead uses the true peak brightness for tone-mapping. 32.148.1.7 Tone mapping # TOC The options in this section control how libplacebo performs tone-mapping and gamut-mapping when dealing with mismatches between wide-gamut or HDR content. In general, libplacebo relies on accurate source tagging and mastering display gamut information to produce the best results. gamut_mode How to handle out-of-gamut colors that can occur as a result of colorimetric gamut mapping. &lsquo; clip &rsquo; Do nothing, simply clip out-of-range colors to the RGB volume. Low quality but extremely fast. &lsquo; perceptual &rsquo; Perceptually soft-clip colors to the gamut volume. This is the default. &lsquo; relative &rsquo; Relative colorimetric hard-clip. Similar to perceptual but without the soft knee. &lsquo; saturation &rsquo; Saturation mapping, maps primaries directly to primaries in RGB space. Not recommended except for artificial computer graphics for which a bright, saturated display is desired. &lsquo; absolute &rsquo; Absolute colorimetric hard-clip. Performs no adjustment of the white point. &lsquo; desaturate &rsquo; Hard-desaturates out-of-gamut colors towards white, while preserving the luminance. Has a tendency to distort the visual appearance of bright objects. &lsquo; darken &rsquo; Linearly reduces content brightness to preserves saturated details, followed by clipping the remaining out-of-gamut colors. &lsquo; warn &rsquo; Highlight out-of-gamut pixels (by inverting/marking them). &lsquo; linear &rsquo; Linearly reduces chromaticity of the entire image to make it fit within the target color volume. Be careful when using this on BT.2020 sources without proper mastering metadata, as doing so will lead to excessive desaturation. tonemapping Tone-mapping algorithm to use. Available values are: &lsquo; auto &rsquo; Automatic selection based on internal heuristics. This is the default. &lsquo; clip &rsquo; Performs no tone-mapping, just clips out-of-range colors. Retains perfect color accuracy for in-range colors but completely destroys out-of-range information. Does not perform any black point adaptation. Not configurable. &lsquo; st2094-40 &rsquo; EETF from SMPTE ST 2094-40 Annex B, which applies the Bezier curves from HDR10+ dynamic metadata based on Bezier curves to perform tone-mapping. The OOTF used is adjusted based on the ratio between the targeted and actual display peak luminances. &lsquo; st2094-10 &rsquo; EETF from SMPTE ST 2094-10 Annex B.2, which takes into account the input signal average luminance in addition to the maximum/minimum. Note that this does not currently include the subjective gain/offset/gamma controls defined in Annex B.3. &lsquo; bt.2390 &rsquo; EETF from the ITU-R Report BT.2390, a hermite spline roll-off with linear segment. The knee point offset is configurable using tonemapping_knee_offset . Note that this parameter defaults to 1.0 , rather than the value of 0.5 from the ITU-R spec. &lsquo; bt.2446a &rsquo; EETF from ITU-R Report BT.2446, method A. Designed for well-mastered HDR sources. Can be used for both forward and inverse tone mapping. Not configurable. &lsquo; spline &rsquo; Simple spline consisting of two polynomials, joined by a single pivot point. The knee point is determined from the source scene average brightness, falling back to tonemapping_knee_default (defaulting to 0.4 ). Can be used for both forward and inverse tone mapping. &lsquo; reinhard &rsquo; Simple non-linear, global tone mapping algorithm. The tonemapping_reinhard_contrast option specifies the local contrast coefficient at the display peak. Essentially, a value of 0.5 implies that the reference white will be about half as bright as when clipping. Defaults to 0.5 , which results in the simplest formulation of this function. &lsquo; mobius &rsquo; Generalization of the reinhard tone mapping algorithm to support an additional linear slope near black. The tonemapping_linear_knee option indicates the trade-off between the linear section and the non-linear section. Essentially, for a given parameter x , every color value below x will be mapped linearly, while higher values get non-linearly tone-mapped. Values near 1.0 make this curve behave like clip , while values near 0.0 make this curve behave like reinhard . The default value is 0.3 , which provides a good balance between colorimetric accuracy and preserving out-of-gamut details. &lsquo; hable &rsquo; Piece-wise, filmic tone-mapping algorithm developed by John Hable for use in Uncharted 2, inspired by a similar tone-mapping algorithm used by Kodak. Popularized by its use in video games with HDR rendering. Preserves both dark and bright details very well, but comes with the drawback of changing the average brightness quite significantly. This is sort of similar to reinhard with parameter 0.24 . &lsquo; gamma &rsquo; Fits a gamma (power) function to transfer between the source and target color spaces, effectively resulting in a perceptual hard-knee joining two roughly linear sections. This preserves details at all scales fairly accurately, but can result in an image with a muted or dull appearance. The tonemapping_linear_knee option is used as the cutoff point, defaulting to 0.3 . &lsquo; linear &rsquo; Linearly stretches the input range to the output range, in PQ space. This will preserve all details accurately, but results in a significantly different average brightness. Can be used for inverse tone-mapping in addition to regular tone-mapping. The tonemapping_exposure option can be used as an additional linear gain coefficient (defaulting to 1.0 ). tonemapping_param For tunable tone mapping functions, this parameter can be used to fine-tune the curve behavior. Refer to the documentation of tonemapping . The default value of 0.0 is replaced by the curve&rsquo;s preferred default setting, or by tonemapping_* options below as applicable. This option, if nonzero, takes effect over the corresponding values of the other tonemapping_* options. Deprecated, do not use. tonemapping_knee_adaptation Controls how strongly the knee point adapts to the source scene average brightness, relative to the target average in PQ space. A value of 1.0 fully adapts the source average to the target average, while 0.0 disables adaptation. Defaults to 0.4 . Affects st2094-40 , st2094-10 and spline . tonemapping_knee_minimum Sets the minimum knee point as a fraction of the PQ luminance range. Limits how low the automatically determined knee point can be. Defaults to 0.1 . tonemapping_knee_maximum Sets the maximum knee point as a fraction of the PQ luminance range. Limits how high the automatically determined knee point can be. Defaults to 0.8 . tonemapping_knee_default Sets the fallback knee point used when source scene average brightness metadata is unavailable. Normally, the knee point is determined from the source scene average instead. The value should be between tonemapping_knee_minimum and tonemapping_knee_maximum . Defaults to 0.4 . tonemapping_knee_offset Sets the knee point offset for bt.2390 . The ITU-R specification defines 0.5 as the default, but libplacebo uses 1.0 . Defaults to 1.0 . tonemapping_slope_tuning Controls how the slope of the spline curve is adjusted based on the difference between source and target peaks. The tuning aims to preserve a slope closer to 1.0 for small differences and approach linear mapping for larger differences. Defaults to 1.5 . tonemapping_slope_offset Controls the slope adjustment of the spline curve, together with tonemapping_slope_tuning .
