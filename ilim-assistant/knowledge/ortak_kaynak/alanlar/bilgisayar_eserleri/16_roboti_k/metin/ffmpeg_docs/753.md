Each frame gets its own palette, built only from the lattice colors actually used by that frame. If a frame uses more than 256 lattice colors, they are reduced by iteratively dropping the color whose removal has the least impact (its pixel count times the squared distance to the nearest remaining color) and mapping its pixels to that nearest remaining color. The alpha channel, if present, is ignored unless the alpha option is set. The filter accepts the following options: density Set the lattice density as the number of lattice steps spanning one color axis (0 to 255). Higher values give a finer lattice and thus more possible colors, making it more likely that the per-frame color reduction has to drop some of them. At a density of 7 with 256 palette entries no reduction ever happens since the whole lattice then holds exactly 256 points. Allowed range is 1 to 255 . Default is 20 . max_colors Set the maximum number of palette entries to use. Frames using more lattice colors than this are reduced accordingly. Allowed range is 2 to 256 . Default is 256 . alpha Quantize the alpha channel too, placing the palette colors on a 4 dimensional D4 lattice over RGBA instead of the FCC lattice over RGB. Inputs without an alpha channel are treated as opaque. With this option the density is limited to 64 . Default is 0 (alpha is ignored and the palette is fully opaque). refine Redistribute the error introduced by dropping colors, which is otherwise uncompensated and can show as discolored patches. Frames that needed no reduction are not changed by this option. &lsquo; none &rsquo; No refinement. &lsquo; full &rsquo; Run a Floyd-Steinberg error diffusion pass over the whole frame against the final palette. Most accurate on average, but re-dithers everything, including regions whose colors survived. &lsquo; residual &rsquo; Diffuse only the residual between each pixel&rsquo;s first pass quantized color and its final palette color. Pixels of surviving colors that receive no residual are unchanged, keeping the character of the selected dither mode outside the reduced regions. &lsquo; batched &rsquo; Interleave color removal and rediffusion: drop half of the excess colors, rediffuse the whole frame against the survivors, recount the colors from the actual assignments and repeat. Colors that the dithering can reproduce by mixing become free to drop while extreme colors keep their pixels and are protected; this gives the best quality at the cost of about log2 of the number of dropped colors rediffusion passes. Default is none . dither Select the dithering mode. Available algorithms are: &lsquo; none &rsquo; No dithering. &lsquo; bayer &rsquo; Ordered 8x8 dithering using the classic swscale dither matrix with its per-channel decorrelation, offsets spanning one lattice period. &lsquo; blue_noise &rsquo; Void-and-cluster blue noise dithering using three 64x64 masks generated at initialization, one per color channel. &lsquo; floyd_steinberg &rsquo; Floyd-Steinberg error diffusion. Default is floyd_steinberg . 32.145 lenscorrection # TOC Correct radial lens distortion This filter can be used to correct for radial distortion as can result from the use of wide angle lenses, and thereby re-rectify the image. To find the right parameters one can use tools available for example as part of opencv or simply trial-and-error. To use opencv use the calibration sample (under samples/cpp) from the opencv sources and extract the k1 and k2 coefficients from the resulting matrix. Note that effectively the same filter is available in the open-source tools Krita and Digikam from the KDE project. In contrast to the vignette filter, which can also be used to compensate lens errors, this filter corrects the distortion of the image, whereas vignette corrects the brightness distribution, so you may want to use both filters together in certain cases, though you will have to take care of ordering, i.e. whether vignetting should be applied before or after lens correction. 32.145.1 Options # TOC The filter accepts the following options: cx Relative x-coordinate of the focal point of the image, and thereby the center of the distortion. This value has a range [0,1] and is expressed as fractions of the image width. Default is 0.5. cy Relative y-coordinate of the focal point of the image, and thereby the center of the distortion. This value has a range [0,1] and is expressed as fractions of the image height. Default is 0.5. k1 Coefficient of the quadratic correction term. This value has a range [-1,1]. 0 means no correction. Default is 0. k2 Coefficient of the double quadratic correction term. This value has a range [-1,1]. 0 means no correction. Default is 0. i Set interpolation type. Can be nearest or bilinear . Default is nearest . fc Specify the color of the unmapped pixels. For the syntax of this option, check the &quot;Color&quot; section in the ffmpeg-utils manual . Default color is black@0 . The formula that generates the correction is: r_src = r_tgt * (1 + k1 * ( r_tgt / r_0 )^2 + k2 * ( r_tgt / r_0 )^4) where r_0 is halve of the image diagonal and r_src and r_tgt are the distances from the focal point in the source and target images, respectively. 32.145.2 Commands # TOC This filter supports the all above options as commands . 32.146 lensfun # TOC Apply lens correction via the lensfun library ( http://lensfun.sourceforge.net/ ).
