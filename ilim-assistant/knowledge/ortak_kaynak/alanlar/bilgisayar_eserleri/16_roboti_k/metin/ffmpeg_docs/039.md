Building them requires the @code{ffnvcodec} headers provided by @url{https://code.ffmpeg.org/FFmpeg/nv-codec-headers, nv-codec-headers}. They are autodetected by configure; they can also be enabled explicitly with @option{--enable-ffnvcodec} and @option{--enable-nvenc}. Available options and values depend on the SDK version exposed by the headers at build time. Feature checks in @file{libavcodec/nvenc.h} distinguish SDK versions 12.0, 12.1, 12.2, 13.0 and 13.1. Runtime support also depends on the GPU and driver. Use @command{ffmpeg -h encoder=hevc_nvenc}, or substitute @code{h264_nvenc} or @code{av1_nvenc}, to list the options, devices and pixel formats available in a particular build. @subsection Hardware input and devices These encoders accept system-memory frames and CUDA hardware frames (@code{AV_PIX_FMT_CUDA}). Builds using SDK 13.1 or newer also accept CUDA array frames (@code{AV_PIX_FMT_CUARRAY}). Builds with @code{d3d11va} support accept D3D11 hardware frames (@code{AV_PIX_FMT_D3D11}). The input pixel format and encoding features must be supported by the selected GPU. For CUDA decoding followed by encoding, use the input options @option{-hwaccel cuda -hwaccel_output_format cuda} to keep decoded frames on the device. A hardware device can also be created with @option{-init_hw_device} and supplied to the encoder, directly or through its hardware frames context. For system-memory input without a supplied hardware device, the encoder option @option{gpu} selects the device. See its entry under @ref{nvenc_other_options,,Other common options} below. @subsection Generic options Several generic encoding options are mapped to NVENC settings. The bitrate options @option{b}, @option{maxrate} and @option{bufsize} set the average bitrate, the maximum bitrate and the VBV buffer size; the NVENC default for @option{b} is @samp{2M}. @option{g} sets the GOP length, with 0 requesting intra-only encoding. @option{bf} sets the number of B-frames between non-B-frames. @option{refs} sets the number of reference frames in each reference list. @option{g} and @option{bf} default to @code{-1} and @option{refs} defaults to 0; these defaults leave the values of the preset unchanged. The generic @option{qmin} and @option{qmax} options are honoured in VBR mode with a warning; API users should set the encoder options of the same names listed below instead. Only applications calling the libavcodec API can change @code{AVCodecContext.bit_rate}, @code{AVCodecContext.rc_max_rate} and @code{AVCodecContext.rc_buffer_size} during encoding. The encoder checks these fields before encoding each frame. When dynamic bitrate changes are supported and rate control is not @samp{constqp}, changed positive values trigger reconfiguration, reset the encoder and force an IDR. A change to the display aspect ratio also triggers reconfiguration. @subsection Common options The following option names are shared by all three encoders.
