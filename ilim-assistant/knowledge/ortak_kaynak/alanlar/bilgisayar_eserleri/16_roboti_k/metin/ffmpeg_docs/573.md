The required syntax for a TCP url is: tcp:// hostname : port [? options ] options contains a list of &amp;-separated options of the form key = val . Standard percent-encoding (and using the plus sign for space) can be used to escape keys and values. Options can also can be specified via command line options (or in code via AVOption s). The list of supported options follows. listen= 2|1|0 Listen for an incoming connection. 0 disables listen, 1 enables listen in single client mode, 2 enables listen in multi-client mode. Default value is 0. local_addr= addr Local IP address of a network interface used for tcp socket connect. local_port= port Local port used for tcp socket connect. timeout= microseconds Set raise error timeout, expressed in microseconds. This option is only relevant in read mode: if no data arrived in more than this time interval, raise error. listen_timeout= milliseconds Set listen timeout, expressed in milliseconds. recv_buffer_size= bytes Set receive buffer size, expressed bytes. send_buffer_size= bytes Set send buffer size, expressed bytes. tcp_nodelay= 1|0 Set TCP_NODELAY to disable Nagle&rsquo;s algorithm. Default value is 0. Remark: Writing to the socket is currently not optimized to minimize system calls and reduces the efficiency / effect of TCP_NODELAY. tcp_mss= bytes Set maximum segment size for outgoing TCP packets, expressed in bytes. The following example shows how to setup a listening TCP connection with ffmpeg , which is then accessed with ffplay : ffmpeg -i input -f format tcp:// hostname : port ?listen ffplay tcp:// hostname : port 16.44 tls # TOC Transport Layer Security (TLS) / Secure Sockets Layer (SSL) The required syntax for a TLS/SSL url is: tls:// hostname : port [? options ] options contains a list of &amp;-separated options of the form key = val . Standard percent-encoding (and using the plus sign for space) can be used to escape keys and values. Options can also can be specified via command line options (or in code via AVOption s). The TLS backend is selected at build time. The available backends are GnuTLS, OpenSSL, mbedTLS, libtls, SChannel (Windows) and Secure Transport (Apple platforms). Only one backend can be linked into a build. On Apple platforms, configure autodetects Secure Transport when no other TLS library is enabled. Apple has deprecated Secure Transport in favor of Network.framework and it does not support TLS 1.3, so such a build cannot connect to servers that require TLS 1.3. configure therefore emits a warning when it selects Secure Transport automatically; building with --enable-gnutls or --enable-openssl is recommended instead. Passing --enable-securetransport explicitly marks the backend as requested and suppresses the warning. This is also needed with --fatal-warnings , since any warning makes configure fail. The list of supported options follows. ca_file, cafile= filename A file containing certificate authority (CA) root certificates to treat as trusted. If the linked TLS library contains a default this might not need to be specified for verification to work, but not all libraries and setups have defaults built in. The file must be in OpenSSL PEM format. When no file is given, Windows builds using OpenSSL 3.2 or later with Windows certificate store support also use certificates from the system ROOT store. OpenSSL applies its usual certificate checks. Additional trust restrictions stored as Windows certificate properties, rather than encoded in the certificates themselves, are not enforced by its Windows certificate store loader. tls_verify, verify= 1|0 If enabled, try to verify the peer that we are communicating with. Note, if using OpenSSL, this currently only makes sure that the peer certificate is signed by one of the root certificates in the CA database, but it does not validate that the certificate actually matches the host name we are trying to connect to. (With other backends, the host name is validated as well.) This is enabled by default. Verifying the peer requires a CA database, which in some cases has to be provided by the caller. cert_file, cert= filename A file containing a certificate to use in the handshake with the peer. (When operating as server, in listen mode, this is more often required by the peer, while client certificates only are mandated in certain setups.) key_file, key= filename A file containing the private key for the certificate. listen= 1|0 If enabled, listen for connections on the provided port, and assume the server role in the handshake instead of the client role. http_proxy The HTTP proxy to tunnel through, e.g. http://example.com:1234 . The proxy must support the CONNECT method. Example command lines: To create a TLS/SSL server that serves an input stream. ffmpeg -i input -f format tls:// hostname : port ?listen&amp;cert= server.crt &amp;key= server.key To play back a stream from the TLS/SSL server using ffplay : ffplay tls:// hostname : port 16.45 dtls # TOC Datagram Transport Layer Security (DTLS) DTLS requires one of the OpenSSL, GnuTLS, mbedTLS or SChannel backends; libtls and Secure Transport provide TLS only. The required syntax for a DTLS URL is: dtls:// hostname : port [? options ] options contains a list of &amp;-separated options of the form key = val . Standard percent-encoding (and using the plus sign for space) can be used to escape keys and values. Options can also can be specified via command line options (or in code via AVOption s). DTLS shares most options with TLS, but operates over UDP instead of TCP. The list of supported options follows. ca_file, cafile= filename A file containing certificate authority (CA) root certificates to treat as trusted. If the linked TLS library contains a default this might not need to be specified for verification to work, but not all libraries and setups have defaults built in. The file must be in OpenSSL PEM format. When no file is given, Windows builds using OpenSSL 3.2 or later with Windows certificate store support also use certificates from the system ROOT store. OpenSSL applies its usual certificate checks. Additional trust restrictions stored as Windows certificate properties, rather than encoded in the certificates themselves, are not enforced by its Windows certificate store loader. tls_verify, verify= 1|0 If enabled, try to verify the peer that we are communicating with. Note, if using OpenSSL, this currently only makes sure that the peer certificate is signed by one of the root certificates in the CA database, but it does not validate that the certificate actually matches the host name we are trying to connect to. This is enabled by default. Verifying the peer requires a CA database, which in some cases has to be provided by the caller. cert_file, cert= filename A file containing a certificate to use in the handshake with the peer. (When operating as server, in listen mode, this is more often required by the peer, while client certificates only are mandated in certain setups.) key_file, key= filename A file containing the private key for the certificate. cert_pem= string Certificate PEM string key_pem= string Private key PEM string listen= 1|0 If enabled, listen for connections on the provided port, and assume the server role in the handshake instead of the client role. mtu= size Set the Maximum Transmission Unit (MTU) for DTLS packets. use_srtp= 1|0 Enable the use_srtp DTLS extension. This is used in WebRTC applications to establish SRTP encryption keys through the DTLS handshake. Default is disabled. external_sock= 1|0 Use an external socket instead of creating a new one. This option only makes sense to pass when interacting with the code via API, enabling this from CLI will cause immediate failure. Default is disabled. Example command lines: To create a DTLS server: ffmpeg -listen 1 -i dtls:// hostname : port output To create a DTLS client and send data to server: ffmpeg -i input -f format dtls:// hostname : port
