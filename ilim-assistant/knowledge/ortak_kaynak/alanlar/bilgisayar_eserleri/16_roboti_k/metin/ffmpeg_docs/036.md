When float or half input is detected with an LDR profile, the profile is automatically promoted to HDR RGB with LDR alpha (@code{HDR_RGB_LDR_A}); an explicitly selected HDR profile is kept. The raw bitstream can be packaged in the @file{.astc} container (16-byte header + compressed blocks) or in the Khronos Texture 1.0 container (@file{.ktx}). This implementation writes LDR 2D textures only through the @file{.ktx} muxer: HDR ASTC and 3D block footprints are not supported by the muxer and @file{.astc} must be used for them instead. The KTX 1.0 linear ASTC GL enums do not imply LDR either, so a linear @file{.ktx} texture may still hold HDR endpoints; such a texture is decoded with HDR precision by default. This encoder requires the presence of the libx264 headers and library during configuration. You need to explicitly configure the build with @code{--enable-libx264}. libx264 supports an impressive number of features, including 8x8 and 4x4 adaptive spatial transform, adaptive B-frame placement, CAVLC/CABAC entropy coding, interlacing (MBAFF), lossless mode, psy optimizations for detail retention (adaptive quantization, psy-RD, psy-trellis). Many libx264 encoder options are mapped to FFmpeg global codec options, while unique encoder options are provided through private options. Additionally the @option{x264opts} and @option{x264-params} private options allows one to pass a list of key=value tuples as accepted by the libx264 @code{x264_param_parse} function. The x264 project website is at @url{http://www.videolan.org/developers/x264.html}.
