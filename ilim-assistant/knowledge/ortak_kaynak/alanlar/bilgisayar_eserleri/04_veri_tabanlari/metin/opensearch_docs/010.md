--- layout: default title: Installing and configuring Data Prepper parent: Getting started nav_order: 10 --- # Installing and configuring Data Prepper You can install OpenSearch Data Prepper using the Docker image or a Linux archive. To build Data Prepper from source, see the [Data Prepper Developer Guide](https://github.com/opensearch-project/data-prepper/blob/main/docs/developer_guide.md). ## Installing the Docker image To use Data Prepper in Docker, install [Docker](https://docs.docker.com/get-docker/) and pull the Data Prepper image: ```bash docker pull opensearchproject/data-prepper:latest ``` {% include copy.html %} The Data Prepper home directory in the image is `/usr/share/data-prepper`. To provide configuration files, mount them into this directory when you start the container. For more information, see [Running Data Prepper]({{site.url}}{{site.baseurl}}/data-prepper/getting-started/running/). ## Installing a Linux archive Download a Data Prepper archive for your platform from the [OpenSearch downloads page](https://opensearch.org/downloads/){:target='\_blank'}. Each release provides the following archives: - `opensearch-data-prepper-jdk- -linux- .tar.gz`: Includes a Java runtime. - `opensearch-data-prepper- -linux- .tar.gz`: Does not include a Java runtime. To use this archive, install Java on your host. Extract the archive, replacing ` ` and ` ` with the values in the file name: ```bash tar -xzf opensearch-data-prepper-jdk- -linux- .tar.gz ``` {% include copy.html %} The extracted directory is the Data Prepper home directory. ## Directory structure The Data Prepper home directory contains the following files and directories. | Path | Description | | :--- | :--- | | `bin/data-prepper` | The script that starts Data Prepper. | | `pipelines/` | The directory for pipeline configuration files. Data Prepper loads every YAML file in this directory. This directory contains no pipelines after installation. | | `config/data-prepper-config.yaml` | The Data Prepper server configuration file. | | `config/log4j2-rolling.properties` | The Log4j 2 logging configuration file. | | `lib/` | The Data Prepper libraries and plugins. | ## Server and logging configuration Data Prepper also reads the following optional configuration files from the `config` directory of the Data Prepper home directory. ### Server configuration The `config/data-prepper-config.yaml` file configures the Data Prepper server, which exposes the [core APIs]({{site.url}}{{site.baseurl}}/data-prepper/managing-data-prepper/core-apis/) on port `4900`. The Docker image and the Linux archives include different default server configurations. | Setting | Docker image | Linux archive | | :--- | :--- | :--- | | TLS | Enabled, using a self-signed certificate. Send requests using `https`. | Disabled. Send requests using `http`. | | Authentication | HTTP basic authentication using the username `admin` and the password `admin`. | None. | The default certificate and credentials in the Docker image are intended for testing only. Replace them before using Data Prepper in production. {: .warning} To change these settings, replace `config/data-prepper-config.yaml` with your own file. For example, the following file disables TLS for the core APIs: ```yaml ssl: false serverPort: 4900 ``` {% include copy.html %} For all server settings, see [Configuring OpenSearch Data Prepper]({{site.url}}{{site.baseurl}}/data-prepper/managing-data-prepper/configuring-data-prepper/). ### Logging configuration Data Prepper reads its logging configuration from `config/log4j2-rolling.properties`. To customize logging, either replace this file or set the `JAVA_OPTS` environment variable to point to a different file: ```bash export JAVA_OPTS="-Dlog4j.configurationFile=/path/to/log4j2.properties" ``` {% include copy.html %} For more information, see [Configuring Log4j]({{site.url}}{{site.baseurl}}/data-prepper/managing-data-prepper/configuring-log4j/). ## Next steps - [Configure a pipeline]({{site.url}}{{site.baseurl}}/data-prepper/getting-started/configuring-pipelines/) for Data Prepper to run.

--- layout: default title: Running Data Prepper parent: Getting started nav_order: 20 --- # Running Data Prepper OpenSearch Data Prepper requires at least one pipeline to start. If Data Prepper finds no pipeline configuration file, it logs the following error and exits: ```text ERROR org.opensearch.dataprepper.pipeline.parser.PipelineConfigurationFileReader - Pipelines configuration file not found at /usr/share/data-prepper/pipelines ``` On this page, you'll define a minimal pipeline, start Data Prepper, and send it a test event. If you haven't installed Data Prepper, see [Installing Data Prepper]({{site.url}}{{site.baseurl}}/data-prepper/getting-started/installing/). For more information about pipeline configuration, see [Configuring pipelines]({{site.url}}{{site.baseurl}}/data-prepper/getting-started/configuring-pipelines/). ## Step 1: Define a pipeline Create a file named `pipelines.yaml` containing the following pipeline configuration: ```yaml test-pipeline: source: http: ssl: false sink: - stdout: ``` {% include copy.html %} This pipeline, named `test-pipeline`, receives events using the [`http`]({{site.url}}{{site.baseurl}}/data-prepper/pipelines/configuration/sources/http/) source on port `2021` and prints each event to the Data Prepper log using the [`stdout`]({{site.url}}{{site.baseurl}}/data-prepper/pipelines/configuration/sinks/stdout/) sink. The pipeline contains no processors, so events are not modified. ## Step 2: Start Data Prepper Start Data Prepper using the Docker image or a Linux archive. ### Docker From the directory containing `pipelines.yaml`, run the following command: ```bash docker run --name data-prepper \ -p 2021:2021 -p 4900:4900 \ -v ${PWD}/pipelines.yaml:/usr/share/data-prepper/pipelines/pipelines.yaml \ opensearchproject/data-prepper:latest ``` {% include copy.html %} The `-v` option mounts `pipelines.yaml` into the `pipelines` directory of the container. `${PWD}` is your current directory, so `${PWD}/pipelines.yaml` is the absolute path to the file, which Docker requires for mounts. The `-p` options publish port `2021` for the `http` source and port `4900` for the [core APIs]({{site.url}}{{site.baseurl}}/data-prepper/managing-data-prepper/core-apis/). To use your own server configuration file, mount it as `/usr/share/data-prepper/config/data-prepper-config.yaml`: ```bash docker run --name data-prepper \ -p 2021:2021 -p 4900:4900 \ -v ${PWD}/pipelines.yaml:/usr/share/data-prepper/pipelines/pipelines.yaml \ -v ${PWD}/data-prepper-config.yaml:/usr/share/data-prepper/config/data-prepper-config.yaml \ opensearchproject/data-prepper:latest ``` {% include copy.html %} ### Linux archive Copy `pipelines.yaml` into the `pipelines` directory of the Data Prepper home directory. Then run the following command from the home directory: ```bash bin/data-prepper ``` {% include copy.html %} Alternatively, provide the pipeline configuration file and the server configuration file as arguments, in that order: ```bash bin/data-prepper /path/to/pipelines.yaml /path/to/data-prepper-config.yaml ``` {% include copy.html %} ## Step 3: Send a test event When the pipeline is ready, the Data Prepper log contains the following line: ```text INFO org.opensearch.dataprepper.plugins.source.loghttp.HTTPSource - Started http source on port 2021... ``` In a new terminal window, send an event to the `http` source. The source accepts a JSON array in which each object becomes one event: ```bash curl -X POST http://localhost:2021/log/ingest \ -H "Content-Type: application/json" \ -d '[{"message": "Hello, Data Prepper!"}]' ``` {% include copy.html %} Data Prepper responds with `200 OK`, and the `stdout` sink prints the event to the Data Prepper log: ```json {"message":"Hello, Data Prepper!"} ``` ## Step 4: List the running pipelines To list the running pipelines, send a request to the core APIs. The request depends on the [default server configuration]({{site.url}}{{site.baseurl}}/data-prepper/getting-started/installing/#server-configuration) of your installation. For the Docker image, use `https` and the default credentials. The `-k` option skips certificate verification because the image uses a self-signed certificate: ```bash curl -k -u admin:admin https://localhost:4900/list ``` {% include copy.html %} For a Linux archive, use `http`: ```bash curl http://localhost:4900/list ``` {% include copy.html %} The response contains the pipeline that you defined: ```json {"pipelines":[{"name":"test-pipeline"}]} ``` ## Step 5: Stop Data Prepper To stop Data Prepper, press `Ctrl+C` in the terminal in which Data Prepper is running. If you started the Docker container in the background, run `docker stop data-prepper`. Alternatively, send a shutdown request to the core APIs. For the Docker image, send the following request: ```bash curl -k -u admin:admin -X POST https://localhost:4900/shutdown ``` {% include copy.html %} For a Linux archive, send the following request: ```bash curl -X POST http://localhost:4900/shutdown ``` {% include copy.html %} To remove the stopped Docker container so that you can reuse the `data-prepper` container name, run `docker rm data-prepper`. ## Running pipelines that read and write files The file-based examples in [Configuring pipelines]({{site.url}}{{site.baseurl}}/data-prepper/getting-started/configuring-pipelines/) read from and write to the `/usr/share/data-prepper/data` directory. To run these examples, create a `data` directory containing an `input.txt` file. In Docker, mount the `data` directory into the container along with the pipeline file: ```bash docker run --name data-prepper \ -v ${PWD}/pipelines.yaml:/usr/share/data-prepper/pipelines/pipelines.yaml \ -v ${PWD}/data:/usr/share/data-prepper/data \ opensearchproject/data-prepper:latest ```
