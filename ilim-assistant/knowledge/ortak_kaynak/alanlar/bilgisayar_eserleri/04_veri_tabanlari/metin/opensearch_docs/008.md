Data Prepper runs separately from OpenSearch and is not included in the OpenSearch installation packages. ## Pipelines and events Data Prepper runs _pipelines_. Each pipeline reads data from a _source_, transforms or drops events using one or more _processors_, and writes the result to one or more _sinks_. Between the source and the processors, events wait in a _buffer_. For example, a pipeline can receive log lines over HTTP, parse each line into fields, and write the result to an OpenSearch index. A single Data Prepper instance can run multiple pipelines. An _event_ is a single data item, such as a log line, that moves through a pipeline. Each event consists of key-value pairs called _fields_, similar to a JSON object. When a pipeline writes to OpenSearch, each event becomes a document. Other sinks, such as Amazon S3, serialize events into files. Processors read and modify the fields of each event before the event reaches a sink. ## Configuration files Data Prepper uses the following configuration files. | File | Required | Description | | :--- | :--- | :--- | | Pipeline configuration | Yes | One or more YAML files that define the pipelines to run, including their sources, processors, and sinks. Data Prepper does not provide a default pipeline and does not start if no pipeline configuration file exists. For more information, see [Configuring pipelines]({{site.url}}{{site.baseurl}}/data-prepper/getting-started/configuring-pipelines/). | | `data-prepper-config.yaml` | No | Settings for the Data Prepper server, such as the port, TLS, and authentication for the [core APIs]({{site.url}}{{site.baseurl}}/data-prepper/managing-data-prepper/core-apis/). --- layout: default title: Ingesting log data into OpenSearch parent: Getting started nav_order: 30 --- # Ingesting log data into OpenSearch In this tutorial, you'll run Data Prepper and OpenSearch in Docker, send raw Apache access logs to Data Prepper, and search the parsed log data in OpenSearch. The pipeline that you create performs the following tasks: 1. Receives log lines over HTTP. 1. Parses each log line into separate fields, such as the client IP address, request path, and response code. 1. Converts the log timestamp into a date and the response code and size into integers. 1. Writes each event to an OpenSearch index and prints it to the Data Prepper log. The pipeline parses log lines in the Apache common log format, such as the following: ```text 10.0.0.7 - - [19/Oct/2026:10:16:03 +0000] "GET /checkout HTTP/1.1" 500 98 ``` Each line contains the client IP address, two identity fields (`-` when empty), the timestamp, the request (method, path, and HTTP version), the response code, and the response size in bytes. Docker Compose downloads the Data Prepper and OpenSearch images when you start the containers, so you don't need to install Data Prepper first. ## Prerequisites Install [Docker](https://docs.docker.com/get-docker/), including [Docker Compose](https://docs.docker.com/compose/). The containers use ports `9200` (OpenSearch) and `2021` (Data Prepper), so make sure that these ports are not in use. If you're using Linux, increase the maximum number of memory maps available to OpenSearch. For more information, see [Important settings]({{site.url}}{{site.baseurl}}/install-and-configure/install-opensearch/index/#important-settings). ## Step 1: Define a pipeline Create a directory for this tutorial (for example, `data-prepper-tutorial`). In this directory, create a file named `pipelines.yaml` containing the following pipeline configuration. Replace ` ` with a password that meets the [admin password requirements]({{site.url}}{{site.baseurl}}/security/configuration/demo-configuration/#admin-password-requirements). You'll also use this password for OpenSearch in the next step: ```yaml log-pipeline: source: http: ssl: false processor: - grok: match: message: ['%{COMMONAPACHELOG}'] - date: match: - key: timestamp patterns: ["dd/MMM/yyyy:HH:mm:ss Z"] destination: "@timestamp" - convert_type: keys: ["response", "bytes"] type: integer sink: - opensearch: hosts: ["https://opensearch:9200"] insecure: true username: admin password: " " index: web-logs flush_timeout: -1 - stdout: ``` {% include copy.html %} This file defines one pipeline named `log-pipeline` containing the following components: - `source`: The [`http`]({{site.url}}{{site.baseurl}}/data-prepper/pipelines/configuration/sources/http/) source receives events on port `2021` at the `/log/ingest` path. The `ssl: false` setting accepts plain HTTP requests, which is suitable only for local testing. - `processor`: Data Prepper runs the processors in the order in which they are listed: - The [`grok`]({{site.url}}{{site.baseurl}}/data-prepper/pipelines/configuration/processors/grok/) processor matches the `message` field against the built-in `COMMONAPACHELOG` pattern and adds a field for each part of the log line, such as `clientip`, `verb`, `request`, `response`, `bytes`, and `timestamp`. - The [`date`]({{site.url}}{{site.baseurl}}/data-prepper/pipelines/configuration/processors/date/) processor parses the `timestamp` field and writes the result to the `@timestamp` field in ISO 8601 format so that OpenSearch maps it as a date. - The [`convert_type`]({{site.url}}{{site.baseurl}}/data-prepper/pipelines/configuration/processors/convert-entry-type/) processor converts the `response` and `bytes` fields from strings to integers so that you can run range queries on them. - `sink`: Each event is sent to both sinks: - The [`opensearch`]({{site.url}}{{site.baseurl}}/data-prepper/pipelines/configuration/sinks/opensearch/) sink writes events to the `web-logs` index. The `opensearch` hostname refers to the OpenSearch container that you'll define in the next step. The `insecure: true` setting skips certificate verification because the OpenSearch container uses demo certificates. By default, the sink waits up to 60 seconds to batch events before writing them to OpenSearch. Setting `flush_timeout` to `-1` writes events as soon as they are processed so that you can see the results immediately. - The [`stdout`]({{site.url}}{{site.baseurl}}/data-prepper/pipelines/configuration/sinks/stdout/) sink prints each processed event to the Data Prepper log so that you can inspect it. ## Step 2: Create the Docker Compose file In the same directory, create a file named `.env` containing the following line. Replace ` ` with the password that you used in `pipelines.yaml`: ```bash OPENSEARCH_INITIAL_ADMIN_PASSWORD= ``` {% include copy.html %} Docker Compose reads the `.env` file automatically and passes the password to OpenSearch. If the password does not meet the requirements, OpenSearch does not start. Create a file named `docker-compose.yml` containing the following configuration: ```yaml services: opensearch: image: opensearchproject/opensearch:latest container_name: opensearch environment: - discovery.type=single-node - OPENSEARCH_INITIAL_ADMIN_PASSWORD=${OPENSEARCH_INITIAL_ADMIN_PASSWORD} ports: - 9200:9200 data-prepper: image: opensearchproject/data-prepper:latest container_name: data-prepper volumes: - ./pipelines.yaml:/usr/share/data-prepper/pipelines/pipelines.yaml ports: - 2021:2021 depends_on: - opensearch ``` {% include copy.html %} This file defines two containers: - `opensearch`: A single-node OpenSearch cluster with security enabled, available at `https://localhost:9200`. - `data-prepper`: A Data Prepper instance. Data Prepper loads every pipeline configuration file in the `/usr/share/data-prepper/pipelines/` directory, so the `volumes` setting mounts your `pipelines.yaml` file into that directory. Port `2021` is published so that you can send data to the `http` source from your machine. Your directory now contains the following files: ```text data-prepper-tutorial/ ├── .env ├── docker-compose.yml └── pipelines.yaml ``` ## Step 3: Start the containers From the `data-prepper-tutorial` directory, start the containers in the background: ```bash docker compose up -d ``` {% include copy.html %} Follow the Data Prep
