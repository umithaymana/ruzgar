--- layout: default title: Kinesis source parent: Pull-based ingestion nav_order: 20 --- # Kinesis source for pull-based ingestion **Introduced 3.0** {: .label .label-purple } This is an experimental feature and is not recommended for use in a production environment. For updates on the progress of the feature or if you want to leave feedback, join the discussion on the [OpenSearch forum](https://forum.opensearch.org/). {: .warning} The `kinesis` source lets an index consume records from an Amazon Kinesis data stream. Each OpenSearch shard reads from one Kinesis shard. For more information, see [Stream partitioning]({{site.url}}{{site.baseurl}}/im-plugin/pull-based-ingestion/index/#stream-partitioning). ## Prerequisites Before you create an index that uses the Kinesis source, install the `ingestion-kinesis` plugin on every node using `bin/opensearch-plugin install ingestion-kinesis`. ## Creating an index The following request creates an index that pulls data from a Kinesis stream in the segment replication mode. For other available modes, see [Ingestion modes]({{site.url}}{{site.baseurl}}/im-plugin/pull-based-ingestion/index/#ingestion-modes): ```json PUT /my-index { "settings": { "ingestion_source": { "type": "kinesis", "pointer.init.reset": "earliest", "param": { "stream": "test", "region": "us-east-1", "access_key": " ", "secret_key": " " } }, "index.number_of_shards": 1, "index.number_of_replicas": 1, "index": { "replication.type": "SEGMENT" } }, "mappings": { "properties": { "name": { "type": "text" }, "age": { "type": "integer" } } } } ``` {% include copy-curl.html %} For all `ingestion_source` settings, see [Ingestion source settings]({{site.url}}{{site.baseurl}}/im-plugin/pull-based-ingestion/index/#ingestion-source-settings). ## Source parameters The following table lists the source parameters. Specify them in the `param` object of `ingestion_source`. | Parameter | Required | Description | | :--- | :--- | :--- | | `stream` | Yes | The Kinesis stream name. | | `region` | Yes | The AWS Region. | | `access_key` | Yes | The AWS access key. | | `secret_key` | Yes | The AWS secret key. | | `endpoint_override` | No | A custom endpoint for the Kinesis service. | When you reset a Kinesis consumer by offset, provide a Kinesis sequence number as the offset. For more information, see [Resume Ingestion API]({{site.url}}{{site.baseurl}}/api-reference/index-apis/resume-ingestion/). ## Related documentation * [Pull-based ingestion]({{site.url}}{{site.baseurl}}/im-plugin/pull-based-ingestion/index/) * [Pull-based ingestion management APIs]({{site.url}}{{site.baseurl}}/api-reference/index-apis/pull-based-ingestion-management/)

--- layout: default title: Object store source parent: Pull-based ingestion has_children: false nav_order: 30 redirect_from: - /api-reference/document-apis/pull-based-ingestion-object-store/ --- # Object store source for pull-based ingestion **Introduced 3.10** {: .label .label-purple } This is an experimental feature and is not recommended for use in a production environment. For updates on the progress of the feature or if you want to leave feedback, join the discussion on the [OpenSearch forum](https://forum.opensearch.org/). {: .warning} The `object_store` source lets an index pull newline-delimited JSON (NDJSON) files directly from object storage, such as Amazon Simple Storage Service (Amazon S3), Google Cloud Storage, Azure Blob Storage, or a shared file system. Each shard reads its own portion of the files, so you don't need a separate streaming system or loading tool for a one-time load. The source reads objects through a registered [snapshot repository]({{site.url}}{{site.baseurl}}/tuning-your-cluster/availability-and-recovery/snapshots/snapshot-restore/), so the bucket, endpoint, and credentials are stored in the repository configuration and never appear in index settings. ## Prerequisites Before you create an index that uses the object store source, ensure that the following prerequisites are met: * Install the `ingestion-object-store` plugin on every node using `bin/opensearch-plugin install ingestion-object-store`. * Register a repository of type `s3`, `gcs`, `azure`, or `fs` and set `readonly` to `true`. The source rejects repositories that are not read-only, so it cannot modify or delete objects in your storage. * Place the files in the repository before you create the index. The files must not change during ingestion. The following request registers a read-only S3 repository: ```json PUT /_snapshot/ingest-repo { "type": "s3", "settings": { "bucket": "my-bucket", "base_path": "exports", "readonly": true } } ``` {% include copy-curl.html %} ## Creating an index The following request creates an index that reads five NDJSON files, assigning each file to one of three shards: ```json PUT /events { "settings": { "index.number_of_shards": 3, "index.number_of_replicas": 0, "index.replication.type": "SEGMENT", "index.ingestion_source.type": "object_store", "index.ingestion_source.pointer.init.reset": "earliest", "index.ingestion_source.mapper_type": "raw_payload", "index.ingestion_source.param.repository": "ingest-repo", "index.ingestion_source.param.shard_split": "whole_files", "index.ingestion_source.param.source_prefix": "events/part-", "index.ingestion_source.param.manifest": "[{\"key\":\"events/part-0001.ndjson\",\"size\":76},{\"key\":\"events/part-0002.ndjson\",\"size\":50},{\"key\":\"events/part-0003.ndjson\",\"size\":52},{\"key\":\"events/part-0004.ndjson\",\"size\":26},{\"key\":\"events/part-0005.ndjson\",\"size\":50}]" }, "mappings": { "properties": { "name": { "type": "keyword" }, "age": { "type": "integer" } } } } ``` {% include copy-curl.html %} The object store source requires the following `ingestion_source` settings to have non-default values: * The `pointer.init.reset` setting must be `earliest` or `none`. The default value, `latest`, starts reading at the end of the data, so the source rejects it. The source also rejects `reset_by_timestamp` and accepts `reset_by_offset` only for single-shard indexes. For more information, see [Stream position]({{site.url}}{{site.baseurl}}/im-plugin/pull-based-ingestion/index/#stream-position). * The `mapper_type` setting must be `raw_payload`. Each line of a file is indexed as one document, using the line as the document body. For more information, see [Message format]({{site.url}}{{site.baseurl}}/im-plugin/pull-based-ingestion/index/#message-format). ## Source parameters The following table lists the source parameters. Specify each parameter as `index.ingestion_source.param. `. | Parameter | Required | Default | Description | | :--- | :--- | :--- | :--- | | `repository` | Yes | | The name of a registered read-only `s3`, `gcs`, `azure`, or `fs` repository. If the repository is not registered, the shard retries every 10 seconds, so you can register the repository after creating the index. | | `source_url` | Conditional | | The key of a single object, relative to the repository base path. Either `source_url` or `source_prefix` is required. Required when `shard_split` is `equal_bytes`. | | `source_prefix` | Conditional | | The key prefix of the objects to read, relative to the repository base path. Either `source_url` or `source_prefix` is required. Required when `shard_split` is `whole_files` or `shard_prefixes`. | | `shard_split` | Yes | | The method used to divide objects among shards. Valid values are `whole_files`, `shard_prefixes`, and `equal_bytes`. For more information, see [Dividing objects among shards](#dividing-objects-among-shards). | | `discovery` | No | `manifest` | The method that shards use to find objects. Valid values are `manifest` and `list`. For more information, see [Finding objects](#finding-objects). | | `manifest` | Conditional | | The list of objects and their exact sizes in bytes, provided as a JSON array in a string: `[{"key":" ","size": }, ...]`. Required when `discovery` is `manifest`. Maximum size is 1 MB. | | `format` | No | `ndjson` | The file format. Only `ndjson` is supported. | | `max_record_bytes` | No | `10485760` (10 MB) | The maximum record size, in bytes. A line that exceeds this size pauses the shard. | | `max_objects` | No | `1000000` | The maximum number of objects that a manifest can list or that a shard can discover. | | `max_list_requests` | No | Unlimited | The maximum number of list requests that a shard can send to the object store. | | `max_get_requests` | No | Unlimited | The maximum number of read requests that a shard can send to the object store. | | `max_bytes` | No | Unlimited | The maximum number of bytes that a shard can read from the object store. | All keys are relative to the repository base path. A key cannot start with `/`; contain `//`, `*`, or `?`; or contain a `.` or `..` path segment. Object storage providers can charge per request and per byte transferred. If `max_list_requests`, `max_get_requests`, or `max_bytes` is unlimited, OpenSearch logs a warning. Limits are counted per shard and reset when the shard restarts or relocates. {: .note} ## Finding objects The `discovery` parameter determines how each shard finds the objects to read. It supports the `manifest` and `list` methods. ### Manifest When `discovery` is `manifest` (the default), you list every object and its exact size in the `manifest` parameter. Every shard reads the same list, so the source sends no list requests to the object store. Each key must start with the `source_prefix` value. Because the manifest is stored in the cluster state, it is limited to 1 MB. For larger sets of objects, use the `list` method. Objects added to the object store after the index is created are not read.
