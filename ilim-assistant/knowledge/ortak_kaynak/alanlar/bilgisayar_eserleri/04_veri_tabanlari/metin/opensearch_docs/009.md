These warnings are expected. Data Prepper retries until OpenSearch is available, which usually takes less than a minute. When the pipeline is ready, the log contains the following lines: ```text data-prepper | ... INFO org.opensearch.dataprepper.plugins.source.loghttp.HTTPSource - Started http source on port 2021... data-prepper | ... INFO org.opensearch.dataprepper.plugins.sink.opensearch.OpenSearchSink - Initialized OpenSearch sink ``` Leave the log running and open a new terminal window for the next step. ## Step 4: Send log data to Data Prepper The `http` source accepts a JSON array in which each object becomes one event. Send three Apache access log lines, each in the `message` field: ```bash curl -X POST http://localhost:2021/log/ingest \ -H "Content-Type: application/json" \ -d '[ {"message": "192.168.1.10 - - [19/Oct/2026:10:15:32 +0000] \"GET /products/123 HTTP/1.1\" 200 5120"}, {"message": "192.168.1.25 - - [19/Oct/2026:10:15:47 +0000] \"POST /cart HTTP/1.1\" 201 342"}, {"message": "10.0.0.7 - - [19/Oct/2026:10:16:03 +0000] \"GET /checkout HTTP/1.1\" 500 98"} ]' ``` {% include copy.html %} Data Prepper responds with `200 OK`. ## Step 5: View the processed events Return to the terminal containing the Data Prepper log. The `stdout` sink prints each processed event on a single line. For example, the following event, formatted for readability, was created from the third log line: ```json { "message": "10.0.0.7 - - [19/Oct/2026:10:16:03 +0000] \"GET /checkout HTTP/1.1\" 500 98", "request": "/checkout", "auth": "-", "ident": "-", "response": 500, "bytes": 98, "clientip": "10.0.0.7", "verb": "GET", "httpversion": "1.1", "timestamp": "19/Oct/2026:10:16:03 +0000", "@timestamp": "2026-10-19T10:16:03.000Z" } ``` Compare the event to the log line that you sent: - The `message` field contains the original log line. - The `grok` processor added the `clientip`, `ident`, `auth`, `timestamp`, `verb`, `request`, `httpversion`, `response`, and `bytes` fields. - The `date` processor added the `@timestamp` field. - The `convert_type` processor changed `response` and `bytes` to integers, so they appear without quotation marks. ## Step 6: Search the data in OpenSearch The `opensearch` sink wrote the same events to the `web-logs` index. Search for requests that returned an error, which are those containing a response code of `400` or higher: ```bash curl -X GET "https://localhost:9200/web-logs/_search?pretty" -ku admin: \ -H "Content-Type: application/json" \ -d '{ "query": { "range": { "response": { "gte": 400 } } } }' ``` {% include copy.html %} The `-k` option skips certificate verification because OpenSearch uses demo certificates. The response contains the event for the request that returned a `500` response code: ```json { "took" : 41, "timed_out" : false, "_shards" : { "total" : 1, "successful" : 1, "skipped" : 0, "failed" : 0 }, "hits" : { "total" : { "value" : 1, "relation" : "eq" }, "max_score" : 1.0, "hits" : [ { "_index" : "web-logs", "_id" : "QJmSVKEBVverMSge8P0k", "_score" : 1.0, "_source":{"message":"10.0.0.7 - - [19/Oct/2026:10:16:03 +0000] \"GET /checkout HTTP/1.1\" 500 98","request":"/checkout","auth":"-","ident":"-","response":500,"bytes":98,"clientip":"10.0.0.7","verb":"GET","httpversion":"1.1","timestamp":"19/Oct/2026:10:16:03 +0000","@timestamp":"2026-10-19T10:16:03.000Z"} } ] } } ``` The range query works because the `convert_type` processor converted `response` to an integer before the event reached OpenSearch. ## Step 7: Modify the pipeline Data Prepper reads pipeline configuration files only at startup, so you must restart Data Prepper after changing a pipeline. The `timestamp` field duplicates the `@timestamp` field. To remove it, add a [`delete_entries`]({{site.url}}{{site.baseurl}}/data-prepper/pipelines/configuration/processors/delete-entries/) processor to the end of the `processor` list in `pipelines.yaml`: ```yaml processor: - grok: match: message: ['%{COMMONAPACHELOG}'] - date: match: - key: timestamp patterns: ["dd/MMM/yyyy:HH:mm:ss Z"] destination: "@timestamp" - convert_type: keys: ["response", "bytes"] type: integer - delete_entries: with_keys: ["timestamp"] ``` {% include copy.html %} Restart Data Prepper: ```bash docker compose restart data-prepper ``` {% include copy.html %} Wait until the Data Prepper log contains a new `Started http source on port 2021` line, and then send another log line: ```bash curl -X POST http://localhost:2021/log/ingest \ -H "Content-Type: application/json" \ -d '[ {"message": "10.0.0.7 - - [19/Oct/2026:10:20:11 +0000] \"GET /checkout HTTP/1.1\" 503 64"} ]' ``` {% include copy.html %} The new event in the Data Prepper log no longer contains the `timestamp` field: ```json { "message": "10.0.0.7 - - [19/Oct/2026:10:20:11 +0000] \"GET /checkout HTTP/1.1\" 503 64", "request": "/checkout", "auth": "-", "ident": "-", "response": 503, "bytes": 64, "clientip": "10.0.0.7", "verb": "GET", "httpversion": "1.1", "@timestamp": "2026-10-19T10:20:11.000Z" } ``` Events that were indexed before the change are not modified. ## Step 8: Clean up To stop and remove the containers, run the following command from the `data-prepper-tutorial` directory: ```bash docker compose down ``` {% include copy.html %} The containers do not use volumes, so removing them deletes the `web-logs` index. ## Next steps -
