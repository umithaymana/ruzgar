Double-click Startup On Windows Windows users can double-click on the sqlite3.exe icon to cause the command-line shell to pop-up a terminal window running SQLite. However, because double-clicking starts the sqlite3.exe without command-line arguments, no database file will have been specified, so SQLite will use a transient in-memory database that is deleted when the session exits. To use a persistent disk file as the database, enter the ".open" command immediately after the terminal window starts up: SQLite version 3.54.0 2026-10-15 18:36:39 Enter ".help" for usage hints. Connected to a transient in-memory database . Use ".open FILENAME" to reopen on a persistent database. SQLite-3.54 memory -&gt; .open ex1.db SQLite-3.54 ex1.db -&gt; The example above causes the database file named "ex1.db" to be opened and used. The "ex1.db" file is created if it does not previously exist. You might want to use a full pathname to ensure that the file is in the directory that you think it is in. Use forward-slashes as the directory separator character. In other words use "c:/work/ex1.db", not "c:\work\ex1.db". Alternatively, you can create a new database using the default temporary storage, then save that database into a disk file using the ".save" command: SQLite version 3.54.0 2026-10-15 18:36:39 Enter ".help" for usage hints. Special commands (dot-commands) Most of the time, sqlite3 just reads lines of SQL input and passes those lines through into the SQLite library for evaluation. But input lines that begin with a dot (".") are intercepted and interpreted by the sqlite3 program itself. These "dot commands" are typically used to change the output format of queries, or to execute certain prepackaged query statements. There were originally just a few dot commands, but over the years many new features have accumulated so that today there are over 60. Most dot-commands can be abbreviated. For example ".q" is a common abbreviation for ".quit". 3. Rules for dot-commands, SQL, and More 3.1. Line Structure The CLI's input is a mixed sequence of: SQL statements dot-commands CLI comments SQL statements are free-form, and can be spread across multiple lines, with whitespace or SQL comments embedded anywhere. Multiple SQL statement are accumulated until a line is seen that ends with ";" when ignoring trailing whitespace and that contains one or more complete SQL statements. Note that ";" can occur internally in a CREATE TRIGGER statement. SQLite knows this and will not try to evaluate the SQL until the CREATE TRIGGER statement is complete. When such a trailing ";" is seen, all accumulated SQL statements are evaluated together. Dot-command have a specific syntax: Dot-commands must begin with a "." at the left margin with no preceding whitespace. Dot-commands must be entirely contained on a single input line. Dot-commands cannot occur in the middle of an ordinary SQL statement. In other words, dot-commands cannot occur at a continuation prompt. There is no comment syntax for dot-commands. Bare (unquoted) semicolons at the end of dot commands are ignored (in version 3.52.0 and after). The CLI also accepts whole-line comments that begin with a '#' character and extend to the end of the line. There can be no whitespace prior to the initial '#'. 3.2. Dot-command arguments Dot-commands can be followed by zero or more space-separated arguments. Arguments are parsed according to these rules: Any trailing whitespace and a final ";" are removed, if present. Arguments are separated from each other and from the initial dot-command itself by whitespace. Text within '...' is treated as a single argument with the ' delimiters removed, even if the text contains white space. Text within "..." is treated as a single argument with the " delimiters removed. C-style backslash escapes (ex: \\ , \n , \r , \" , \033 , etc.) work only within double-quoted arguments. 3.3. Dot-commands are evaluated separately The dot-commands are interpreted by the sqlite3.exe command-line program, not by the SQLite library. So dot-commands will not work as an argument to core SQLite library interfaces such as sqlite3_prepare() or sqlite3_exec() . 4.
