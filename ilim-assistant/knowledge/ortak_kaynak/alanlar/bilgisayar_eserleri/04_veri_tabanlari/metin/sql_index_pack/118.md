The json_valid() function The json_valid(X,Y) function returns 1 if the argument X is well-formed JSON, or returns 0 if X is not well-formed. The Y parameter is an integer bitmask that defines what is meant by "well-formed". The following bits of Y are currently defined: 0x01 &rarr; The input is text that strictly complies with canonical RFC-8259 JSON, without any extensions. 0x02 &rarr; The input is text that is JSON with JSON5 extensions described above. 0x04 &rarr; The input is a BLOB that superficially appears to be JSONB . 0x08 &rarr; The input is a BLOB that strictly conforms to the internal JSONB format. By combining bits, the following useful values of Y can be derived: 1 &rarr; X is RFC-8259 JSON text 2 &rarr; X is JSON5 text 4 &rarr; X is probably JSONB 5 &rarr; X is RFC-8259 JSON text or JSONB 6 &rarr; X is JSON5 text or JSONB &larr; This is probably the value you want 8 &rarr; X is strictly conforming JSONB 9 &rarr; X is RFC-8259 or strictly conforming JSONB 10 &rarr; X is JSON5 or strictly conforming JSONB The Y parameter is optional. If omitted, it defaults to 1, which means that the default behavior is to return true only if the input X is strictly conforming RFC-8259 JSON text without any extensions. This makes the one-argument version of json_valid() compatible with older versions of SQLite, prior to the addition of support for JSON5 and JSONB . The difference between 0x04 and 0x08 bits in the Y parameter is that 0x04 only examines the outer wrapper of the BLOB to see if it superficially looks like JSONB . This is sufficient for most purposes and is very fast. The 0x08 bit does a thorough examination of all internal details of the BLOB. The 0x08 bit takes time that is linear in the size of the X input and is much slower. The 0x04 bit is recommended for most purposes. If you just want to know if a value is a plausible input to one of the other JSON functions, a Y value of 6 is probably what you want to use. Any Y value less than 1 or greater than 15 raises an error, for the latest version of json_valid(). However, future versions of json_valid() might be enhanced to accept flag values outside of this range, having new meanings that we have not yet thought of. If either X or Y inputs to json_valid() are NULL, then the function returns NULL. Examples: json_valid('{"x":35}') &rarr; 1 json_valid('{x:35}') &rarr; 0 json_valid('{x:35}',6) &rarr; 1 json_valid('{"x":35') &rarr; 0 json_valid(NULL) &rarr; NULL 4.22. The json_quote() function The json_quote(X) function converts the SQL value X (a number or a string) into its corresponding JSON representation. If X is a JSON value returned by another JSON function, then this function is a no-op.
