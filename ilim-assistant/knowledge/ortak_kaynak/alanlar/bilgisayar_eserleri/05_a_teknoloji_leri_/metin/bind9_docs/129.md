Known Issues  The list of known issues affecting the latest version in the 9.21 branch can be found at https://gitlab.isc.org/isc-projects/bind9/-/wikis/Known-Issues-in-BIND-9.21 Notes for BIND 9.21.27  Security Fixes  Prevent exhaustion of CPU while parsing crafted DNS messages. (CVE-2026-19630) A crafted message could make named spend a disproportionate amount of time expanding compressed names in it, letting a client saturate all worker threads with very little traffic and time out legitimate queries. The amount of name expansion a single message can require is now bounded, and named answers FORMERR when that bound is exceeded; ordinary traffic, including zone transfers and dynamic updates, stays well within it. [GL #5932] Prevent concurrent GSS-TSIG traffic from terminating named . (CVE-2026-94300) A GSS-TSIG session negotiated through TKEY is shared by every message signed or verified with that key; previously, named did not serialize access to it, so concurrent signed messages could corrupt Kerberos-owned state and terminate named unexpectedly. Access to the shared session is now serialized. ISC would like to thank Dave Aitel from OpenAI who independently discovered and responsibly reported the issue to ISC. [GL #6320] Fix a crash with redirect zones and strict QNAME minimization. (CVE-2026-96888) Processing an NXDOMAIN response with a redirect zone configured could cause named to crash if qname-minimization was set to strict . This has been fixed. ISC would like to thank Vitaly Simonovich for bringing this vulnerability to our attention. [GL #6386] Fix a crash when resuming from a query initiated by RPZ. (CVE-2026-97313) The named process could terminate unexpectedly when resuming from a query initiated by RPZ processing. This has been fixed. ISC would like to thank Vitaly Simonovich for bringing this vulnerability to our attention. [GL #6408] New Features  Add NXNAME to the known type mnemonics. Type NXNAME is used by servers returning Compact Denial of Existence in DNSSEC ( RFC 9824 ) answers. Such answers are now displayed using the NXNAME mnemonic instead of TYPE128. [GL #5721] Feature Changes  Reject DNS messages that repeat a SOA, CNAME, or DNAME record. Previously, named discarded identical copies of a SOA, CNAME, or DNAME record repeated within a DNS message. Such a message is now treated as malformed regardless of whether the copies are identical, so responses from servers that send duplicate singleton records are rejected. [GL #6335] Reject compressed names in record types that forbid compression. Previously, named accepted compressed domain names inside any type of DNS record, but RFC 3597 permits compression only in the types defined in RFC 1035 and in a few older types such as SRV and NAPTR. Any DNS message that compresses a name in another record type, for example the signer name in an RRSIG record, is now rejected as malformed. [GL !12854] Bug Fixes  Remove a spurious root trust anchor warning and recognize the new root key. The static entry for the root zone WILL FAIL after key rollover warning only makes sense for the IANA root keys, which are rolled over using RFC 5011 ; named and named-checkconf no longer log it for other static root trust anchors. Both now also warn when the configured root trust-anchors include an older IANA root key but not the new one (ID 38696). [GL #5572] Do not accept HMAC keys and signatures for SIG(0) or DNSSEC. Due to an oversight, keys and signatures using HMAC algorithms, which are only meant for TSIG, could be accepted for SIG(0) and DNSSEC purposes. This has been fixed. [GL #6086] Fix DNSSEC tool dates being read one hour late during Daylight Saving Time. When a key timing value was passed to the DNSSEC tools in the format printed by dnssec-settime -p (for example, Wed Jul &#160; 1 12:00:00 2026 ), it was read as standard time. While Daylight Saving Time was in effect, the resulting time was one hour late. These values are now read in the correct local time. [GL #6089] Reject URI records with an empty target. RFC 7553 requires that the target field of a URI record not be empty. Such records were accepted, but are now rejected both in zone files and in DNS messages. [GL #6134] Fix a crash when loading a zone in raw format. When loading a specially crafted zone file in raw format ( masterfile-format ), the named process could terminate unexpectedly. This has been fixed. [GL #6141] Fix rndc signing -list output for private algorithms. rndc signing -list printed the wrong algorithm name for keys using private algorithms. This has been fixed. [GL #6206] Prevent dynamic update prerequisites from probing zones that refuse queries. Dynamic update prerequisites did not honor allow-query-on , nor allow-query for inline-signed zones, so clients that were refused queries could use them to learn whether records existed in the zone. These ACLs are now enforced for dynamic updates. [GL #6216] [GL #6217] Fix a named-journalprint crash when using the -x option. When a journal file had no index table, named-journalprint could crash while printing extended diagnostics with -x . This has been fixed. [GL #6238] Honor server settings for keyed NOTIFY and DS queries. When named sent a NOTIFY message, or a DS query to a parental agent, to a server listed with an explicit TSIG key, settings from the matching server statement, such as notify-source or tcp-only , could be ignored. This has been fixed. [GL #6239] Fix DNSSEC re-signing stopping after a rejected dynamic update. Since 9.21.22, a dynamic update that deleted an RRset in a zone signed with dnssec-policy , but was then rejected (for example, for exceeding max-records-per-type ), could stop named from re-signing the zone until the server was restarted. Once the existing signatures expired, the zone failed DNSSEC validation. An affected zone showed a next re-signing time in the year 2106 in rndc zonestatus output. This has been fixed. [GL #6303] Fix a catalog zone update bug. When a catalog zone update reused the label of an existing member zone for a different member zone, the old member zone could remain in the view and be served authoritatively until named was reloaded or restarted. This has been fixed. [GL #6305] Fix an out-of-bounds read in dig +dns64prefix . When a hostile resolver returned AAAA records of a class other than IN, dig +dns64prefix could process them and read out of bounds. This has been fixed. [GL #6312] Prevent excessive RRL table scans under load. When response rate limiting ( rate-limit ) was in use, recycling entries in a large RRL table could require scanning much of the table while holding a lock, delaying other responses. The amount of work done to recycle entries is now bounded. [GL #6351] Fix a crash when a forwarder answers with a referral. The resolver could crash when a forwarder used with forward only; answered a query with a referral. This has been fixed. [GL #6373] Make named-checkconf fail on invalid command-line arguments. Previously, named-checkconf exited with status 0 when given an invalid command-line argument, so a command such as named-checkconf $ARGS &amp;&amp; rndc reload could reload the server even when $ARGS was invalid. It now exits with a non-zero status. [GL #6400] Remove the temporary file when saving a zone file fails. When writing a zone file failed at the final rename step, the temporary file was left behind. It is now removed, as it already was on other errors. [GL #6405] Prevent the statistics channel from serving data on unregistered URL prefixes. The statistics-channels HTTP server also matched request paths that were only a prefix of a URL it served, so it returned data for URLs that it should have rejected. This has been fixed. [GL #6415] Fix a crash on OpenBSD when a signal reached an idle worker thread. On OpenBSD, a signal delivered to named while one of its worker threads was idle could make the server abort with a fatal &quot;Operation canceled&quot; error, because OpenBSD reports such an interrupted wait differently from Linux and the other supported systems. The wait is now resumed after the signal, as it already was elsewhere. [GL #6427] Use the CDS type in NOTIFY(CDS) messages. When sending generalized DNS notifications ( notify-cfg ) to the endpoint listed in a parent zone's DSYNC record, named set the type to SOA instead of CDS. This has been fixed. [GL #6433] Resolve names in insecure zones whose apex answers with a CNAME. A validating resolver returned SERVFAIL for names in an unsigned zone whose apex answers with a CNAME, because the validator refused to look up the DS proof showing that the zone was insecure. That lookup is now allowed. The cache now also keeps a CNAME alongside other records at the same name, including the parent's delegation data, instead of replacing one with the other, and chooses the fresher record at lookup time.
