[GL #5979] [GL !12280] Prevent overwriting an existing iptable node when merging. dfa9967150 Previously, if an ACL was misconfigured with a duplicate entry in a negated nested ACL, like this: { 10.9.8.1; ! { 10.9.8.1; }; } ... the first-match node for 10.9.8.1 would have been reversed, producing the effective ACL: { !10.9.8.1; }; This has been corrected by modifying isc_radix_insert() . Radix insertion cannot fail, and previously the function had no return value. But it actually has two different success cases: one in which it has created a new radix node, and one in which it has found an existing node with a matching prefix and passed back a pointer to it. To distinguish between these, it now returns either ISC_R_SUCCESS or ISC_R_EXISTS . dns_iptable_merge() uses this to ensure that existing nodes won't be overwritten by subsequently-specified ones.
