[GL #6433] [GL !12872] Resolve names in insecure zones whose apex answers with a CNAME. 6a9fa41ca5d A validating resolver returned SERVFAIL for names in an unsigned zone whose apex answers with a CNAME, because the validator refused to look up the DS proof that shows the zone is insecure. That lookup is now allowed, and the cache keeps a CNAME next to other records at the same name (including the parent's delegation data) instead of deleting one for the other, choosing the fresher record at lookup time; this supersedes the earlier fix for stale answers after a record changes to or from a CNAME. [GL !12853] Add sign delay to offline KSK ZRRSIG state timing. a8eb03d8592 With offline KSK, the ZRRSIG state of a ZSK was derived from the key timing without the sign delay, and retire-safety only counted towards the next rekey time, so during a ZSK rollover the signatures were reported omnipresent (or hidden) days too early. Signing itself is not affected. [GL !12762] Cache hostname, version, and server-id at configuration time. 4568504e9c2 Replace the pattern of calling gethostname() on every CHAOS TXT query and every NSID EDNS option with a cached copy that is computed once during configuration loading and updated on reconfiguration. The char* + bool sentinel pairs (version/version_set, hostname/hostname_set, server_id/usehostname) are consolidated into isc_region_t structs, which carry both the pointer and length, eliminating redundant strlen() calls in the query path and simplifying the control flow in builtin.c and client.c. This reduces per-query overhead for hostname.bind, version.bind, id.server lookups and NSID option generation. [GL !11635] Decompress message names into their own buffers. ed0a44bcac6 Names returned by dns_message_gettempname() are dns_fixedname_t objects, each with a buffer large enough for any name. Despite that, the message parser decompressed question and owner names into the shared scratchpad buffer. Names are now decompressed directly into their own buffers, so only rdata uses the scratchpad and large messages allocate fewer extra scratchpad buffers. [GL !12891] Fix TSIG session loss across a reload. 375c8f5243c Dynamic TSIG sessions negotiated through TKEY were saved to disk by whichever view released the key ring first, which during a reload was the outgoing view — consuming sessions the incoming view was still using and forcing clients to renegotiate. Sessions are now saved only when the last view releases them, and a failed save no longer replaces the stored sessions with a truncated file. [GL !12800] Fix and extend the counted_by bounds annotations. b7166490fbb More structs now carry counted_by annotations, and the existing ones were reordered so the length comes before the pointer it describes. [GL !12804] Fix compression table bookkeeping in dns_compress_rollback() a39b1ce9596 Discarding the whole compression table underflowed its entry count, so the rest of the message went out uncompressed, and a partial rollback could miss entries that were moved during deletion. Both only made responses less compact; named never sent a wrong name. [GL !12541] GSS-TSIG keys now last as long as the negotiated context. 21e44102bf0 When GSS-TSIG is in use, the TSIG key that named derives from a completed TKEY negotiation always expired after at most one hour, even when the negotiated security context was valid for far longer, so clients had to repeat the TKEY exchange every hour to keep sending dynamic updates. named now keeps such a key for as long as that context remains valid, and applies the one-hour limit only when its lifetime cannot be determined. [GL !12749] Keep the zone table read section open until the zone is attached. 89fa3e48577 dns_zt_find() ended its qp-trie read transaction before checking the zone type and attaching to the zone, which is only safe as long as the callers in view.c happen to hold an RCU read lock of their own. The read section is now closed after the reference has been taken, so the zone can no longer be reclaimed out from under the lookup.
