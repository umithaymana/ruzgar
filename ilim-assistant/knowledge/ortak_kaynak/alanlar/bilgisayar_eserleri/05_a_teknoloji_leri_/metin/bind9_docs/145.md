Changelog &mdash; BIND 9 9.21.29-dev documentation Changelog View page source Changelog  Note The following list contains detailed information about BIND 9 development. Regular users should refer to Release Notes for changes relevant to them. BIND 9.21.27  Security Fixes  [CVE-2026-19630] Crafted DNS messages could exhaust CPU while being parsed. 6b80ca9b191 A crafted message could make named spend a disproportionate amount of time expanding compressed names in it, letting a client saturate all worker threads with very little traffic and time out legitimate queries. named now bounds how much name expansion a single message can require and answers FORMERR when that bound is exceeded; ordinary traffic, including zone transfers and dynamic updates, stays well inside it. [GL #5932] [CVE-2026-94300] Fix remote termination of named under concurrent GSS-TSIG traffic. 0fd028e16d9 A GSS-TSIG session negotiated through TKEY is shared by every message signed or verified with that key, and named did not serialize access to it, so concurrent signed messages could corrupt Kerberos-owned state and terminate named unexpectedly. [GL #6320] [CVE-2026-96888] Possible crash with redirect and qname-minimization strict. 13fe8e97f81 Processing an NXDOMAIN response with a redirect zone could cause named to crash if qname-minimization was set to strict . [GL #6386] [CVE-2026-97313] Fix a bug when resuming from a query initiated by RPZ. 34dfbc25b9b The named process could terminate unexpectedly when resuming from a query initiated by RPZ processing. This has been fixed. ISC would like to thank whisperer for reporting the issue. [GL #6408] New Features  Add NXNAME to the known type mnemonics. c0a3e676641 Type NXNAME is used by servers returning Compact Denial of Existence in DNSSEC (RFC 9824) answers. Such answers will now be displayed using the NXNAME mnemonic instead of TYPE128 . [GL #5721] [GL !11500] Removed Features  Remove the authors.bind builtin zone. 89d23d1791a The authors.bind chaos zone contained a static, hand-maintained list of contributors that has become outdated and incomplete. Now that the project uses version control which tracks all contributions (including external ones), the zone serves no useful purpose. Remove the authors_lookup() function, the associated zone definition from the default configuration, and the corresponding documentation. [GL #5417] [GL !11068] Feature Changes  Reject DNS messages that repeat a SOA, CNAME, or DNAME record. a04770e52ac A DNS message could carry the same SOA, CNAME, or DNAME record many times and named kept every copy while parsing it; with name compression those copies took up far more memory internally than in the message itself, and every later processing step had to handle all of them. named now treats a message that repeats such a record as malformed, whether or not the copies are identical, so responses from a server that sends duplicate singleton records are rejected instead of being accepted as before. [GL #6335] [GL !12803] Use size_t as the type used for isc_counter_t 73fe702d39a isc_counter_t was using a plethora of integer types internally and in it's API. Change it to be consistent and use size_t only. [GL #6354] [GL !12702] Do not store the effective config as text. 2534fd5371b In the 1m zones startup test in perflab, storing the effective config as text brings us from 45.3s to 56s startup (and should have a similar effect on rndc reload and rndc reconfig ), while saving us 1.7 GB of memory. It has been easier to reduce memory consumption than startup time, so we'd rather take the startup time side of the tradeoff. [GL !12732] Optimize NSEC3 parsing and query handling. 09565537725 This branch introduces a more specialized base32 conversion of NSEC3 hashes, and optimizes the loading of NSEC3 records from zone files. [GL !12733] Reject compressed names in record types that forbid compression. cf682cf0a18 named used to accept compressed domain names inside any type of DNS record, but RFC 3597 permits compression only in the types defined in RFC 1035 and in a few older types such as SRV and NAPTR. named now rejects as malformed any DNS message that compresses a name in another record type, for example the signer name in an RRSIG record. [GL !12854] Simplify dns_rdata_tostruct() and remove dns_rdata_freestruct() 22dcc479f6e The type-specific rdata structures could optionally own copies of their data, but nearly every caller used the borrowing mode and the few that did not had no need for a private copy. The memory-context argument, the per-structure mctx member, and the whole dns_rdata_freestruct() machinery are removed, so the structures now always point directly into the wire-format rdata and the caller keeps that rdata alive while the structure is in use. [GL !12757] Skip expensive string lookups in zone creation in the common case. 74c478f8fcf Both the search for rfc1918 names and for zone template labels are implemented in linear time in the number of possible cases. In hosting-type setups with lots of zones, these checks can delay startup time. This MR adds a pre-check to skip the expensive checks when possible. [GL !11070] Bug Fixes  Remove spurious named/named-checkconf warning. 89df45ac94b &quot;static entry for the root zone WILL FAIL after key rollover - use trust-anchors with initial-key or initial-ds instead&quot; only makes sense when you are using ICANN root keys as they use RFC 5011 for DNSKEY management. Don't log it in other circumstances. [GL #5572] [GL !11097] Fix a data race in the RPZ summary database. c53102aed05 Reloading a response policy zone could modify entries of the summary database in place while queries were reading them without a lock, which ThreadSanitizer reported as a data race. Entries are now replaced with a fresh copy instead, so queries keep reading a consistent entry and the query path stays lock-free. [GL #5594] [GL !12630] Fix private-type RRset handling during apex delete updates. 2b5dfa831d6 When DNS UPDATE processing manipulates diff.tuples (e.g. during delete-all-at-name or delete-RRset operations at a zone apex with TYPE65534 private signing state), tuples were being unlinked from the list using ISC_LIST_UNLINK() directly. This bypassed the diff.size counter, causing it to drift out of sync with the actual list contents. This commit introduces dns_diff_unlink() , which keeps diff.size accurate when removing a tuple, and updates all call sites in lib/dns/ and lib/ns/ that previously manipulated the list directly. ISC thanks Mcsky23 and Qifan Zhang of Palo Alto Networks for reporting the issue. [GL #5802] [GL !12170] Revert &quot;Prevent overwriting an existing iptable node when merging&quot; b0e59d9a336 This reverts commit b1ee26c94d9c8084d3e40a5f190ef5cc33abca99. The above change had unintended side effects. The issue it attempted to address will be fixed properly in due course. [GL #6049] [GL !12738] Dns_ds_fromkeyrdata private OID digest length check is off by one. 0e902459393 The length check in dns_ds_fromkeyrdata for private OID digest check failed to account for the length byte itself. This has been fixed. [GL #6079] [GL !12784] Don't accept HMAC-based keys and signatures for SIG(0) or DNSSEC. 285e09588d0 Due to an oversight HMAC keys could be accepted for SIG(0) and DNSSEC purposes. This has been fixed. [GL #6086] [GL !12237] Fix DNSSEC tool dates read one hour late during daylight saving time. ff2504bbb58 When a key timing value was passed to the DNSSEC tools in the format that dnssec-settime -p prints (for example Wed Jul 1 12:00:00 2026), it was read as standard time. While daylight saving time was in effect, the resulting time was one hour late. These values are now read in the correct local time. [GL #6089] [GL !12857] &quot;libisccc flat S-expression free can exhaust stack&quot; 9403ddeaa5d It was possible to exceed the stack in rndc if it had to free really deep answer chains from a hostile server. Flatten the freeing of answer chains. Printing the sexpr tree for debugging also suffers from the same stack exhaustion problem due to excessive recursion. Flatten sexpr tree printing. [GL #6090] [GL !12572] Fix RRL qps-scale TCP credit age check uses the response bucket age. 129afe4ef2e There was a cut-and-paste bug in debit_rrl_entry where the age from the wrong entry was used to set scale. Use credit_e instead of e . [GL #6106] [GL !12848] Enforce non empty URI target field in URI record. 7fe5d97d7ce RFC 7553 requires that the URI target field MUST NOT be an empty URI (&quot;&quot;). This is now enforced by the from text and from wire methods. [GL #6134] [GL !12631] Fix a space calculation bug when loading a zone in &quot;RAW&quot; format. dd8f60f7fcc When loading a specially crafted zone file in &quot;RAW&quot; format, the named process could terminate unexpectedly. This has been fixed. [GL #6141] [GL !12508] Dst_key_fromdns should fail on unsupported algorithms. d9e14117c68 dst_key_fromdns could succeed on unsupported algorithms causing failures later in code which assumed that a dst_key_t always had a supported algorithms. [GL #6192] [GL !12598] Fix isc_time_formatISO8601TZms writes past short caller buffers. 07887ddd5da The function isc_time_formatiso8601tzms was incorrectly documented and if the passed in buffer was exactly 29 bytes long there was a 1 byte buffer write overrun. This has been fixed.
