[GL !11607] Replace lock keyfile hashmap with lock pool. 4fd84193c73 Kasp used a lock per zone origin in order to prevent concurrent access to keyfiles. This lead to substantial memory consumption in the case of authoritative servers with many small zones, as lots of locks need to be allocated. Since the number of keyfile locks taken cannot exceed the number of helper threads, it makes more sense to use a lock pool of fixed size keyed by the hash of the origin name, leading to memory savings. [GL !11588] BIND 9.21.19  Security Fixes  Remove purged adb names and entries from SIEVE list immediately. 22181ec1b8a Both expire_name() and expire_entry() use isc_async mechanism to remove the names and entries from the SIEVE-LRU lists on the matching isc_loop.
