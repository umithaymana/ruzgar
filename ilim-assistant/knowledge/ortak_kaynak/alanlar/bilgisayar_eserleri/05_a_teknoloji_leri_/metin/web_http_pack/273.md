Known Issues  The list of known issues affecting the latest version in the 9.21 branch can be found at https://gitlab.isc.org/isc-projects/bind9/-/wikis/Known-Issues-in-BIND-9.21 Notes for BIND 9.21.27  Security Fixes  Prevent exhaustion of CPU while parsing crafted DNS messages. (CVE-2026-19630) A crafted message could make named spend a disproportionate amount of time expanding compressed names in it, letting a client saturate all worker threads with very little traffic and time out legitimate queries. The amount of name expansion a single message can require is now bounded, and named answers FORMERR when that bound is exceeded; ordinary traffic, including zone transfers and dynamic updates, stays well within it. [GL #5932] Prevent concurrent GSS-TSIG traffic from terminating named . (CVE-2026-94300) A GSS-TSIG session negotiated through TKEY is shared by every message signed or verified with that key; previously, named did not serialize access to it, so concurrent signed messages could corrupt Kerberos-owned state and terminate named unexpectedly. Access to the shared session is now serialized. ISC would like to thank Dave Aitel from OpenAI who independently discovered and responsibly reported the issue to ISC. [GL #6320] Fix a crash with redirect zones and strict QNAME minimization. (CVE-2026-96888) Processing an NXDOMAIN response with a redirect zone configured could cause named to crash if qname-minimization was set to strict . This has been fixed. ISC would like to thank Vitaly Simonovich for bringing this vulnerability to our attention. [GL #6386] Fix a crash when resuming from a query initiated by RPZ. (CVE-2026-97313) The named process could terminate unexpectedly when resuming from a query initiated by RPZ processing. This has been fixed. ISC would like to thank Vitaly Simonovich for bringing this vulnerability to our attention. [GL #6408] New Features  Add NXNAME to the known type mnemonics. Type NXNAME is used by servers returning Compact Denial of Existence in DNSSEC ( RFC 9824 ) answers. Such answers are now displayed using the NXNAME mnemonic instead of TYPE128. [GL #5721] Feature Changes  Reject DNS messages that repeat a SOA, CNAME, or DNAME record. Previously, named discarded identical copies of a SOA, CNAME, or DNAME record repeated within a DNS message. Such a message is now treated as malformed regardless of whether the copies are identical, so responses from servers that send duplicate singleton records are rejected. [GL #6335] Reject compressed names in record types that forbid compression. Previously, named accepted compressed domain names inside any type of DNS record, but RFC 3597 permits compression only in the types defined in RFC 1035 and in a few older types such as SRV and NAPTR. Any DNS message that compresses a name in another record type, for example the signer name in an RRSIG record, is now rejected as malformed. [GL !12854] Bug Fixes  Remove a spurious root trust anchor warning and recognize the new root key. The static entry for the root zone WILL FAIL after key rollover warning only makes sense for the IANA root keys, which are rolled over using RFC 5011 ; named and named-checkconf no longer log it for other static root trust anchors. Both now also warn when the configured root trust-anchors include an older IANA root key but not the new one (ID 38696). [GL #5572] Do not accept HMAC keys and signatures for SIG(0) or DNSSEC. Due to an oversight, keys and signatures using HMAC algorithms, which are only meant for TSIG, could be accepted for SIG(0) and DNSSEC purposes. This has been fixed. [GL #6086] Fix DNSSEC tool dates being read one hour late during Daylight Saving Time. When a key timing value was passed to the DNSSEC tools in the format printed by dnssec-settime -p (for example, Wed Jul &#160; 1 12:00:00 2026 ), it was read as standard time. While Daylight Saving Time was in effect, the resulting time was one hour late. These values are now read in the correct local time. [GL #6089] Reject URI records with an empty target. RFC 7553 requires that the target field of a URI record not be empty. Such records were accepted, but are now rejected both in zone files and in DNS messages. [GL #6134] Fix a crash when loading a zone in raw format. When loading a specially crafted zone file in raw format ( masterfile-format ), the named process could terminate unexpectedly. This has been fixed. [GL #6141] Fix rndc signing -list output for private algorithms. rndc signing -list printed the wrong algorithm name for keys using private algorithms. This has been fixed.
