[GL #4793] [GL !9123] Fix the assertion failure in the isc_hashmap iterator. c31cd677882 When the round robin hashing reorders the map entries on deletion, we were adjusting the iterator table size only when the reordering was happening at the internal table boundary. The iterator table size had to be reduced by one to prevent seeing the entry that resized on position [0] twice because it migrated to [iter-&gt;size - 1] position. However, the same thing could happen when the same entry migrates a second time from [iter-&gt;size - 1] to [iter-&gt;size - 2] position (and so on) because the check that we are manipulating the entry just in the [0] position was insufficient. Instead of checking the position [pos == 0], we now check that the [pos % iter-&gt;size == 0], thus ignoring all the entries that might have moved back to the end of the internal table.
