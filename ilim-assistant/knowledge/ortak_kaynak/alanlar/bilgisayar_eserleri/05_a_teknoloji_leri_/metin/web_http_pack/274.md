These ACLs are now enforced for dynamic updates. [GL #6216] [GL #6217] Fix a named-journalprint crash when using the -x option. When a journal file had no index table, named-journalprint could crash while printing extended diagnostics with -x . This has been fixed. [GL #6238] Honor server settings for keyed NOTIFY and DS queries. When named sent a NOTIFY message, or a DS query to a parental agent, to a server listed with an explicit TSIG key, settings from the matching server statement, such as notify-source or tcp-only , could be ignored. This has been fixed. [GL #6239] Fix DNSSEC re-signing stopping after a rejected dynamic update. Since 9.21.22, a dynamic update that deleted an RRset in a zone signed with dnssec-policy , but was then rejected (for example, for exceeding max-records-per-type ), could stop named from re-signing the zone until the server was restarted. Once the existing signatures expired, the zone failed DNSSEC validation. An affected zone showed a next re-signing time in the year 2106 in rndc zonestatus output. This has been fixed. [GL #6303] Fix a catalog zone update bug. When a catalog zone update reused the label of an existing member zone for a different member zone, the old member zone could remain in the view and be served authoritatively until named was reloaded or restarted. This has been fixed. [GL #6305] Fix an out-of-bounds read in dig +dns64prefix . When a hostile resolver returned AAAA records of a class other than IN, dig +dns64prefix could process them and read out of bounds. This has been fixed. [GL #6312] Prevent excessive RRL table scans under load. When response rate limiting ( rate-limit ) was in use, recycling entries in a large RRL table could require scanning much of the table while holding a lock, delaying other responses. The amount of work done to recycle entries is now bounded. [GL #6351] Fix a crash when a forwarder answers with a referral. The resolver could crash when a forwarder used with forward only; answered a query with a referral. This has been fixed. [GL #6373] Make named-checkconf fail on invalid command-line arguments. Previously, named-checkconf exited with status 0 when given an invalid command-line argument, so a command such as named-checkconf $ARGS &amp;&amp; rndc reload could reload the server even when $ARGS was invalid. It now exits with a non-zero status. [GL #6400] Remove the temporary file when saving a zone file fails. When writing a zone file failed at the final rename step, the temporary file was left behind. It is now removed, as it already was on other errors. [GL #6405] Prevent the statistics channel from serving data on unregistered URL prefixes. The statistics-channels HTTP server also matched request paths that were only a prefix of a URL it served, so it returned data for URLs that it should have rejected. This has been fixed. [GL #6415] Fix a crash on OpenBSD when a signal reached an idle worker thread. On OpenBSD, a signal delivered to named while one of its worker threads was idle could make the server abort with a fatal &quot;Operation canceled&quot; error, because OpenBSD reports such an interrupted wait differently from Linux and the other supported systems. [GL #6433] Resolve names in insecure zones whose apex answers with a CNAME. A validating resolver returned SERVFAIL for names in an unsigned zone whose apex answers with a CNAME, because the validator refused to look up the DS proof showing that the zone was insecure.
