Changelog &mdash; BIND 9 9.21.29-dev documentation Changelog View page source Changelog  Note The following list contains detailed information about BIND 9 development. Regular users should refer to Release Notes for changes relevant to them. BIND 9.21.27  Security Fixes  [CVE-2026-19630] Crafted DNS messages could exhaust CPU while being parsed. 6b80ca9b191 A crafted message could make named spend a disproportionate amount of time expanding compressed names in it, letting a client saturate all worker threads with very little traffic and time out legitimate queries. named now bounds how much name expansion a single message can require and answers FORMERR when that bound is exceeded; ordinary traffic, including zone transfers and dynamic updates, stays well inside it. [GL #5932] [CVE-2026-94300] Fix remote termination of named under concurrent GSS-TSIG traffic. 0fd028e16d9 A GSS-TSIG session negotiated through TKEY is shared by every message signed or verified with that key, and named did not serialize access to it, so concurrent signed messages could corrupt Kerberos-owned state and terminate named unexpectedly. [GL #6320] [CVE-2026-96888] Possible crash with redirect and qname-minimization strict. 13fe8e97f81 Processing an NXDOMAIN response with a redirect zone could cause named to crash if qname-minimization was set to strict . [GL #6386] [CVE-2026-97313] Fix a bug when resuming from a query initiated by RPZ. 34dfbc25b9b The named process could terminate unexpectedly when resuming from a query initiated by RPZ processing. This has been fixed. ISC would like to thank whisperer for reporting the issue. [GL #6408] New Features  Add NXNAME to the known type mnemonics. c0a3e676641 Type NXNAME is used by servers returning Compact Denial of Existence in DNSSEC (RFC 9824) answers. Such answers will now be displayed using the NXNAME mnemonic instead of TYPE128 . [GL #5721] [GL !11500] Removed Features  Remove the authors.bind builtin zone. 89d23d1791a The authors.bind chaos zone contained a static, hand-maintained list of contributors that has become outdated and incomplete. Now that the project uses version control which tracks all contributions (including external ones), the zone serves no useful purpose. Remove the authors_lookup() function, the associated zone definition from the default configuration, and the corresponding documentation. [GL #5417] [GL !11068] Feature Changes  Reject DNS messages that repeat a SOA, CNAME, or DNAME record. a04770e52ac A DNS message could carry the same SOA, CNAME, or DNAME record many times and named kept every copy while parsing it; with name compression those copies took up far more memory internally than in the message itself, and every later processing step had to handle all of them. named now treats a message that repeats such a record as malformed, whether or not the copies are identical, so responses from a server that sends duplicate singleton records are rejected instead of being accepted as before. [GL #6335] [GL !12803] Use size_t as the type used for isc_counter_t 73fe702d39a isc_counter_t was using a plethora of integer types internally and in it's API. Change it to be consistent and use size_t only. [GL #6354] [GL !12702] Do not store the effective config as text. 2534fd5371b In the 1m zones startup test in perflab, storing the effective config as text brings us from 45.3s to 56s startup (and should have a similar effect on rndc reload and rndc reconfig ), while saving us 1.7 GB of memory. It has been easier to reduce memory consumption than startup time, so we'd rather take the startup time side of the tradeoff. [GL !12732] Optimize NSEC3 parsing and query handling. 09565537725 This branch introduces a more specialized base32 conversion of NSEC3 hashes, and optimizes the loading of NSEC3 records from zone files. [GL !12733] Reject compressed names in record types that forbid compression. cf682cf0a18 named used to accept compressed domain names inside any type of DNS record, but RFC 3597 permits compression only in the types defined in RFC 1035 and in a few older types such as SRV and NAPTR. named now rejects as malformed any DNS message that compresses a name in another record type, for example the signer name in an RRSIG record. [GL !12854] Simplify dns_rdata_tostruct() and remove dns_rdata_freestruct() 22dcc479f6e The type-specific rdata structures could optionally own copies of their data, but nearly every caller used the borrowing mode and the few that did not had no need for a private copy. The memory-context argument, the per-structure mctx member, and the whole dns_rdata_freestruct() machinery are removed, so the structures now always point directly into the wire-format rdata and the caller keeps that rdata alive while the structure is in use. [GL !12757] Skip expensive string lookups in zone creation in the common case. 74c478f8fcf Both the search for rfc1918 names and for zone template labels are implemented in linear time in the number of possible cases. In hosting-type setups with lots of zones, these checks can delay startup time. This MR adds a pre-check to skip the expensive checks when possible. [GL !11070] Bug Fixes  Remove spurious named/named-checkconf warning. 89df45ac94b &quot;static entry for the root zone WILL FAIL after key rollover - use trust-anchors with initial-key or initial-ds instead&quot; only makes sense when you are using ICANN root keys as they use RFC 5011 for DNSKEY management. Don't log it in other circumstances. [GL #5572] [GL !11097] Fix a data race in the RPZ summary database. c53102aed05 Reloading a response policy zone could modify entries of the summary database in place while queries were reading them without a lock, which ThreadSanitizer reported as a data race. Entries are now replaced with a fresh copy instead, so queries keep reading a consistent entry and the query path stays lock-free.
