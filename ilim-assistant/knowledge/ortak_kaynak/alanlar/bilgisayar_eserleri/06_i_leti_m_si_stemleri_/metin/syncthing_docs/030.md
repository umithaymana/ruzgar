port 443 as an unprivileged user ¶ It is recommended that you run the relay on port 443 (or another port which is commonly allowed through corporate firewalls), in order to maximise the chances that people are able to connect. However, binding to ports below 1024 requires root privileges, and running a relay as root is not recommended. Thankfully there are a couple of approaches available to you. One option is to run the relay on port 22067, and use an iptables rule to forward traffic from port 443 to port 22067, for example: iptables - t nat - A PREROUTING - p tcp -- dport 443 - j REDIRECT -- to - port 22067 Or, if you’re using ufw , add the following to /etc/ufw/before.rules : * nat : PREROUTING ACCEPT [ 0 : 0 ] : POSTROUTING ACCEPT [ 0 : 0 ] - A PREROUTING - p tcp -- dport 443 - j REDIRECT -- to - port 22067 COMMIT You will need to start strelaysrv with -ext-address &quot;:443&quot; . This tells strelaysrv that it can be contacted on port 443, even though it is listening on port 22067. You will also need to let both port 443 and 22067 through your firewall. Another option is described here , although your mileage may vary. Firewall Considerations ¶ The relay server listens on two ports by default. One for data connections and the other for providing public statistics at https://relays.syncthing.net/ . The firewall, such as iptables , must permit incoming TCP connections to the following ports: Data port: 22067/tcp overridden with -listen and advertised with -ext-address Status port: 22070/tcp overridden with -status-srv Runtime iptables rules to allow access to the default ports: iptables - I INPUT - p tcp -- dport 22067 - j ACCEPT iptables - I INPUT - p tcp -- dport 22070 - j ACCEPT Please consult Linux distribution documentation to persist firewall rules. Access control for private relays ¶ Added in version 1.22.1. Private relays can be configured to only accept connections from peers in possession of a shared secret. Custom Upgrade Server &#8212; Syncthing documentation Custom Upgrade Server ¶ Syncthing by default upgrades automatically from the official release packages on GitHub. If this is unsuitable, Syncthing can instead be configured to look for upgrades on a local or private upgrade server. Added in version 0.12.0. Usage ¶ The URL used to fetch release information can be set in Advanced Configuration , under the name releasesURL . The URL should point to a location serving a valid release list. The release list is a JSON file on the following format: [ { &quot;tag_name&quot; : &quot;v0.11.24&quot; , &quot;prerelease&quot; : false , &quot;assets&quot; : [ { &quot;url&quot; : &quot;https://example.com/dl/syncthing-dragonfly-amd64-v0.11.24.tar.gz&quot; , &quot;name&quot; : &quot;syncthing-dragonfly-amd64-v0.11.24.tar.gz&quot; }, { &quot;url&quot; : &quot;https://example.com/dl/syncthing-freebsd-386-v0.11.24.tar.gz&quot; , &quot;name&quot; : &quot;syncthing-freebsd-386-v0.11.24.tar.gz&quot; }, { &quot;url&quot; : &quot;https://example.com/dl/syncthing-freebsd-amd64-v0.11.24.tar.gz&quot; , &quot;name&quot; : &quot;syncthing-freebsd-amd64-v0.11.24.tar.gz&quot; }, { &quot;url&quot; : &quot;https://example.com/dl/syncthing-linux-386-v0.11.24.tar.gz&quot; , &quot;name&quot; : &quot;syncthing-linux-386-v0.11.24.tar.gz&quot; } ] }, { &quot;tag_name&quot; : &quot;v0.11.23&quot; , &quot;prerelease&quot; : false , &quot;assets&quot; : [ { &quot;url&quot; : &quot;https://example.com/dl/syncthing-dragonfly-amd64-v0.11.23.tar.gz&quot; , &quot;name&quot; : &quot;syncthing-dragonfly-amd64-v0.11.23.tar.gz&quot; }, { &quot;url&quot; : &quot;https://example.com/dl/syncthing-freebsd-386-v0.11.23.tar.gz&quot; , &quot;name&quot; : &quot;syncthing-freebsd-386-v0.11.23.tar.gz&quot; }, { &quot;url&quot; : &quot;https://example.com/dl/syncthing-freebsd-amd64-v0.11.23.tar.gz&quot; , &quot;name&quot; : &quot;syncthing-freebsd-amd64-v0.11.23.tar.gz&quot; }, { &quot;url&quot; : &quot;https://example.com/dl/syncthing-linux-386-v0.11.23.tar.gz&quot; , &quot;name&quot; : &quot;syncthing-linux-386-v0.11.23.tar.gz&quot; } ] } ] The file may include additional attributes; these are ignored. Syncthing looks for a version number in tag_name , then for an asset name matching syncthing-$os-$arch-$version.$ext . Only beta releases (i.e. releases with version numbers of the form v0.11.24-beta... ) will consider an upgrade to a release marked as &quot;prerelease&quot;: true . The actual assets must be official releases downloaded from GitHub, or they must be custom compiled and signed according to the process outlined in Release Signing .
